Chapitre 01

Qu'est-ce qu'AWS et pourquoi l'apprendre ?

Amazon Web Services (AWS) est la plateforme cloud n°1 mondiale, lancée par Amazon en 2006. Elle propose plus de 200 services : hébergement de serveurs, bases de données, stockage de fichiers, intelligence artificielle, réseaux, sécurité…

En tant que développeur connaissant Docker, tu gères déjà les conteneurs sur une seule machine. AWS te permet de faire pareil mais à l'échelle mondiale, avec des dizaines de datacenters, de la haute disponibilité, et sans gérer le matériel physique.

Le modèle Cloud : IaaS, PaaS, SaaS

ModèleTu gèresAWS gèreExemple AWS
IaaS
Infrastructure as a Service		 OS, runtime, appli, données Matériel, réseau, virtualisation EC2 (serveurs virtuels)
PaaS
Platform as a Service		 Appli, données Tout le reste + OS + runtime Elastic Beanstalk, RDS
SaaS
Software as a Service		 Utilisation uniquement Tout S3 (stockage), SES (emails)
FaaS
Function as a Service		 Code de la fonction Tout (serveurs, scaling, OS) AWS Lambda

Les services AWS les plus utilisés

🗄️

S3 — Simple Storage

Stockage de fichiers à l'infini. Images, vidéos, backups, sites statiques. Comme un disque dur dans le cloud.

🖥️

EC2 — Elastic Compute

Serveurs virtuels (VMs) dans le cloud. Tu choisis CPU, RAM, OS. Comme une VPS mais plus flexible.

λ

Lambda — Serverless

Exécute du code sans serveur. Tu paies uniquement quand le code s'exécute. Idéal pour des APIs ou tâches ponctuelles.

🗃️

DynamoDB — NoSQL

Base de données NoSQL ultra-rapide et scalable. Pas de schéma fixe, performances constantes.

📬

SQS — Message Queue

File de messages entre services. Comme RabbitMQ ou Kafka, mais géré par AWS. Découple les microservices.

🔐

IAM — Permissions

Gestion des identités et accès. Contrôle qui peut faire quoi sur tes ressources AWS.

🌐

VPC — Réseau Privé

Réseau virtuel isolé dans AWS. Sous-réseaux, firewalls, passerelles. Ton datacenter privé dans le cloud.

🔄

ECS / EKS — Conteneurs

Lancer des conteneurs Docker dans le cloud. ECS = AWS natif, EKS = Kubernetes managé.

Chapitre 02

LocalStack — AWS dans Docker, gratuitement

LocalStack est un projet open source qui émule l'API d'AWS entièrement en local dans un conteneur Docker. Tu envoies exactement les mêmes commandes AWS CLI qu'en production, mais elles s'exécutent sur ta machine, sans coût et sans compte AWS.

🔧
Ce que LocalStack émule (version Community gratuite) S3, SQS, SNS, Lambda, DynamoDB, API Gateway, IAM, SES, CloudFormation, Kinesis, Route53, CloudWatch Logs, SSM, Secrets Manager, et plus encore. Plus de 50 services AWS disponibles gratuitement.

Chapitre 03

Installation de l'environnement complet

Nous avons besoin de trois outils : Docker (que tu as déjà), LocalStack (émule AWS), et AWS CLI (l'outil en ligne de commande).

Étape 1 — Lancer LocalStack avec Docker Compose

La façon la plus simple est de créer un fichier docker-compose.yml dédié à LocalStack. Tu peux le placer dans ~/localstack/ et le laisser tourner en arrière-plan.

bash — Préparer le dossier
# Créer un dossier de travail pour LocalStack
$ mkdir -p ~/localstack ~/localstack/data
$ cd ~/localstack
yaml — ~/localstack/docker-compose.yml
version: '3.8'

services:
  localstack:
    image: localstack/localstack:3.4    # Version stable la plus récente
    container_name: localstack
    ports:
      - "127.0.0.1:4566:4566"           # Port principal : tous les services
      - "127.0.0.1:4510-4559:4510-4559" # Ports additionnels (Lambda, etc.)
    environment:
      - SERVICES=s3,sqs,sns,lambda,dynamodb,iam,secretsmanager,ssm,apigateway,cloudwatch,logs
                                           # Services à activer (vide = tous)
      - DEBUG=0                          # 1 pour plus de logs de debug
      - DATA_DIR=/var/lib/localstack/data # Persistance des données
      - DOCKER_HOST=unix:///var/run/docker.sock  # Pour Lambda (exécution en conteneur)
      - AWS_DEFAULT_REGION=eu-west-1     # Région par défaut (Paris = eu-west-3)
    volumes:
      - "./data:/var/lib/localstack"      # Persister les données entre restarts
      - "/var/run/docker.sock:/var/run/docker.sock"  # Docker socket pour Lambda
    networks:
      - localstack-net
    restart: unless-stopped

networks:
  localstack-net:
    driver: bridge
Variables d'environnement LocalStack expliquées
SERVICESListe des services AWS à activer séparés par des virgules. Laisser vide active tout (plus lent au démarrage).
DEBUG=1Affiche des logs détaillés dans la console du conteneur. Utile pour debugger.
DATA_DIRDossier où LocalStack stocke les données (S3 files, DynamoDB tables...). Permet de persister entre redémarrages.
DOCKER_HOSTNécessaire pour que LocalStack puisse lancer des conteneurs Docker pour exécuter les fonctions Lambda.
AWS_DEFAULT_REGIONRégion AWS simulée. eu-west-3 = Paris, us-east-1 = Virginie (défaut AWS).
bash — Démarrer LocalStack
$ cd ~/localstack

# Démarrer LocalStack en arrière-plan
$ docker compose up -d

# Suivre les logs de démarrage
$ docker compose logs -f

# Attendre le message : "Ready." dans les logs
# LocalStack est prêt quand tu vois :
# localstack  | Ready.

# Vérifier que LocalStack répond (health check)
$ curl http://localhost:4566/_localstack/health
# Réponse JSON avec le statut de chaque service

# Voir les conteneurs actifs
$ docker ps | grep localstack
docker compose — arguments expliqués
upCrée et démarre les conteneurs définis dans docker-compose.yml
-d / --detachMode détaché : tourne en arrière-plan, libère le terminal
logs -fAffiche les logs en temps réel (-f = follow). Ctrl+C pour quitter sans arrêter le conteneur.
downArrête et supprime les conteneurs (mais conserve les volumes)
restart localstackRedémarre uniquement le service localstack
psListe les conteneurs gérés par ce docker-compose

Étape 2 — Installer AWS CLI v2

L'AWS CLI (Command Line Interface) est l'outil qui te permet d'interagir avec AWS (ou LocalStack) depuis ton terminal. C'est l'équivalent de la commande docker mais pour AWS.

bash — Installation AWS CLI v2 sur Ubuntu
# ─── Méthode officielle AWS CLI v2 ───

# 1. Télécharger l'installeur
$ curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o awscliv2.zip

# 2. Décompresser
$ unzip awscliv2.zip

# 3. Installer (dans /usr/local/aws-cli)
$ sudo ./aws/install

# 4. Vérifier l'installation
$ aws --version
# aws-cli/2.x.x Python/3.x.x Linux/6.x.x

# 5. Nettoyer
$ rm -rf awscliv2.zip aws/
Installer awslocal — le wrapper pratique pour LocalStack

awslocal est un wrapper de la CLI AWS qui ajoute automatiquement --endpoint-url http://localhost:4566 à chaque commande. Tu n'as donc pas à le taper à chaque fois.

bash — Installer awslocal
# Installer pip si pas déjà présent
$ sudo apt-get install -y python3-pip

# Installer awscli-local (fournit la commande "awslocal")
$ pip3 install awscli-local

# Vérifier
$ awslocal --version

# Test : lister les buckets S3 (vide pour l'instant)
$ awslocal s3 ls
# (pas de résultat = normal, aucun bucket créé)

Chapitre 04

S3 — Simple Storage Service ✓ LocalStack

Amazon S3 est le service de stockage de fichiers d'AWS. Pense à lui comme un disque dur dans le cloud avec une capacité quasiment illimitée. Il est organisé en buckets (sceaux), qui contiennent des objets (fichiers).

🗄️
Analogie Docker S3 ≈ un volume Docker dans le cloud, accessible depuis partout via HTTPS. Mais contrairement aux volumes Docker (liés à un conteneur), les objets S3 sont indépendants et accessibles publiquement si tu le souhaites.

Concepts fondamentaux S3

TermeSignificationExemple
BucketConteneur de fichiers. Nom globalement unique dans AWS.mon-site-web-2024
ObjectUn fichier (+ ses métadonnées) dans un bucketimages/photo.jpg
KeyLe "chemin" de l'objet dans le bucket (pas de vraie arborescence)dossier/sous/fichier.txt
PrefixPartie du chemin pour simuler un dossierimages/
ACLAccess Control List : qui peut lire/écrire l'objetpublic-read
VersioningConserver l'historique des versions d'un fichierPermet le rollback

Commandes S3 essentielles

awslocal s3 mb — Créer un bucket

mb = "make bucket". Crée un nouveau bucket S3.

bash
# Créer un bucket (nom doit être unique, sans majuscules ni espaces)
$ awslocal s3 mb s3://mon-premier-bucket
# make_bucket: mon-premier-bucket

# Créer un bucket dans une région spécifique
$ awslocal s3 mb s3://mon-bucket-paris --region eu-west-3

# Lister tous les buckets
$ awslocal s3 ls
# 2024-01-15 10:30:00 mon-premier-bucket
# 2024-01-15 10:31:00 mon-bucket-paris
awslocal s3 cp — Copier des fichiers

Copie un fichier local vers S3, ou depuis S3 vers local, ou entre deux emplacements S3.

s3://bucket/keyChemin d'un objet S3. Toujours préfixé par s3://
--recursiveCopie un dossier entier et ses sous-dossiers
--acl public-readRend le fichier accessible publiquement via URL
--content-typeDéfinit le type MIME du fichier (ex: text/html)
--storage-classClasse de stockage : STANDARD, GLACIER (archive pas chère), etc.
--excludeExclure des fichiers selon un pattern (ex: "*.tmp")
--includeInclure uniquement les fichiers matching le pattern
bash
# Créer un fichier de test
$ echo "Bonjour depuis S3 LocalStack!" > bonjour.txt

# Uploader (local → S3)
$ awslocal s3 cp bonjour.txt s3://mon-premier-bucket/bonjour.txt
# upload: ./bonjour.txt to s3://mon-premier-bucket/bonjour.txt

# Uploader dans un "dossier" virtuel
$ awslocal s3 cp bonjour.txt s3://mon-premier-bucket/docs/bonjour.txt

# Télécharger (S3 → local)
$ awslocal s3 cp s3://mon-premier-bucket/bonjour.txt ./telecharge.txt

# Copier un dossier entier vers S3 (récursif)
$ awslocal s3 cp ./mon-site/ s3://mon-premier-bucket/ --recursive

# Copier avec métadonnées de type de contenu
$ awslocal s3 cp index.html s3://mon-premier-bucket/ --content-type "text/html"
awslocal s3 ls — Lister les objets
s3://bucket/Lister le contenu d'un bucket
s3://bucket/prefix/Lister uniquement les objets avec ce préfixe (simuler un dossier)
--recursiveLister récursivement tous les objets y compris sous-dossiers
--human-readableAfficher les tailles en Ko/Mo/Go
--summarizeAfficher le nombre total d'objets et la taille totale
bash
# Lister le contenu du bucket
$ awslocal s3 ls s3://mon-premier-bucket/
# 2024-01-15 10:35:00       28 bonjour.txt
# PRE docs/

# Lister avec détails lisibles
$ awslocal s3 ls s3://mon-premier-bucket/ --recursive --human-readable --summarize

# Lister seulement les fichiers du "dossier" docs/
$ awslocal s3 ls s3://mon-premier-bucket/docs/
awslocal s3 sync — Synchroniser des dossiers

sync synchronise un dossier local avec S3 (ou l'inverse). Il ne copie que les fichiers nouveaux ou modifiés. C'est la commande idéale pour déployer un site web statique.

source destinationLocal → S3, S3 → Local, ou S3 → S3
--deleteSupprime dans la destination les fichiers qui n'existent plus dans la source
--exclude "*.log"Exclure les fichiers .log de la synchronisation
--dryrunSimule la synchronisation sans rien modifier (utile pour vérifier)
bash
# Synchroniser un dossier local vers S3
$ awslocal s3 sync ./mon-site/ s3://mon-site-bucket/

# Avec suppression des fichiers obsolètes côté S3
$ awslocal s3 sync ./mon-site/ s3://mon-site-bucket/ --delete

# Simulation avant de vraiment synchroniser
$ awslocal s3 sync ./mon-site/ s3://mon-site-bucket/ --dryrun

# Télécharger tout un bucket localement
$ awslocal s3 sync s3://mon-site-bucket/ ./backup-site/

Commandes S3 avancées

bash — awslocal s3api (API complète)
# ─── s3api : accès bas niveau à l'API S3 ───

# Créer un bucket avec s3api
$ awslocal s3api create-bucket --bucket mon-bucket-api \
    --region eu-west-3 \
    --create-bucket-configuration LocationConstraint=eu-west-3

# Activer le versioning sur un bucket
$ awslocal s3api put-bucket-versioning \
    --bucket mon-premier-bucket \
    --versioning-configuration Status=Enabled

# Configurer un bucket pour héberger un site web statique
$ awslocal s3api put-bucket-website \
    --bucket mon-premier-bucket \
    --website-configuration '{
        "IndexDocument": {"Suffix": "index.html"},
        "ErrorDocument": {"Key": "error.html"}
    }'

# Obtenir les métadonnées d'un objet
$ awslocal s3api head-object \
    --bucket mon-premier-bucket \
    --key bonjour.txt

# Rendre un bucket public (désactive BlockPublicAccess)
$ awslocal s3api put-public-access-block \
    --bucket mon-premier-bucket \
    --public-access-block-configuration "BlockPublicAcls=false,IgnorePublicAcls=false,BlockPublicPolicy=false,RestrictPublicBuckets=false"

# Supprimer un objet
$ awslocal s3api delete-object \
    --bucket mon-premier-bucket \
    --key bonjour.txt

# Supprimer un bucket (doit être vide d'abord)
$ awslocal s3 rm s3://mon-premier-bucket --recursive  # Vider
$ awslocal s3 rb s3://mon-premier-bucket                 # Supprimer
s3 vs s3api — Quelle différence ?
aws s3Interface de haut niveau. Commandes simplifiées : cp, mv, ls, sync, rm, mb, rb. Idéal pour les opérations courantes avec fichiers.
aws s3apiInterface de bas niveau, accès direct à l'API REST S3. Permet toutes les configurations avancées : versioning, lifecycle, CORS, ACL, policy, website hosting.
Chapitre 05

EC2 — Elastic Compute Cloud ~ LocalStack

EC2 est le service de machines virtuelles d'AWS. Tu loues un serveur virtuel (appelé instance) avec les ressources que tu veux, dans la région que tu choisis. C'est l'équivalent d'un VPS (Hetzner, OVH...) mais avec bien plus de flexibilité.

⚠️
Support LocalStack limité pour EC2 LocalStack Community supporte EC2 en mode simulation légère. Les instances ne "tournent" pas vraiment (pas de vrai OS). Pour pratiquer EC2 réellement sans CB, utilise AWS Academy (gratuit pour étudiants) ou Play with AWS (labs temporaires). Ce chapitre couvre les commandes que tu utiliseras sur le vrai AWS.

Commandes EC2 essentielles (AWS CLI)

bash — Créer une paire de clés SSH
# Créer une paire de clés (la clé privée est téléchargée UNE SEULE FOIS)
$ awslocal ec2 create-key-pair \
    --key-name ma-cle-ssh \
    --query 'KeyMaterial' \
    --output text > ~/.ssh/ma-cle-ssh.pem

# Sécuriser les droits (SSH refuse les clés trop permissives)
$ chmod 400 ~/.ssh/ma-cle-ssh.pem

# Lister les paires de clés existantes
$ awslocal ec2 describe-key-pairs
ec2 create-key-pair — arguments
--key-nameNom de la paire de clés dans AWS. Doit être unique dans la région.
--query 'KeyMaterial'Filtre la réponse JSON pour n'extraire que le contenu de la clé privée.
--output textFormat texte brut (sans les guillemets JSON). Nécessaire pour sauvegarder la clé.
> fichier.pemRedirige la sortie vers le fichier. La clé privée ne peut être récupérée qu'une seule fois.
chmod 400Droits lecture seule pour le propriétaire. SSH refuse de se connecter si les droits sont trop ouverts.
bash — Créer un Security Group et lancer une instance
# ─── 1. Créer un Security Group (firewall) ───
$ awslocal ec2 create-security-group \
    --group-name mon-sg-web \
    --description "Security group pour serveur web"
# Retourne : { "GroupId": "sg-xxxxxxxx" }

# ─── 2. Autoriser SSH (port 22) depuis n'importe où ───
$ awslocal ec2 authorize-security-group-ingress \
    --group-name mon-sg-web \
    --protocol tcp \
    --port 22 \
    --cidr 0.0.0.0/0

# ─── 3. Autoriser HTTP (port 80) ───
$ awslocal ec2 authorize-security-group-ingress \
    --group-name mon-sg-web \
    --protocol tcp \
    --port 80 \
    --cidr 0.0.0.0/0

# ─── 4. Trouver l'AMI Ubuntu 24.04 (sur vrai AWS) ───
$ aws ec2 describe-images \
    --owners 099720109477 \
    --filters "Name=name,Values=ubuntu/images/hvm-ssd-gp3/ubuntu-noble-24.04-amd64-server-*" \
    --query 'Images | sort_by(@, &CreationDate) | [-1].ImageId' \
    --output text
# Retourne : ami-xxxxxxxxxxxxxxxxx

# ─── 5. Lancer une instance EC2 ───
$ awslocal ec2 run-instances \
    --image-id ami-0c02fb55956c7d316 \
    --instance-type t3.micro \
    --key-name ma-cle-ssh \
    --security-groups mon-sg-web \
    --count 1 \
    --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=mon-serveur-web}]'

--image-idL'AMI à utiliser. Chaque région a ses propres IDs d'AMI. Ubuntu = ami-0c02fb55956c7d316 en us-east-1.

Chapitre 06

Lambda — Fonctions Serverless ✓ LocalStack

AWS Lambda permet d'exécuter du code sans gérer de serveur. Tu écris une fonction, tu la déploies, et AWS l'exécute à la demande. Tu ne paies que le temps d'exécution réel (première tranche de 1 million d'appels et 400 000 Go-secondes gratuits par mois à vie).

⚡
Analogie Docker Lambda ≈ un conteneur qui démarre en millisecondes à la demande, exécute ta fonction, puis s'arrête. Tu n'as pas à gérer le serveur, l'OS, le scaling, ni la disponibilité.

Comment fonctionne Lambda

── CYCLE DE VIE D'UNE LAMBDA ──
Déclencheur          Lambda          Ta Fonction
(Trigger)        (AWS gère)         (Ton code)
   │                  │                  │
   │ 1. Événement     │                  │
   │ ─────────────►   │                  │
   │                  │ 2. Init cold     │

   │                  │ ─────────────►   │

   │ ◄─────────────   │                  │
   │                  │ (Conteneur gardé │
   │                  │  en veille 15mn) │

 • API Gateway (requête HTTP)

Créer et déployer une Lambda en Python

1

Écrire la fonction Lambda

python — handler.py
import json
import os
from datetime import datetime

# La fonction Lambda a TOUJOURS la signature handler(event, context)
def handler(event, context):
    """
    event   : dict contenant les données du déclencheur (ex: requête HTTP)
    context : informations sur l'exécution Lambda (timeout, mémoire, etc.)
    """

    # Lire les paramètres de la requête (si appelé via API Gateway)
    params = event.get('queryStringParameters', {}) or {}
    nom    = params.get('nom', 'Monde')

    # Lire une variable d'environnement
    env = os.environ.get('APP_ENV', 'development')

    # Logique de ta fonction
    message = f"Bonjour {nom} ! Il est {datetime.now().strftime('%H:%M:%S')}. Env: {env}"

    # Retourner une réponse HTTP (format API Gateway)
    return {
        'statusCode': 200,
        'headers': {
            'Content-Type': 'application/json',
            'Access-Control-Allow-Origin': '*'
        },
        'body': json.dumps({
            'message': message,
            'timestamp': datetime.now().isoformat()
        })
    }

IAM — Gestion des Identités et Accès ✓ LocalStack

IAM (Identity and Access Management) contrôle qui peut faire quoi sur tes ressources AWS. C'est le service de sécurité fondamental d'AWS. Chaque appel à une API AWS est vérifié par IAM.

🔐
Règle d'or : Principe du moindre privilège N'accorde toujours que les permissions strictement nécessaires. Jamais de wildcard "Action": "*" ou "Resource": "*" en production. Un compte compromis avec des droits limités cause beaucoup moins de dégâts.

Concepts IAM

👤

User

Une identité permanente (personne ou service). A ses propres credentials (Access Key + Secret).

👥

Group

Collection d'utilisateurs partageant les mêmes permissions. Ex: "Developers", "Admins".

🎭

Role

Identité temporaire pour les services AWS (Lambda, EC2...). Pas de mot de passe permanent.

📄

Policy

Document JSON définissant les permissions : quelles actions sur quelles ressources.

                "Effect": "Allow",
                "Action": [

Structure d'une Policy IAM JSON
"Version": "2012-10-17"Version du langage de policy. Toujours utiliser "2012-10-17" (la plus récente).
"Effect": "Allow"Allow = accorde la permission. Deny = refuse explicitement (prioritaire sur Allow).

import json, boto3, os
from datetime import datetime

s3     = boto3.client('s3',         endpoint_url=os.environ.get('AWS_ENDPOINT'))
dynamo = boto3.resource('dynamodb', endpoint_url=os.environ.get('AWS_ENDPOINT'))
table  = dynamo.Table('images-metadata')

def handler(event, context):
    processed = 0
    for record in event.get('Records', []):
        try:
            body   = json.loads(record['body'])
            bucket = body.get('bucket', 'images-upload-local')
            key    = body.get('key', 'unknown.jpg')

            image_id = f"img-{datetime.now().timestamp():.0f}"
            metadata = {
                'imageId':     image_id,

                'destination': f"s3://images-processed-local/processed-{key}",
                'status':      'processed',
                'processedAt': datetime.now().isoformat()

            # Enregistrer dans DynamoDB
            table.put_item(Item=metadata)

            # Copier vers bucket de sortie
            try:
                s3.copy_object(
                    CopySource={'Bucket': bucket, 'Key': key},
                    Bucket='images-processed-local',
                    Key=f"processed-{key}"
                )
            except Exception as e:
                print(f"⚠️  Copie impossible : {e}")

            print(f"✅ Image traitée : {key} → {image_id}")
            processed += 1
        except Exception as e:
            print(f"❌ Erreur : {e}")
            raise

    return {'statusCode': 200, 'body': json.dumps({'processed': processed})}
