Le serveur Proxmox et votre espace

Dans ce bloc, les machines ne tournent plus sur votre PC : elles tournent sur un serveur de virtualisation Proxmox VE, un hyperviseur de type 1 (installé directement sur le matériel, voir cours 1). Votre PC ne sert plus qu’à vous y connecter : un navigateur et un client SSH suffisent.

Tout est installé à neuf sur ce serveur : on ne récupère ni les machines virtuelles du BLOC 1 (elles tournaient dans VirtualBox, sur votre PC), ni leurs clés SSH.

Chaque étudiant dispose d’un espace isolé des autres :

Élément Valeur Exemple pour l’étudiant 3
Votre numéro N, donné par M. CHADEYRON en séance 1 (1 à 5 ; 9 est réservé aux démonstrations) 3
Adresse du serveur PROXMOX, donnée en séance 1
Interface d’administration https://PROXMOX:8006
Identifiant et mot de passe donnés par M. CHADEYRON
Pool (dossier de vos VM) etuN etu3
Réseau virtuel (VNet) hexaN, réseau 10.20.N.0/24 hexa3, 10.20.3.0/24
Passerelle 10.20.N.1 : le serveur Proxmox lui-même, qui fait la traduction d’adresses (NAT) vers Internet 10.20.3.1
Stockage des disques nom donné par M. CHADEYRON
Stockage des sauvegardes pbs-etuN (à partir de la séance 10) pbs-etu3

Vous ne voyez et ne pouvez modifier que vos propres VM. Les réseaux des étudiants sont isolés les uns des autres : votre 10.20.N.0/24 ne voit pas celui du voisin.

Dans tous les TP, remplacez N par votre numéro

Une adresse notée 10.20.N.20 s’écrit 10.20.3.20 pour l’étudiant 3 ; un port noté 1N022 s’écrit 13022 ; une VM notée N20 porte le numéro 320. Notez vos valeurs une fois pour toutes dans le tableau « Mes adresses » de votre journal de bord.

Accéder à vos machines depuis votre PC

Vos VM ont des adresses privées, invisibles depuis votre PC. Le serveur Proxmox redirige quelques ports vers elles (redirection de ports, comme web-srv au BLOC 1) :

Port sur PROXMOX Mène à Usage Séances
1N022 10.20.N.40:22 (sup-lnx-01) SSH : point d’entrée de l’administration, puis rebond vers les autres VM Linux à partir de 1
1N080 10.20.N.40:80 (sup-lnx-01) Nagios /nagios4, Zabbix /zabbix à partir de 3
1N020 10.20.N.20:80 (srv-lnx-01) l’intranet, vu comme un utilisateur à partir de 1
1N081 10.20.N.21:80 (srv-lnx-02) GLPI à partir de 8
1N443 10.20.N.41:443 (sup-win-01) PRTG 6

Exemples pour l’étudiant 3 : ssh -p 13022 sysadmin@PROXMOX, http://PROXMOX:13080/zabbix, http://PROXMOX:13020/.

Les machines Windows s’administrent par la console de Proxmox (bouton Console, dans le navigateur), en interface graphique.

Le fichier de configuration SSH de votre PC

On donne un nom court à chaque machine, on utilise la clé du BLOC 2 (id_bloc2, créée au TP 1) et l’on rebondit par le point d’entrée. Sous Windows, le fichier est C:\Users\<vous>\.ssh\config (sans extension) ; sous Linux, ~/.ssh/config. Remplacez PROXMOX et N :

Fichier : ~/.ssh/config
# Lab Proxmox, BLOC 2
Host sup-lnx-01
    HostName PROXMOX
    Port 1N022
    User sysadmin
    IdentityFile ~/.ssh/id_bloc2

Host srv-lnx-01
    HostName 10.20.N.20
    User sysadmin
    IdentityFile ~/.ssh/id_bloc2
    ProxyJump sup-lnx-01

Host srv-lnx-02
    HostName 10.20.N.21
    User sysadmin
    IdentityFile ~/.ssh/id_bloc2
    ProxyJump sup-lnx-01

Puis ssh sup-lnx-01 ou ssh srv-lnx-01. Votre clé privée reste sur votre PC ; seule la clé publique est déposée sur les serveurs (TP 1, partie F).

Toutes les VM se créent avec le bouton Créer VM de l’interface et s’installent depuis les images ISO du stockage local, dans la console du navigateur :

  • Debian 13 (netinst) : installeur en français, réseau configuré à la main (pas de DHCP), mot de passe de root laissé vide pour que le compte sysadmin utilise sudo, logiciels « serveur SSH » et « utilitaires usuels » seulement (pas d’interface graphique). Méthode détaillée au TP 1, partie C.
  • Windows Server 2025 : version d’évaluation de 180 jours, Expérience de bureau. Le disque et la carte réseau sont VirtIO : il faut charger le pilote vioscsi pendant l’installation, puis installer virtio-win-guest-tools. Méthode détaillée au TP 1, parties B et D.
  • Sur toutes les VM, l’agent invité QEMU est installé et l’option Agent QEMU cochée : Proxmox affiche alors l’adresse IP de la VM dans son Résumé, l’arrête proprement et fige ses disques pendant les sauvegardes.

Comptes et mots de passe

  • VM Debian : le compte sysadmin, créé à l’installation ; root est désactivé, sysadmin passe par sudo (avec son mot de passe). En SSH, connexion par clé uniquement (TP 1, partie F.6) ; le mot de passe sert à la console et à sudo.
  • Windows Server : Administrateur, puis HEXALOG\Administrateur après la création du domaine.
  • Interfaces web : nagiosadmin (Nagios), Admin (Zabbix), glpi (GLPI), prtgadmin (PRTG). Leur mot de passe par défaut est changé dès l’installation pour le mot de passe de lab.
  • Le mot de passe de lab est donné en séance 1. Il ne sert que dans le lab : ne le réutilisez jamais ailleurs, et n’utilisez jamais un mot de passe personnel dans le lab.

Bonnes pratiques

  • Éteindre proprement : bouton Arrêter (Shutdown) de Proxmox, ou sudo poweroff. Le bouton Stop équivaut à couper le courant.
  • Snapshot avant chaque étape risquée, avec un nom numéroté ; supprimer de temps en temps ceux devenus inutiles. Un snapshot reste sur le même serveur que la VM : ce n’est pas une sauvegarde (séance 10).
  • Ne pas surdimensionner : le serveur est partagé ; les tailles du tableau suffisent.
  • Supervision par adresse IP : dans Nagios et Zabbix, on déclare les hôtes par leur adresse, pour qu’une panne du DNS ne fasse pas croire que tout est tombé.
  • Noter dans le journal de bord toute modification, même petite : pendant l’exercice d’astreinte, vous serez content de savoir ce qui a changé.

Dépannage Proxmox

Symptôme Solution
Échec de connexion à https://PROXMOX:8006 identifiant ou mot de passe mal saisis ; accepter le certificat (autosigné) ; sinon, prévenir M. CHADEYRON
Le pont hexaN n’apparaît pas dans l’onglet Réseau de Créer VM prévenir M. CHADEYRON (droit sur le VNet manquant)
Créer VM refuse de terminer (« permission check failed ») choisir votre pool etuN et le numéro de VM de la convention
La console reste noire cliquer dans la console et appuyer sur une touche ; pour Windows, bouton Ctrl-Alt-Suppr du panneau de gauche
Windows : aucun disque pendant l’installation charger le pilote vioscsi\2k25\amd64 depuis le lecteur virtio-win
Windows : pas de réseau installer virtio-win-guest-tools depuis le lecteur virtio-win
La VM redémarre sur l’installeur retirer l’ISO : Matériel → Lecteur CD/DVD → N’utiliser aucun média
Adresses IP vide dans le Résumé de la VM agent invité absent ou arrêté (sudo apt install qemu-guest-agent, sudo systemctl start qemu-guest-agent), ou option Agent QEMU décochée (VM → Options)
Permission denied (publickey) en SSH clé non déposée sur le serveur, ou IdentityFile absent du fichier config : corriger depuis la console Proxmox
apt update échoue (pas d’Internet) ip route (passerelle 10.20.N.1 ?), cat /etc/resolv.conf (DNS ?), ping -c 2 DNS-SECOURS ; si toute la classe est touchée, prévenir M. CHADEYRON
Le port redirigé ne répond pas la VM est-elle allumée, avec la bonne adresse ? le service écoute-t-il (ss -tlnp) ?
« Out of memory » au démarrage d’une VM le serveur est plein : éteindre les VM inutiles (sup-win-01 en dehors de la séance 6)

Si le serveur Proxmox est indisponible

Tous les TP fonctionnent aussi sur VirtualBox, avec un réseau NAT dédié (par exemple LAB-HEXALOG2, à créer) : remplacez alors 10.20.N. par l’adresse de ce réseau, installez les VM à neuf depuis les mêmes ISO, accédez-y par des redirections de ports de VirtualBox, et sautez les parties propres à Proxmox (Proxmox Backup Server). M. CHADEYRON vous donnera les consignes le jour venu.
