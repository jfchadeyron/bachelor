Cours de la séance 4

Zabbix : architecture et agents

Zabbix réunit dans un seul outil ce que Nagios laisse à des modules : la collecte, l'historique des mesures dans une base de données, les seuils, les alertes, les graphiques et les tableaux de bord, le tout configuré par une interface web. Cette séance présente son architecture, son vocabulaire (hôtes, éléments, déclencheurs, modèles, macros) et ses agents ; le TP l'installe et supervise les serveurs Linux et Windows d'Hexalog.

1. Zabbix en quelques mots

Zabbix est un logiciel libre (licence AGPL depuis la version 7.0) développé par la société lettone Zabbix SIA, qui vend du support et des formations. Il sort une version LTS (Long Term Support) tous les deux ans environ, maintenue cinq ans :

Version Sortie Fin de support complet Fin de support limité
6.0 LTS février 2022 février 2025 février 2027
7.0 LTS juin 2024 juin 2027 juin 2029
8.0 LTS en préparation (version candidate à l’automne 2026)

Le bloc utilise la 7.0 LTS, la plus diffusée en entreprise aujourd’hui. Entre deux LTS paraissent des versions intermédiaires (7.2, 7.4), maintenues quelques mois seulement : on les évite en production.

2. L’architecture

Composant Rôle
Serveur (zabbix_server) le cœur : des processus spécialisés interrogent les agents (pollers), reçoivent les données envoyées (trappers), font les pings (pingers, avec fping), évaluent les déclencheurs, envoient les alertes (alerters), purgent l’historique (housekeeper)
Base de données toute la configuration et toutes les mesures : MariaDB/MySQL ou PostgreSQL (avec l’extension TimescaleDB pour les gros volumes)
Interface web application PHP : configuration, visualisation, tableaux de bord ; elle ne lit que la base (et interroge le serveur pour son état)
Agent (zabbix_agentd, en C) et agent 2 (zabbix_agent2, en Go) collectent sur la machine supervisée ; l’agent 2 ajoute des greffons (plugins) : MySQL, PostgreSQL, Docker, Redis, certificats…
Proxy collecte pour le compte du serveur dans un site distant ou un réseau isolé, garde les données si le lien tombe, puis les transmet

Ports à retenir : 10050 (l’agent écoute, contrôles passifs) et 10051 (le serveur ou le proxy écoute : agents actifs, proxys, envois par zabbix_sender).

3. Le modèle de données

Terme Sens Exemple
Hôte (host) une machine ou un équipement supervisé srv-lnx-01
Groupe d’hôtes regroupement, aussi utilisé pour les droits et les actions ; les groupes peuvent s’imbriquer avec / Hexalog/Linux
Interface comment joindre l’hôte : Agent, SNMP, IPMI, JMX Agent 10.20.N.20:10050
Élément (item) une mesure : une clé, un intervalle, un type de valeur, une durée de conservation vfs.fs.size[/,pused] toutes les minutes
Déclencheur (trigger) une expression logique sur des éléments, avec une sévérité last(/srv-lnx-01/vfs.fs.size[/,pused])>90
Problème, événement un déclencheur qui passe à l’état PROBLÈME crée un événement et un problème, jusqu’à son rétablissement « FS [/]: Space is critically low »
Action ce qu’on fait quand un problème apparaît : notifier, escalader, exécuter un script courriel à l’astreinte (séance 5)
Modèle (template) un ensemble prêt à l’emploi d’éléments, déclencheurs, graphiques, règles de découverte, macros, qu’on lie à des hôtes Linux by Zabbix agent
Macro utilisateur une variable {$NOM}, définie dans un modèle et redéfinissable sur un hôte {$VFS.FS.PUSED.MAX.WARN} = 80
Découverte de bas niveau (LLD) une règle qui découvre les objets d’un hôte (systèmes de fichiers, interfaces, services Windows) et crée pour chacun éléments et déclencheurs à partir de prototypes un élément « espace utilisé » par système de fichiers trouvé
Étiquette (tag) une paire nom-valeur attachée aux problèmes, pour filtrer et router les alertes service:intranet

Des clés pour tout

Chaque mesure d’un agent est désignée par une clé, éventuellement avec des paramètres entre crochets :

Clé Mesure
agent.ping l’agent répond (1)
system.cpu.load[all,avg1] charge sur 1 minute
vm.memory.size[pavailable] pourcentage de mémoire disponible
vfs.fs.size[/,pused] pourcentage utilisé du système de fichiers /
proc.num[nginx] nombre de processus nginx
net.tcp.service[http,,80] le service HTTP local répond
web.page.get[localhost,basic_status,80] contenu d’une page web, lue par l’agent
service.info[DNS,state] état du service Windows DNS
eventlog[Security,,,,4625] les événements 4625 du journal Sécurité de Windows
log[/var/log/auth.log,"Failed password"] les lignes d’un fichier journal contenant un motif

Historique et tendances

Zabbix garde chaque valeur dans l’historique pendant une durée courte (souvent 7 à 31 jours), puis seulement des tendances (minimum, moyenne, maximum par heure) pendant un an ou plus. Le housekeeper supprime régulièrement les données expirées. C’est ce stockage qui permet les graphiques sur un an et la maintenance prévisionnelle (« le disque sera plein dans 20 jours »), mais c’est aussi lui qui fait grossir la base : le dimensionnement de la base est le principal souci d’exploitation de Zabbix.

4. Les agents

Passif ou actif

Contrôle passif Contrôle actif
Qui ouvre la connexion le serveur, vers l’agent (port 10050) l’agent, vers le serveur (port 10051)
Fonctionnement le serveur demande une valeur, l’agent répond l’agent demande au serveur la liste de ses éléments, les mesure lui-même et envoie les résultats par lots
Réglage de l’agent Server= : adresses autorisées à l’interroger ServerActive= : où envoyer ; Hostname= : doit être identique au nom de l’hôte dans Zabbix
Intérêts simple ; le serveur sait tout de suite si l’agent ne répond pas traverse un pare-feu ou une NAT dans un seul sens ; charge moindre pour le serveur ; indispensable pour lire des journaux (log[], eventlog[])

Les modèles existent en deux variantes (Linux by Zabbix agent et Linux by Zabbix agent active). Dans le lab, on utilise les contrôles passifs, plus faciles à diagnostiquer, et les contrôles actifs pour les journaux (séance 7).

Configurer et tester

Sous Debian, la configuration est dans /etc/zabbix/zabbix_agent2.conf, qui inclut les fichiers de /etc/zabbix/zabbix_agent2.d/. Comme pour SSH au BLOC 1, on ne modifie pas le fichier du paquet : on dépose un fichier à soi, qui remplace les valeurs par défaut.

ExempleFichier : /etc/zabbix/zabbix_agent2.d/hexalog.confà lire, pas à taper
Server=10.20.N.40
ServerActive=10.20.N.40
Hostname=srv-lnx-01

Deux outils de test :

  • zabbix_agent2 -t <clé> sur la machine supervisée : l’agent calcule la valeur localement ;
  • zabbix_get -s <adresse> -k <clé> sur le serveur : on interroge l’agent par le réseau, exactement comme le fera le serveur.

Sécuriser l’agent

Mesure Réglage
seules les adresses du serveur et du proxy peuvent l’interroger Server=
chiffrer et authentifier les échanges TLSConnect, TLSAccept avec une clé partagée (PSK) ou des certificats
interdire certaines clés DenyKey=, AllowKey= ; la clé system.run (exécuter une commande) est désactivée par défaut
compte sans privilèges l’agent tourne sous le compte zabbix ; on évite AllowRoot

5. Installer Zabbix

Debian 13 contient Zabbix 7.0, mais le dépôt officiel de Zabbix fournit des correctifs plus récents : c’est la méthode recommandée par l’éditeur pour le serveur. Les étapes :

  1. installer le paquet zabbix-release, qui déclare le dépôt, puis le serveur, l’interface, la configuration Apache, les scripts SQL et l’agent 2 ;
  2. créer la base zabbix (jeu de caractères utf8mb4, collation utf8mb4_bin) et son compte, puis importer le schéma (environ 200 tables, quelques minutes) ;
  3. indiquer le mot de passe de la base au serveur (DBPassword dans /etc/zabbix/zabbix_server.conf) et le démarrer ;
  4. terminer par l’assistant de l’interface web, qui écrit /etc/zabbix/web/zabbix.conf.php ;
  5. se connecter avec Admin / zabbix et changer ce mot de passe immédiatement.

Pour une interface en français, la locale fr_FR.UTF-8 doit exister sur le serveur. La traduction est incomplète : certains libellés restent en anglais, d’où les deux noms donnés dans les TP, par exemple Collecte de données → Hôtes (Data collection → Hosts).

6. Les modèles fournis

Zabbix livre plusieurs centaines de modèles. Ceux du bloc :

Modèle Lié à Ce qu’il apporte À régler
Linux by Zabbix agent srv-lnx-01 processeur, charge, mémoire, systèmes de fichiers et interfaces (découverts), redémarrages, heure rien ; certains déclencheurs informatifs
Nginx by Zabbix agent srv-lnx-01 connexions, requêtes, processus, à partir de la page basic_status page, hôte et port par macros (valeurs par défaut correctes ici)
PHP-FPM by Zabbix agent srv-lnx-01 file d’attente, processus actifs, lenteurs, à partir de /status et /ping idem
MySQL by Zabbix agent 2 srv-lnx-01 disponibilité, connexions, requêtes, tampons de MariaDB {$MYSQL.DSN}, {$MYSQL.USER}, {$MYSQL.PASSWORD}
Windows by Zabbix agent srv-win-01 processeur, mémoire, disques, et chaque service Windows en démarrage automatique (découvert), avec un déclencheur s’il est arrêté rien
ICMP Ping tous joignabilité, pertes, temps de réponse (par fping depuis le serveur) rien
Linux by SNMP un hôte SNMP les mêmes indicateurs, lus en SNMP (séance 5) interface et identifiants SNMP

Lier un modèle crée en une fois des dizaines d’éléments et de déclencheurs : c’est la grande différence avec Nagios. La contrepartie est qu’il faut relire ce qu’ils surveillent et ajuster seuils et alertes (séance 5) : un modèle ne connaît pas votre contexte.

9. À retenir

Points clés

  • Zabbix 7.0 LTS : serveur, base de données (toute la configuration et toutes les mesures), interface PHP, agents, proxys.
  • Hôte, interface, élément (clé), déclencheur (expression + sévérité), problème, action, modèle, macro, découverte de bas niveau, étiquette.
  • Historique (court) et tendances (longues) : la base grossit, le housekeeper purge.
  • Agent passif : le serveur interroge le port 10050 (Server=) ; actif : l’agent envoie au port 10051 (ServerActive=, Hostname= identique au nom de l’hôte).
  • zabbix_agent2 -t sur la machine, zabbix_get depuis le serveur.
  • Un modèle crée des dizaines de contrôles d’un coup : relire et ajuster.

Quiz

  1. Où Zabbix range-t-il sa configuration et ses mesures ?
  2. Que fait un proxy Zabbix, et dans quel cas en installe-t-on un ?
  3. Différence entre un élément et un déclencheur ?
  4. Que représente la clé vfs.fs.size[/,pused] ?
  5. Un agent est réglé avec Server=10.20.3.40. Que se passe-t-il si on l’interroge avec zabbix_get depuis 10.20.3.20 ?
  6. En contrôle actif, pourquoi Hostname= doit-il être identique au nom de l’hôte dans l’interface ?
  7. Pourquoi la base d’un Zabbix grossit-elle avec le temps, et comment limite-t-on sa taille ?
  8. À quoi sert une macro comme {$VFS.FS.PUSED.MAX.WARN} dans un modèle ?
  9. Que crée la découverte de bas niveau sur un serveur Windows lié au modèle Windows by Zabbix agent ?
  10. Citez deux avantages de Zabbix sur Nagios, et un inconvénient.
Voir la correction
  1. Dans la base de données (MariaDB ou PostgreSQL), pour les deux.
  2. Il collecte pour le compte du serveur dans un site distant ou un réseau isolé, garde les données en cas de coupure et les transmet ensuite ; on l’installe pour un site distant, une zone isolée par un pare-feu, ou pour répartir la charge.
  3. L’élément mesure (une valeur par intervalle) ; le déclencheur évalue une condition sur des éléments et passe à l’état problème.
  4. Le pourcentage d’espace utilisé du système de fichiers monté sur /.
  5. L’agent refuse : la connexion est fermée sans réponse (zabbix_get signale une réponse vide), et l’agent note le refus dans son journal.
  6. L’agent se présente au serveur sous ce nom pour obtenir la liste de ses éléments et envoyer ses valeurs : si le nom ne correspond à aucun hôte, le serveur ignore ses données.
  7. Chaque valeur est stockée ; on limite la durée d’historique et de tendances, et le housekeeper supprime ce qui a expiré. On choisit aussi des intervalles raisonnables.
  8. C’est un seuil réglable : le déclencheur du modèle l’utilise, et on peut le redéfinir sur un hôte (par exemple 85 % au lieu de 80 %) sans modifier le modèle.
  9. Un élément d’état et un déclencheur pour chaque service Windows en démarrage automatique (et pour chaque disque, chaque interface).
  10. Avantages : historique et graphiques intégrés, configuration par l’interface, modèles et découverte, agents riches. Inconvénient : plus lourd (base de données à dimensionner et à sauvegarder), plus complexe à prendre en main.
