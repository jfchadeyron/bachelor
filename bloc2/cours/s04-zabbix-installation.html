Cours de la séance 4

Zabbix : architecture et agents

Zabbix réunit dans un seul outil ce que Nagios laisse à des modules : collecte, historique dans une base de données, seuils, alertes, graphiques et tableaux de bord, configurés par une interface web. Son architecture, son vocabulaire et ses agents ; le TP l'installe et supervise les serveurs Linux et Windows d'Hexalog.

Chez vous Quiz (10 min)

1. Zabbix en quelques mots

Zabbix est libre (AGPL depuis la 7.0), développé par la société lettone Zabbix SIA. Une version LTS sort environ tous les deux ans, maintenue cinq ans : la 7.0 LTS (juin 2024, support complet jusqu’en juin 2027) est celle du bloc et la plus répandue en entreprise. Les versions intermédiaires (7.2, 7.4) ne vivent que quelques mois : on les évite en production.

2. L’architecture

Composant Rôle
Serveur interroge les agents, reçoit les envois, fait les pings (fping), évalue les déclencheurs, envoie les alertes, purge l’historique (housekeeper)
Base de données toute la configuration et toutes les mesures (MariaDB ou PostgreSQL)
Interface web application PHP qui lit la base : configuration, graphiques, tableaux de bord
Agent 2 collecte sur la machine ; greffons MySQL, Docker, certificats…
Proxy collecte pour le serveur dans un site distant, garde les données si le lien tombe

Ports à retenir : 10050 (l’agent écoute) et 10051 (le serveur écoute : agents actifs, proxys).

3. Le modèle de données

Terme Sens
Hôte, groupe d’hôtes une machine ; un regroupement (Hexalog/Linux), aussi pour les droits
Interface comment joindre l’hôte : Agent 10.20.N.20:10050, SNMP…
Élément (item) une mesure : une clé, un intervalle, une durée de conservation
Déclencheur (trigger) une expression sur des éléments, avec une sévérité
Problème un déclencheur en état PROBLÈME, jusqu’à son rétablissement
Modèle (template) éléments, déclencheurs, graphiques et découvertes prêts à l’emploi, qu’on lie à des hôtes
Macro {$NOM} une variable du modèle, redéfinissable sur un hôte (seuils)
Découverte de bas niveau trouve les disques, interfaces, services d’un hôte et crée leurs éléments à partir de prototypes
Étiquette (tag) service:intranet, pour filtrer et router les alertes
Clé Mesure
agent.ping l’agent répond
system.cpu.load[all,avg1] charge sur 1 minute
vfs.fs.size[/,pused] pourcentage utilisé de /
proc.num[nginx] nombre de processus nginx
service.info[DNS,state] état du service Windows DNS
log[/var/log/auth.log,"Failed password"] lignes d’un journal contenant un motif

Historique et tendances : chaque valeur est gardée quelques jours (historique), puis seulement min/moyenne/max par heure (tendances) pendant un an ou plus. C’est ce qui permet la maintenance prévisionnelle, et ce qui fait grossir la base : son dimensionnement est le principal souci d’exploitation.

4. Les agents

Contrôle passif Contrôle actif
Qui ouvre le serveur → agent (10050) l’agent → serveur (10051)
Réglage de l’agent Server= : qui peut l’interroger ServerActive= : où envoyer ; Hostname= identique au nom de l’hôte
Intérêt simple, l’absence de réponse se voit tout de suite traverse un pare-feu dans un seul sens ; indispensable pour les journaux (log[], eventlog[])

On ne modifie pas le fichier du paquet : on dépose le sien, qui remplace les valeurs par défaut.

ExempleFichier : /etc/zabbix/zabbix_agent2.d/hexalog.confà lire, pas à taper
Server=10.20.N.40
ServerActive=10.20.N.40
Hostname=srv-lnx-01

Tester : zabbix_agent2 -t <clé> sur la machine (calcul local) ; zabbix_get -s <adresse> -k <clé> depuis le serveur (comme le fera Zabbix).

Sécuriser : Server= (adresses autorisées) ; chiffrement par clé partagée (PSK) ou certificats ; system.run (exécuter une commande) désactivé par défaut ; l’agent tourne sous le compte zabbix, sans privilèges.

5. Installer Zabbix

Debian 13 contient Zabbix 7.0, mais le dépôt de l’éditeur apporte des correctifs plus récents : c’est la méthode recommandée pour le serveur.

Pour l’interface en français, la locale fr_FR.UTF-8 doit exister. La traduction est incomplète : les TP donnent les deux noms, par exemple Collecte de données → Hôtes (Data collection → Hosts).

6. Les modèles fournis

Modèle Lié à Ce qu’il apporte
Linux by Zabbix agent srv-lnx-01 processeur, mémoire, disques et interfaces découverts
Nginx by Zabbix agent, PHP-FPM by Zabbix agent srv-lnx-01 connexions, requêtes, files d’attente (pages de statut)
MySQL by Zabbix agent 2 srv-lnx-01 disponibilité et activité de MariaDB (macros {$MYSQL.*} à renseigner)
Windows by Zabbix agent srv-win-01 processeur, mémoire, disques, et chaque service en démarrage automatique
ICMP Ping tous joignabilité, pertes, temps de réponse

Lier un modèle crée des dizaines de contrôles d’un coup : c’est la grande différence avec Nagios. Mais un modèle ne connaît pas votre contexte : il faut relire et ajuster (séance 5).

8. Nagios et Zabbix

Nagios Core Zabbix
Configuration fichiers texte interface web, API
Mesures dernier état ; données de performance via un module historique et tendances dans une base
Seuils dans la ligne du plugin dans des déclencheurs, séparés de la collecte
Graphiques, découverte modules externes ; non intégrés
Ressources très léger base à dimensionner et à sauvegarder

9. À retenir

Points clés

  • Serveur, base (configuration et mesures), interface PHP, agents, proxys.
  • Élément (clé) → déclencheur (expression + sévérité) → problème → action ; modèles, macros, découverte.
  • Historique court, tendances longues : la base grossit, le housekeeper purge.
  • Passif : serveur → 10050 (Server=) ; actif : agent → 10051 (ServerActive=, Hostname= identique).
  • zabbix_agent2 -t sur la machine, zabbix_get depuis le serveur.
  • Un modèle crée des dizaines de contrôles : relire et ajuster.

Quiz

  1. Où Zabbix range-t-il sa configuration et ses mesures ?
  2. Que fait un proxy Zabbix, et dans quel cas en installe-t-on un ?
  3. Différence entre un élément et un déclencheur ?
  4. Que représente la clé vfs.fs.size[/,pused] ?
  5. Un agent est réglé avec Server=10.20.3.40. Que se passe-t-il si on l’interroge avec zabbix_get depuis 10.20.3.20 ?
  6. En contrôle actif, pourquoi Hostname= doit-il être identique au nom de l’hôte dans l’interface ?
  7. Pourquoi la base d’un Zabbix grossit-elle avec le temps, et comment limite-t-on sa taille ?
  8. À quoi sert une macro comme {$VFS.FS.PUSED.MAX.WARN} dans un modèle ?
  9. Que crée la découverte de bas niveau sur un serveur Windows lié au modèle Windows by Zabbix agent ?
  10. Citez deux avantages de Zabbix sur Nagios, et un inconvénient.
Voir la correction
  1. Dans la base de données (MariaDB ou PostgreSQL), pour les deux.
  2. Il collecte pour le compte du serveur dans un site distant ou un réseau isolé, garde les données en cas de coupure et les transmet ensuite ; on l’installe pour un site distant, une zone isolée par un pare-feu, ou pour répartir la charge.
  3. L’élément mesure (une valeur par intervalle) ; le déclencheur évalue une condition sur des éléments et passe à l’état problème.
  4. Le pourcentage d’espace utilisé du système de fichiers monté sur /.
  5. L’agent refuse : la connexion est fermée sans réponse (zabbix_get signale une réponse vide), et l’agent note le refus dans son journal.
  6. L’agent se présente au serveur sous ce nom pour obtenir la liste de ses éléments et envoyer ses valeurs : si le nom ne correspond à aucun hôte, le serveur ignore ses données.
  7. Chaque valeur est stockée ; on limite la durée d’historique et de tendances, et le housekeeper supprime ce qui a expiré. On choisit aussi des intervalles raisonnables.
  8. C’est un seuil réglable : le déclencheur du modèle l’utilise, et on peut le redéfinir sur un hôte (par exemple 85 % au lieu de 80 %) sans modifier le modèle.
  9. Un élément d’état et un déclencheur pour chaque service Windows en démarrage automatique (et pour chaque disque, chaque interface).
  10. Avantages : historique et graphiques intégrés, configuration par l’interface, modèles et découverte, agents riches. Inconvénient : plus lourd (base de données à dimensionner et à sauvegarder), plus complexe à prendre en main.
