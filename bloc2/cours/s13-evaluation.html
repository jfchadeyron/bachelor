Cours de la séance 13

Évaluation finale

La dernière séance est consacrée à l'évaluation finale : une étude de cas écrite sur une autre entreprise, puis une mise en situation sur votre lab, qui reprend le travail d'une équipe d'exploitation : superviser un nouveau service, traiter des incidents, restaurer des données, et en rendre compte. Cette page présente le déroulement, ce qui est évalué et une fiche de révision.

Durée4 h
Prérequisséances 1 à 12 ; lab dans l'état des snapshots 12-lab-final
Sommaire
  • Déroulement
  • Ce qui est évalué
  • Fiche de révision
  • Conseils

Déroulement

Temps Activité
15 min Vérification que chaque lab démarre depuis 12-lab-final, questions
1 h Partie 1 : étude de cas écrite
2 h 30 Partie 2 : mise en situation sur votre lab (pause libre)
15 min Bilan du bloc

Le sujet précise les documents autorisés et le barème. Pendant la partie 2, vous travaillez comme pendant l’astreinte : chaque action est datée et notée, chaque incident a un ticket.

Ce qui est évalué

Axe Vous devez savoir
1. Superviser choisir quoi surveiller et comment pour un service ; configurer la collecte, un déclencheur pertinent, une alerte, un tableau de bord ; choisir et justifier un outil
2. Traiter les incidents qualifier et prioriser ; diagnostiquer avec méthode ; rétablir et vérifier ; tenir le ticket et communiquer
3. Maintenir conduire un changement avec maintenance, vérification et traçabilité ; exploiter les journaux centralisés
4. Sauvegarder et reprendre analyser l’impact, fixer RTO et RPO, proposer une stratégie de sauvegarde et de reprise ; restaurer des données et le prouver
5. Rendre compte chronologie horodatée, compte rendu après incident, preuves (captures, journaux, tickets)

Fiche de révision

MCO et indicateurs (séance 1)

  • MCO, MCS ; maintenance corrective (palliative, curative), préventive (systématique, conditionnelle, prévisionnelle), évolutive.
  • Disponibilité ; 99,9 % = 43 min par mois ; série (on multiplie les disponibilités), parallèle (on multiplie les indisponibilités) ; disponibilité = MTBF / (MTBF + MTTR) ; MTTD, MTTA, MTTR.
  • SLI, SLO, SLA, budget d’erreur ; boîte blanche, boîte noire ; métrique, état, événement, journal ; seuil, durée, hystérésis ; alerte actionnable, fatigue d’alerte.
  • Proxmox VE : type 1, pool, VNet, image ISO, périphériques VirtIO, agent invité, snapshot.

Collecte et outils (séances 2 à 6)

  • Interrogation ou envoi, avec ou sans agent ; ping, port, test applicatif.
  • Plugins : codes 0, 1, 2, 3 ; données de performance ; seuils 10, 10:, 10:20, @10:20.
  • SNMP : UDP 161, traps 162 ; OID, MIB ; v2c (communauté en clair), v3 authPriv.
  • Nagios : objets, modèles, macros ; SOFT et HARD ; délai de détection ; parents, dépendances ; NRPE (5666), NCPA ; acquitter, planifier un arrêt.
  • Zabbix 7.0 : serveur, base, interface, agents (10050 passif, 10051 actif), proxy ; hôte, élément, déclencheur, modèle, macro, découverte, étiquette ; last, min, avg, count, nodata, timeleft ; récupération, dépendances ; actions, médias, escalades ; maintenance ; scénarios web ; services et SLA.
  • PRTG : sonde, groupe, appareil, capteur, canal ; licence par capteurs ; WMI, SNMP, HTTP.
  • Choisir un outil : besoin, coût, compétences, fonctions, échelle, pérennité, sécurité.

Journaux et maintenance (séance 7)

  • syslog (facilité, sévérité ; UDP, TCP, TLS) ; journald et rsyslog ; omfwd avec file d’attente, imtcp ; rotation ; heure (NTP) ; conservation (CNIL : six mois à un an) ; log[] et eventlog[].
  • Plan de maintenance ; unattended-upgrades ; CVE, CVSS, failles exploitées ; changement standard, normal, urgent ; RFC ; journal des modifications ; capacité.

Incidents (séances 8 et 9)

  • Événement, alerte, incident, demande, problème, erreur connue, contournement, changement.
  • Cycle de vie du ticket ; priorité = impact × urgence ; SLA, OLA, TTO, TTR ; niveaux 0 à 3 ; escalade ; incident majeur et communication.
  • Méthode de diagnostic ; couche par couche ; fiches réflexes ; main courante ; cinq pourquoi ; post-mortem sans recherche de coupable.

Sauvegarde et reprise (séances 10 et 11)

  • Snapshot, réplication, sauvegarde ; complète, différentielle, incrémentale, déduplication ; 3-2-1-1-0 ; cohérence (agent invité, mariadb-dump --single-transaction, état du système) ; GFS ; PBS ; tester la restauration ; superviser l’âge des sauvegardes ; tirer plutôt que pousser.
  • PCA, PRA ; BIA ; DMIA, PDMA, RTO, RPO ; stratégies et coûts ; ordre de reprise ; rançongiciel : isoler, déclarer, préserver, ne pas payer, point d’entrée, restaurer sain, changer les secrets, CNIL sous 72 h ; tests et retour d’expérience.

Conseils

  • Lisez tout le sujet avant de commencer la partie 2, et commencez par ce qui rapporte le plus.
  • Notez l’heure de chaque action dès le début : la chronologie demandée à la fin se construit pendant, pas après.
  • Diagnostiquez avant de corriger : un suivi de ticket qui montre la démarche vaut des points, même si la panne résiste.
  • Vérifiez côté utilisateur : « le service tourne » n’est pas « le service est rendu ».
  • Aucun mot de passe dans vos comptes rendus.
