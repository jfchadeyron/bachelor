Cours de la séance 2

Collecter les mesures : ICMP, SNMP, agents

Avant de parler d'outils, il faut comprendre comment un serveur de supervision obtient ses informations : en testant de l'extérieur, en interrogeant un agent, en recevant des messages. Cette séance présente les méthodes de collecte, le contrat des plugins de supervision, le protocole SNMP et les agents, ainsi que les flux réseau et les précautions de sécurité qui vont avec.

1. Comment le serveur de supervision obtient-il l’information ?

Trois questions permettent de décrire n’importe quelle méthode de collecte :

  • Qui prend l’initiative ? Le serveur de supervision va chercher l’information (interrogation, pull), ou la machine supervisée l’envoie d’elle-même (envoi, push).
  • Faut-il installer quelque chose ? Un agent (programme dédié installé sur la machine supervisée) ou rien de plus que les services déjà présents (supervision sans agent).
  • Que voit-on ? L’extérieur, comme un utilisateur (boîte noire), ou l’intérieur de la machine (boîte blanche).
Méthode Initiative Agent Vue Exemple dans le bloc
Ping, test d’un port TCP serveur non boîte noire srv-win-01 répond-il ? le port 389 est-il ouvert ?
Test applicatif (HTTP, DNS, LDAP) serveur non boîte noire la page sante.php contient-elle BASE-OK ?
SNMP : requêtes serveur le service SNMP de la machine boîte blanche charge et disques de srv-lnx-01
SNMP : traps machine le service SNMP événement un commutateur signale un port tombé
NRPE, NCPA serveur oui boîte blanche Nagios demande à srv-lnx-01 l’espace disque
Agent Zabbix, contrôles passifs serveur oui boîte blanche le serveur Zabbix interroge l’agent sur le port 10050
Agent Zabbix, contrôles actifs agent oui boîte blanche l’agent envoie ses mesures au port 10051 du serveur
WMI (Windows) serveur non (service intégré à Windows) boîte blanche PRTG lit le processeur et les services de srv-win-01
Syslog machine le service de journalisation journaux srv-lnx-01 envoie ses journaux à sup-lnx-01

Actif et passif : attention au vocabulaire

Les mots changent de sens selon l’outil. Dans Nagios, un contrôle actif est lancé par Nagios ; un contrôle passif est un résultat qu’on lui envoie. Dans Zabbix, un agent passif attend qu’on l’interroge ; un agent actif envoie lui-même ses mesures au serveur. Dans les deux cas, demandez-vous simplement : qui ouvre la connexion ? C’est aussi ce qui détermine les règles de pare-feu.

Avec ou sans agent ?

Avec agent Sans agent
Ce qu’on peut mesurer tout ce que la machine voit : processus, fichiers, journaux, services ce que le réseau et les protocoles standard exposent
Installation un logiciel à déployer, configurer, mettre à jour sur chaque machine rien (ou un service intégré à activer : SNMP, WMI)
Sécurité un service de plus qui écoute, parfois avec des droits élevés identifiants à confier au serveur de supervision (communauté SNMP, compte WMI)
Équipements fermés (commutateurs, onduleurs, imprimantes) impossible SNMP est souvent le seul moyen

2. Tester de l’extérieur

Chaque test prouve quelque chose de précis, et rien de plus :

Test Prouve que… Ne prouve pas que…
Ping (ICMP) la machine est allumée et sa pile réseau répond les services fonctionnent ; un ping refusé ne prouve pas non plus que la machine est éteinte (pare-feu)
Port TCP un programme écoute sur ce port et accepte la connexion ce programme répond correctement
Test applicatif le service répond comme attendu : code HTTP, contenu, temps de réponse, réponse DNS correcte toutes les fonctions de l’application sont disponibles

On les enchaîne pour localiser une panne : ping OK, port 80 OK, mais page en erreur 500 → le réseau et nginx vont bien, le problème est dans l’application ou sa base.

3. Les plugins de supervision

Nagios a imposé une convention très simple, reprise par Icinga, Centreon, Checkmk, Naemon et utilisable par Zabbix : un plugin est un programme qui fait un test, puis affiche une ligne de texte et se termine avec un code retour.

Code retour État Sens
0 OK tout va bien
1 WARNING (avertissement) seuil d’avertissement franchi
2 CRITICAL (critique) seuil critique franchi ou service en panne
3 UNKNOWN (inconnu) le test n’a pas pu être réalisé (mauvais argument, délai dépassé, plugin absent)

Le projet Monitoring Plugins fournit une cinquantaine de plugins standard (check_ping, check_tcp, check_http, check_disk, check_load, check_snmp…) ; sous Debian, ils sont dans /usr/lib/nagios/plugins.

ExempleMachine : exemple de résultatà lire, pas à taper
$ /usr/lib/nagios/plugins/check_disk -w 20% -c 10% -p /
DISK OK - free space: / 6532 MiB (68% inode=89%);| /=3061MiB;7880;8865;0;9850
$ echo $?
0

Après la barre verticale viennent les données de performance (perfdata), que l’outil enregistre pour faire des graphiques : étiquette=valeur[unité];avertissement;critique;minimum;maximum.

La notation des seuils

Les options -w (avertissement) et -c (critique) acceptent des plages. L’alerte se déclenche quand la valeur sort de la plage :

Notation Alerte si la valeur est… Exemple
10 supérieure à 10 (ou négative) charge : -w 4 -c 8
10: inférieure à 10 processus nginx : -c 1: (au moins un)
~:10 supérieure à 10 identique à 10, sans borne basse
10:20 hors de l’intervalle 10–20 température
@10:20 dans l’intervalle 10–20 plage interdite

Pour les disques, check_disk accepte aussi des pourcentages d’espace libre : -w 20% -c 10% signifie « avertissement sous 20 % libres, critique sous 10 % ».

Écrire son propre plugin est facile : un script qui teste quelque chose, affiche une ligne et sort avec le bon code. C’est ce qui rend ces outils extensibles à presque tout.

4. SNMP

Les acteurs

SNMP (Simple Network Management Protocol) est le protocole standard de supervision des équipements réseau, depuis 1988. Il met en relation :

  • un gestionnaire (manager) : le serveur de supervision, qui interroge ;
  • un agent : le service SNMP de l’équipement supervisé (snmpd sous Linux), qui répond sur le port UDP 161 ;
  • des traps : messages envoyés spontanément par l’agent au gestionnaire, sur le port UDP 162.

MIB et OID

Chaque information est désignée par un OID (Object Identifier), une suite de nombres qui forme un chemin dans un arbre mondial. Une MIB (Management Information Base) est un fichier texte qui décrit une branche de cet arbre : noms, types, unités, signification.

Objet OID Nom dans la MIB
description du système .1.3.6.1.2.1.1.1.0 SNMPv2-MIB::sysDescr.0
temps depuis le démarrage .1.3.6.1.2.1.1.3.0 DISMAN-EVENT-MIB::sysUpTimeInstance
nom de la machine .1.3.6.1.2.1.1.5.0 SNMPv2-MIB::sysName.0
état des interfaces .1.3.6.1.2.1.2.2.1.8 IF-MIB::ifOperStatus
octets reçus (compteur 64 bits) .1.3.6.1.2.1.31.1.1.1.6 IF-MIB::ifHCInOctets
espaces de stockage : nom, taille, utilisé .1.3.6.1.2.1.25.2.3.1.3, .5, .6 HOST-RESOURCES-MIB::hrStorageDescr, hrStorageSize, hrStorageUsed
charge sur 1, 5, 15 minutes .1.3.6.1.4.1.2021.10.1.3 UCD-SNMP-MIB::laLoad

Le .0 final désigne une valeur unique (scalaire) ; dans une table, le dernier nombre est l’index de la ligne (hrStorageDescr.31 = le 31ᵉ espace de stockage). Debian n’installe pas les MIB standard (pour des raisons de licence) : sans elles, les outils affichent les OID en chiffres. Le paquet snmp-mibs-downloader (dépôt non-free) les télécharge.

Les opérations

Opération Sens
GET lire un OID précis
GETNEXT, GETBULK lire l’OID suivant, ou un lot d’OID suivants (v2c et v3)
walk parcourir une branche entière par une suite de GETNEXT ou GETBULK (commande snmpwalk)
SET modifier une valeur (rarement autorisé)
TRAP, INFORM message spontané de l’agent ; l’INFORM attend un accusé de réception

Beaucoup de valeurs sont des compteurs qui ne font qu’augmenter (octets reçus par une interface) : l’outil calcule le débit en faisant la différence entre deux lectures, divisée par le temps écoulé. Les compteurs 32 bits débordent vite sur un lien rapide ; on lit les compteurs 64 bits (ifHCInOctets).

Les versions

Version Authentification Chiffrement Remarques
v1 (1988) « communauté », en clair aucun obsolète
v2c « communauté », en clair aucun GETBULK, compteurs 64 bits ; toujours très répandue
v3 utilisateur et mot de passe, condensé HMAC (SHA-2) AES trois niveaux : noAuthNoPriv, authNoPriv, authPriv (authentifié et chiffré)

La communauté de v1 et v2c n’est qu’un mot de passe qui circule en clair : quiconque écoute le réseau la lit. La valeur par défaut public est connue de tous. Avec v2c, on se limite donc à la lecture seule, depuis la seule adresse du serveur de supervision, avec une communauté non triviale. Dès que possible, on utilise v3 en authPriv.

Et Windows ?

Microsoft a déclaré le service SNMP de Windows obsolète depuis Windows Server 2012 : il existe encore comme fonctionnalité facultative, mais n’évolue plus. Pour Windows, on utilise un agent (Zabbix, NCPA) ou WMI. SNMP reste incontournable pour le matériel réseau, les onduleurs, les imprimantes, les NAS et les hyperviseurs.

5. Les agents

Agent Outil Port, sens Principe
NRPE Nagios serveur → agent, 5666/tcp (TLS) le serveur demande l’exécution d’une commande prédéfinie sur l’agent, qui renvoie le résultat du plugin
NCPA Nagios (multiplateforme) serveur → agent, 5693/tcp (HTTPS) une API qui expose processeur, mémoire, disques, services, processus ; protégée par un jeton
Zabbix agent 2 Zabbix passif : serveur → agent 10050/tcp ; actif : agent → serveur 10051/tcp collecte de centaines d’indicateurs prédéfinis (clés), extensions (MySQL, Docker…)
Sonde distante PRTG sonde → serveur central 23560/tcp une sonde installée dans un site distant interroge les machines locales et remonte les résultats
Exporter Prometheus serveur → exporter, HTTP (9100 pour node_exporter) une page web de métriques lue régulièrement par le serveur

6. Windows : WMI et compteurs de performance

WMI (Windows Management Instrumentation, implémentation de la norme CIM) donne accès à presque tout l’état d’une machine Windows sous forme de classes : Win32_OperatingSystem (mémoire, démarrage), Win32_LogicalDisk (disques), Win32_Service (services), Win32_PerfFormattedData_* (compteurs de performance). On l’interroge à distance par DCOM/RPC (port 135, puis un port dynamique) ou par WinRM (5985 en HTTP, 5986 en HTTPS).

Les compteurs de performance (Analyseur de performances, perfmon) mesurent processeur, mémoire, disques, réseau et chaque rôle (DNS, AD). Le journal des événements complète le tableau : un service qui s’arrête, une ouverture de session refusée (4625), un verrouillage de compte (4740), vus au BLOC 1.

L’accès WMI à distance demande un compte administrateur de la machine (ou des droits finement délégués, difficiles à régler) : c’est l’un des points faibles de la supervision sans agent sous Windows.

7. Les flux de supervision

La supervision crée des flux réseau qu’il faut autoriser, et seulement ceux-là. On les décrit dans une matrice des flux (source, destination, port, protocole, sens, justification), comme celle de la page du lab.

Deux principes :

  • le serveur de supervision est une machine sensible : il joint toutes les autres, détient des identifiants (communautés, comptes WMI, jetons) et donne une carte complète du système d’information. Il doit être aussi protégé qu’un contrôleur de domaine ;
  • dans les infrastructures importantes, les flux d’administration et de supervision passent par un réseau d’administration séparé du réseau des utilisateurs.

8. Sécuriser la collecte

Risque Mesure
quelqu’un interroge l’agent à la place du serveur restreindre par adresse : allowed_hosts (NRPE), Server= (Zabbix), rocommunity … 10.20.N.40 (SNMP)
quelqu’un écoute le réseau chiffrer : SNMPv3 authPriv, TLS de NRPE, chiffrement PSK ou certificats de Zabbix, HTTPS de NCPA
l’agent exécute n’importe quoi commandes prédéfinies seulement (dont_blame_nrpe=0), pas de commandes distantes dans Zabbix
identifiants trop puissants lecture seule, comptes dédiés, droits minimaux
identifiants visibles dans des fichiers lisibles par le seul service (resource.cfg de Nagios), jamais en clair dans un tableau de bord
logiciel de supervision vulnérable mises à jour régulières ; en 2020, la compromission de la chaîne de mise à jour d’un outil de supervision très répandu (SolarWinds Orion) a ouvert l’accès à des milliers d’organisations

9. À retenir

Points clés

  • Qui ouvre la connexion ? Interrogation (pull) ou envoi (push), avec ou sans agent, boîte noire ou blanche.
  • Ping, port, test applicatif : chacun prouve une chose précise ; on les enchaîne pour localiser une panne.
  • Plugin : une ligne de texte, un code retour (0 OK, 1 WARNING, 2 CRITICAL, 3 UNKNOWN), des données de performance après |. Seuils : 10, 10:, 10:20, @10:20.
  • SNMP : agent sur UDP 161, traps sur 162 ; OID et MIB ; GET, walk, trap ; v2c = communauté en clair, v3 authPriv = authentifié et chiffré.
  • Agents : NRPE (5666), NCPA (5693), Zabbix (10050 passif, 10051 actif). Windows : agent ou WMI ; SNMP Windows obsolète.
  • Matrice des flux ; serveur de supervision = machine sensible ; restreindre, chiffrer, moindre privilège.

Quiz

  1. Un agent Zabbix configuré en mode actif : qui ouvre la connexion, et vers quel port ?
  2. Le ping de srv-win-01 échoue. Peut-on conclure que la machine est éteinte ? Quel test feriez-vous ensuite ?
  3. Un plugin affiche HTTP CRITICAL - pattern not found et se termine avec le code 2. Que signifie le code 3 ?
  4. Que signifient -w 10: -c 5: pour un contrôle du nombre de processus ?
  5. Dans DISK OK - free space: / 6532 MiB (68%);| /=3061MiB;7880;8865;0;9850, que représentent 7880 et 8865 ?
  6. Que désigne l’OID .1.3.6.1.2.1.1.5.0 ? Pourquoi se termine-t-il par .0 ?
  7. Pourquoi la communauté public est-elle dangereuse, même en lecture seule ?
  8. Quel niveau de sécurité SNMPv3 faut-il choisir, et que garantit-il ?
  9. Pourquoi ne supervise-t-on plus les serveurs Windows récents en SNMP ?
  10. Citez trois mesures qui empêchent un attaquant d’utiliser vos agents de supervision.
Voir la correction
  1. L’agent ouvre la connexion vers le port 10051 du serveur Zabbix.
  2. Non : le pare-feu de Windows peut refuser le ping (règle désactivée par défaut). On teste un port (check_tcp -p 3389 ou 389) ou un service (DNS).
  3. UNKNOWN : le test n’a pas pu être réalisé (argument invalide, délai dépassé, plugin introuvable).
  4. Avertissement s’il y a moins de 10 processus, critique s’il y en a moins de 5.
  5. Les seuils d’avertissement et critique, convertis en espace utilisé (en Mio) ; 0 et 9850 sont le minimum et le maximum.
  6. sysName, le nom de la machine ; .0 désigne l’instance unique d’un objet scalaire (pas une ligne de table).
  7. Elle est connue de tous et circule en clair : n’importe qui sur le réseau peut lire la configuration (interfaces, adresses, processus, logiciels), ce qui aide à préparer une attaque.
  8. authPriv : les messages sont authentifiés (on sait qu’ils viennent de l’utilisateur prévu et n’ont pas été modifiés) et chiffrés (personne ne peut les lire).
  9. Microsoft a déclaré le service SNMP de Windows obsolète depuis Windows Server 2012 ; on utilise un agent ou WMI.
  10. Restriction par adresse source, chiffrement (TLS, SNMPv3, PSK), commandes prédéfinies seulement, droits minimaux, mises à jour, filtrage par pare-feu.
