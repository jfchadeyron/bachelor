Chez vous Quiz (10 min)

1. Comment le serveur obtient-il l’information ?

Trois questions décrivent n’importe quelle méthode : qui ouvre la connexion (le serveur interroge, pull, ou la machine envoie, push) ? Faut-il un agent ? Voit-on l’extérieur (boîte noire) ou l’intérieur (boîte blanche) ?

Méthode Qui ouvre Agent Exemple dans le bloc
Ping, port TCP, test HTTP/DNS serveur non la page sante.php contient-elle BASE-OK ?
SNMP (requêtes) serveur service SNMP charge et disques de srv-lnx-01
SNMP (traps) machine service SNMP un commutateur signale un port tombé
NRPE, NCPA serveur oui Nagios demande l’espace disque
Agent Zabbix passif / actif serveur / agent oui port 10050 / port 10051
WMI serveur non (intégré à Windows) PRTG lit les services de srv-win-01
Syslog machine service de journalisation srv-lnx-01 envoie ses journaux

Actif et passif : attention au vocabulaire

Dans Nagios, un contrôle actif est lancé par Nagios ; dans Zabbix, un agent actif envoie lui-même ses mesures. Posez-vous toujours la même question : qui ouvre la connexion ? C’est elle qui fixe les règles de pare-feu.

Avec agent Sans agent
Ce qu’on voit tout : processus, fichiers, journaux ce que les protocoles standard exposent
Installation un logiciel à déployer et maintenir partout rien, ou un service à activer (SNMP, WMI)
Sécurité un service de plus qui écoute des identifiants confiés au serveur
Équipement fermé (commutateur, onduleur) impossible SNMP, souvent le seul moyen

2. Tester de l’extérieur

Test Prouve que… Ne prouve pas que…
Ping la pile réseau répond les services marchent ; un ping refusé ne prouve pas que la machine est éteinte (pare-feu)
Port TCP un programme écoute et accepte il répond correctement
Test applicatif le service répond comme attendu (code, contenu, délai) toute l’application fonctionne

On les enchaîne pour localiser : ping OK, port 80 OK, page en erreur 500 → le problème est dans l’application ou sa base.

3. Les plugins de supervision

Convention de Nagios, reprise par Icinga, Centreon, Checkmk et utilisable par Zabbix : un plugin fait un test, affiche une ligne et sort avec un code retour.

Code État Sens
0 OK tout va bien
1 WARNING seuil d’avertissement franchi
2 CRITICAL seuil critique franchi, ou service en panne
3 UNKNOWN test impossible (argument, délai, plugin absent)

Les Monitoring Plugins (check_ping, check_tcp, check_http, check_disk, check_snmp…) sont dans /usr/lib/nagios/plugins sous Debian.

ExempleMachine : exemple de résultatà lire, pas à taper
$ /usr/lib/nagios/plugins/check_disk -w 20% -c 10% -p /
DISK OK - free space: / 6532 MiB (68% inode=89%);| /=3061MiB;7880;8865;0;9850
$ echo $?
0

Après la barre | : les données de performance, que l’outil enregistre pour les graphiques (étiquette=valeur;avertissement;critique;min;max).

La notation des seuils

L’alerte se déclenche quand la valeur sort de la plage :

Notation Alerte si la valeur est… Exemple
10 supérieure à 10 charge : -w 4 -c 8
10: inférieure à 10 au moins un processus nginx : -c 1:
10:20 hors de 10–20 température
@10:20 dans 10–20 plage interdite

Pour check_disk, -w 20% -c 10% signifie « moins de 20 % / 10 % libres ». Écrire son propre plugin est simple : un script qui teste, affiche une ligne et sort avec le bon code (TP, partie B).

4. SNMP

SNMP est le protocole standard de supervision des équipements réseau. Le gestionnaire (le serveur de supervision) interroge l’agent (snmpd) sur UDP 161 ; l’agent peut aussi envoyer des traps sur UDP 162.

MIB et OID

Chaque information a un OID, un chemin de nombres dans un arbre mondial. Une MIB est un fichier qui décrit une branche : noms, types, unités.

Objet OID Nom
nom de la machine .1.3.6.1.2.1.1.5.0 SNMPv2-MIB::sysName.0
état des interfaces .1.3.6.1.2.1.2.2.1.8 IF-MIB::ifOperStatus
octets reçus (64 bits) .1.3.6.1.2.1.31.1.1.1.6 IF-MIB::ifHCInOctets
stockages : nom, taille, utilisé .1.3.6.1.2.1.25.2.3.1.3, .5, .6 HOST-RESOURCES-MIB::hrStorage…
charge 1, 5, 15 min .1.3.6.1.4.1.2021.10.1.3 UCD-SNMP-MIB::laLoad

Le .0 final désigne une valeur unique ; dans une table, le dernier nombre est l’index de la ligne. Debian n’installe pas les MIB standard (licence) : sans elles, on voit des OID en chiffres.

Opérations : GET (un OID), walk (une branche, commande snmpwalk), SET (rarement autorisé), TRAP. Beaucoup de valeurs sont des compteurs : le débit se calcule par différence entre deux lectures.

Les versions

Version Authentification Chiffrement
v1, v2c « communauté », en clair aucun
v3 utilisateur, mot de passe (SHA-2) AES, au niveau authPriv

La communauté n’est qu’un mot de passe qui circule en clair, et public est connue de tous. En v2c : lecture seule, depuis la seule adresse du serveur, communauté non triviale. Dès que possible : v3 authPriv.

Et Windows ?

Le service SNMP de Windows est obsolète depuis Windows Server 2012. Pour Windows : un agent ou WMI. SNMP reste incontournable pour le matériel réseau, les onduleurs, les imprimantes, les NAS.

5. Les agents

Agent Outil Port, sens
NRPE Nagios serveur → agent, 5666/tcp ; exécute des commandes prédéfinies
NCPA Nagios serveur → agent, 5693/tcp (HTTPS, jeton)
Zabbix agent 2 Zabbix passif 10050/tcp ; actif → serveur 10051/tcp
Sonde distante PRTG sonde → serveur 23560/tcp
Exporter Prometheus serveur → exporter, HTTP (9100)

6. Windows : WMI et compteurs

WMI expose l’état de Windows sous forme de classes (Win32_LogicalDisk, Win32_Service, compteurs de performance), interrogées à distance par DCOM/RPC (135 puis un port dynamique) ou WinRM (5985/5986). Il faut un compte administrateur de la machine : c’est le point faible du sans-agent sous Windows. Le journal des événements complète (4625 : ouverture de session refusée ; 4740 : compte verrouillé).

7. Les flux de supervision

La supervision crée des flux qu’il faut autoriser, et seulement ceux-là : on les écrit dans une matrice des flux (source, destination, port, sens, justification), comme celle de la page du lab. Le serveur de supervision joint toutes les machines et détient des identifiants : il est aussi sensible qu’un contrôleur de domaine.

8. Sécuriser la collecte

Risque Mesure
quelqu’un interroge l’agent restreindre par adresse : allowed_hosts (NRPE), Server= (Zabbix), rocommunity … 10.20.N.40
quelqu’un écoute le réseau chiffrer : SNMPv3 authPriv, TLS, PSK
l’agent exécute n’importe quoi commandes prédéfinies seulement (dont_blame_nrpe=0)
identifiants trop puissants ou visibles lecture seule, comptes dédiés, fichiers lisibles par le seul service
outil de supervision vulnérable mises à jour (affaire SolarWinds Orion, 2020)

9. À retenir

Points clés

  • Qui ouvre la connexion ? Interrogation ou envoi, avec ou sans agent, boîte noire ou blanche.
  • Ping, port, test applicatif : chacun prouve une chose précise.
  • Plugin : une ligne, un code (0 OK, 1 WARNING, 2 CRITICAL, 3 UNKNOWN), des données de performance après |. Seuils : 10, 10:, 10:20, @10:20.
  • SNMP : UDP 161 (traps 162) ; OID, MIB ; v2c en clair, v3 authPriv authentifié et chiffré.
  • Agents : NRPE 5666, NCPA 5693, Zabbix 10050/10051. Windows : agent ou WMI.
  • Matrice des flux ; restreindre, chiffrer, moindre privilège.

Quiz

  1. Un agent Zabbix configuré en mode actif : qui ouvre la connexion, et vers quel port ?
  2. Le ping de srv-win-01 échoue. Peut-on conclure que la machine est éteinte ? Quel test feriez-vous ensuite ?
  3. Un plugin affiche HTTP CRITICAL - pattern not found et se termine avec le code 2. Que signifie le code 3 ?
  4. Que signifient -w 10: -c 5: pour un contrôle du nombre de processus ?
  5. Dans DISK OK - free space: / 6532 MiB (68%);| /=3061MiB;7880;8865;0;9850, que représentent 7880 et 8865 ?
  6. Que désigne l’OID .1.3.6.1.2.1.1.5.0 ? Pourquoi se termine-t-il par .0 ?
  7. Pourquoi la communauté public est-elle dangereuse, même en lecture seule ?
  8. Quel niveau de sécurité SNMPv3 faut-il choisir, et que garantit-il ?
  9. Pourquoi ne supervise-t-on plus les serveurs Windows récents en SNMP ?
  10. Citez trois mesures qui empêchent un attaquant d’utiliser vos agents de supervision.
Voir la correction
  1. L’agent ouvre la connexion vers le port 10051 du serveur Zabbix.
  2. Non : le pare-feu de Windows peut refuser le ping (règle désactivée par défaut). On teste un port (check_tcp -p 3389 ou 389) ou un service (DNS).
  3. UNKNOWN : le test n’a pas pu être réalisé (argument invalide, délai dépassé, plugin introuvable).
  4. Avertissement s’il y a moins de 10 processus, critique s’il y en a moins de 5.
  5. Les seuils d’avertissement et critique, convertis en espace utilisé (en Mio) ; 0 et 9850 sont le minimum et le maximum.
  6. sysName, le nom de la machine ; .0 désigne l’instance unique d’un objet scalaire (pas une ligne de table).
  7. Elle est connue de tous et circule en clair : n’importe qui sur le réseau peut lire la configuration (interfaces, adresses, processus, logiciels), ce qui aide à préparer une attaque.
  8. authPriv : les messages sont authentifiés (on sait qu’ils viennent de l’utilisateur prévu et n’ont pas été modifiés) et chiffrés (personne ne peut les lire).
  9. Microsoft a déclaré le service SNMP de Windows obsolète depuis Windows Server 2012 ; on utilise un agent ou WMI.
  10. Restriction par adresse source, chiffrement (TLS, SNMPv3, PSK), commandes prédéfinies seulement, droits minimaux, mises à jour, filtrage par pare-feu.
