Cours de la séance 7

Journaux centralisés et maintenance préventive

Les journaux racontent ce qui s'est passé ; encore faut-il qu'ils soient au même endroit, à la même heure, conservés assez longtemps et lus. La maintenance préventive, elle, évite que l'incident se produise : mises à jour, changements préparés et tracés, surveillance de la capacité.

1. Pourquoi centraliser les journaux

Au BLOC 1, vous lisiez les journaux machine par machine. Pour exploiter un système d’information, on les rassemble :

Besoin Ce que la centralisation apporte
Corréler suivre une intervention ou une attaque qui traverse plusieurs machines, en un seul endroit
Survivre à la machine les journaux d’un serveur perdu restent lisibles ailleurs
Résister à l’effacement un attaquant efface d’abord les traces locales ; la copie centrale reste
Détecter un outil lit en continu et alerte
Conserver une seule politique de rotation et de durée

2. syslog, journald et rsyslog

syslog (RFC 5424) : chaque message porte une facilité (qui l’émet : kern, auth/authpriv, daemon, cron, mail, user, local0 à local7) et une sévérité (de 0 emerg à 7 debug, en passant par 3 err, 4 warning, 6 info). La priorité vaut facilité × 8 + sévérité. Transport : UDP 514 (sans garantie), TCP 514 (fiable), TLS 6514 (chiffré).

  • journald reçoit tous les messages (journalctl). Depuis Debian 12, c’est le seul système d’une installation neuve : ni /var/log/syslog, ni /var/log/auth.log.
  • rsyslog, une fois installé, écrit les fichiers texte (lisibles par le groupe adm), envoie à un serveur central (action omfwd, en TCP, avec une file d’attente sur disque si le serveur est injoignable) et reçoit (module imtcp, un dossier par machine). On n’écrit que dans /etc/rsyslog.d/, et on vérifie avant de redémarrer : sudo rsyslogd -N1.

Le nom de la machine vient du message

Le serveur range les messages d’après le nom écrit dans le message : une machine autorisée peut prétendre s’appeler autrement. Le TP limite les émetteurs au réseau du lab et interdit les / dans ce nom (secpath-replace). En production : TLS avec certificats.

Windows ne parle pas syslog : on centralise par le transfert d’événements (un collecteur s’abonne aux événements des autres machines) ou par un agent (Zabbix eventlog[], NXLog, Wazuh). Au-delà, les plateformes de recherche (Graylog, OpenSearch, Loki) et les SIEM (Wazuh, Sentinel) corrèlent les événements de sécurité.

3. Fiabiliser : l’heure et le transport

Une chronologie n’a de sens que si toutes les machines sont à la même heure.

Élément Réglage
Synchronisation NTP (UDP 123) : systemd-timesyncd sur Debian, chrony sur Proxmox, W32Time sous Windows ; dans un domaine, les contrôleurs servent l’heure
Vérification timedatectl (System clock synchronized: yes), w32tm /query /status ; Zabbix signale System time is out of sync
Horodatage ISO 8601 avec décalage (2027-01-26T10:42:07+01:00)
Transport TCP, file d’attente sur disque, et supervision du serveur de journaux lui-même

4. Conserver et protéger

logrotate, chaque jour, renomme le fichier courant, compresse les anciens et supprime ceux qui dépassent la durée prévue (/etc/logrotate.d/).

Source Ce qu’elle dit
CNIL (délibération 2021-122) journaux d’accès et d’actions : six mois à un an en règle générale ; analyse automatique ; accès protégé
ANSSI centraliser, synchroniser l’heure, protéger l’intégrité, documenter la durée

La durée se décide, se justifie et s’écrit : trop court, on ne peut plus enquêter ; trop long, on garde des données personnelles sans raison. Car un journal contient identifiants, adresses IP, heures : ce sont des données personnelles (RGPD). D’où une finalité claire, un accès restreint (groupe adm), une durée limitée, une protection contre la modification.

5. Détecter dans les journaux

Système Clé Zabbix Exemple
Linux log[fichier,motif,,,skip] log[/var/log/auth.log,"Invalid user|Failed password|authenticating user",,,skip]
Windows eventlog[journal,,,,identifiant,,skip] eventlog[Security,,,,4625,,skip]
  • Contrôles actifs : l’agent lit le journal et envoie les nouvelles lignes (ServerActive=, Hostname= identique).
  • skip : seules les nouvelles lignes comptent.
  • Droit de lecture : sous Debian, le compte zabbix dans le groupe adm.

Le déclencheur compte : count(/srv-lnx-01/log[…],5m)>=5. Avec la clé SSH obligatoire, un essai par mot de passe échoue, mais révèle quelqu’un qui cherche : un signal faible.

6. La maintenance préventive

Les tâches préventives sont listées, planifiées, attribuées et prouvées :

Tâche Fréquence Preuve
Correctifs de sécurité Linux quotidienne, automatique journal de unattended-upgrades
Mises à jour complètes Linux et Windows mensuelle demande de changement
Vérification des sauvegardes ; test de restauration quotidienne ; trimestriel rapport de test (séance 10)
Espace disque, tendances, certificats mensuelle graphiques
Revue des comptes et des accès semestrielle rapport de revue
Debian Windows
Rythme sécurité au fil de l’eau (trixie-security) ; versions intermédiaires (13.1, 13.2…) tous les deux mois environ cumulatifs mensuels, deuxième mardi (Patch Tuesday)
Outils apt, unattended-upgrades Windows Update ; en entreprise WSUS, Intune
Redémarrage /run/reboot-required ; needrestart (à installer) souvent nécessaire

L’installateur de Debian installe et active par défaut unattended-upgrades, qui applique chaque matin les correctifs de sécurité et ceux des versions intermédiaires. Politique d’Hexalog : sécurité automatique, le reste pendant la maintenance mensuelle, avec demande de changement. L’urgence d’un correctif se juge sur la CVE, son score CVSS et surtout le fait qu’elle soit exploitée (alertes du CERT-FR).

Étendre la supervision : un paramètre utilisateur ajoute une clé à l’agent Zabbix, dont la valeur est la sortie d’une commande (l’équivalent du plugin écrit au TP 2) :

ExempleFichier : /etc/zabbix/zabbix_agent2.d/hexalog-maj.confà lire, pas à taper
UserParameter=hexalog.maj.attente,apt-get -s -o Debug::NoLocking=true upgrade | grep -c '^Inst' || true

7. La gestion des changements

La moitié des incidents viennent d’un changement. Le but : changer souvent et sans casse.

Type Définition Exemple Validation
Standard fréquent, faible risque, procédure éprouvée créer un compte pré-autorisé
Normal à évaluer à chaque fois mise à jour mensuelle responsable ou comité (CAB)
Urgent tout de suite (incident, faille exploitée) correctif du serveur web exposé accélérée, régularisée après

La demande de changement dit : quoi, pourquoi, sur quoi, quel impact, quel risque, comment on teste, comment on revient en arrière, quand (fenêtre), qui prévenir. La période de maintenance de Zabbix suspend les notifications ; le snapshot Proxmox est le retour arrière le plus simple (à supprimer une fois le changement validé).

8. La capacité

La maintenance prévisionnelle s’appuie sur les tendances : timeleft(/hôte/clé,période,seuil) donne le temps restant avant le seuil, forecast(/hôte/clé,période,horizon) la valeur prévue. Exemple : timeleft(/srv-lnx-01/vfs.fs.dependent.size[/,pused],1h,100)<1d signale que / sera plein dans moins d’un jour. On commande le disque avant d’en avoir besoin.

9. À retenir

Points clés

  • Centraliser pour corréler, survivre, résister à l’effacement, détecter, conserver.
  • syslog : facilité + sévérité ; UDP/TCP 514, TLS 6514. Debian 13 neuve : journald seul ; rsyslog écrit, envoie (omfwd, file sur disque) et reçoit (imtcp). rsyslogd -N1 avant de redémarrer.
  • Même heure partout (NTP) ; logrotate ; durée justifiée (CNIL : six mois à un an) ; journaux = données personnelles.
  • log[], eventlog[] : contrôles actifs, skip, groupe adm, count(…,5m).
  • Plan de maintenance ; unattended-upgrades actif par défaut ; CVE, CVSS, CERT-FR.
  • Changement standard, normal, urgent ; RFC avec impact, risque, test, retour arrière, fenêtre.
  • Capacité : timeleft(), forecast().

  4. Sur une Debian 13 que vous venez d’installer, ls /var/log/auth.log ne trouve rien. Est-ce normal ? Où sont les journaux ?
  5. Pourquoi l’heure de toutes les machines doit-elle être synchronisée ?

  10. Que doit contenir une demande de changement pour la mise à jour mensuelle d’un serveur ?

Voir la correction
  1. Corréler les événements de plusieurs machines ; lire les journaux d’une machine perdue ; résister à l’effacement des traces ; détecter automatiquement ; appliquer une seule politique de conservation.
  2. 4 × 8 + 4 = 36.
  3. TCP garantit la remise (UDP perd silencieusement les messages) ; la file d’attente garde les messages tant que le serveur est injoignable, puis les renvoie.
  4. Oui : une installation neuve de Debian n’a que journald ; les journaux sont dans le journal binaire (journalctl). Le fichier apparaît une fois rsyslog installé.
  5. Pour reconstituer une chronologie fiable entre machines (et parce que Kerberos et TLS refusent les écarts d’heure trop grands).
  6. Par exemple six mois à un an, selon la recommandation de la CNIL sur la journalisation, en l’écrivant dans la politique de journalisation avec sa justification.
  7. Le droit de lecture : le compte zabbix n’est pas membre du groupe adm (ou l’agent n’a pas été redémarré après l’ajout).
  8. Parce que c’est l’agent qui lit le fichier en continu, retient où il en est et envoie les nouvelles lignes ; le serveur ne peut pas demander « les nouvelles lignes depuis la dernière fois ».
  9. Standard : fréquent, à faible risque, procédure éprouvée, pré-autorisé (créer un compte). Normal : évalué et validé à chaque fois (mise à jour mensuelle, nouvelle version d’un logiciel).
  10. Les machines et services concernés, la raison, l’impact pendant l’intervention, le risque, les tests, le retour arrière (snapshot), la fenêtre, les personnes prévenues, puis la clôture.
  11. Au rythme de remplissage observé sur la dernière heure, / serait plein dans moins de 7 jours.
