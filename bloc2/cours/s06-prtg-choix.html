Cours de la séance 6

PRTG et le choix d'un outil

PRTG représente une troisième approche : un logiciel commercial, installé sous Windows, qui découvre le réseau tout seul et se configure en quelques clics. Avec trois expériences concrètes, vous pourrez répondre à la question de toute entreprise : quel outil de supervision choisir, pour quel contexte ?

Durée4 h
Prérequisséances 3 à 5 (Nagios, Zabbix)

Objectifs de la séance

Chez vous Quiz (10 min)

1. PRTG en quelques mots

PRTG Network Monitor (Paessler, Allemagne) s’installe sur Windows et se pilote par une interface web. Sa promesse : être opérationnel en une heure, grâce à la découverte automatique du réseau.

Édition Capteurs
Freeware 100, gratuite, même en entreprise
Essai illimité pendant 30 jours, puis Freeware
Commerciales 500 à plusieurs milliers, prix selon le nombre

Un capteur est un contrôle (un ping, un disque, un service). Un serveur en compte vite 10 à 15 : le coût dépend directement de ce qu’on décide de surveiller.

2. L’architecture

Le serveur central garde la configuration et les mesures (dans ses propres fichiers, sans base SQL) et sert l’interface ; la sonde locale fait les contrôles ; une sonde distante contrôle un autre site et renvoie les résultats par une seule connexion chiffrée.

Les réglages s’héritent de haut en bas : identifiants Windows, Linux, SNMP, intervalle, notifications se règlent une fois sur un groupe.

Couleur État
vert, jaune, rouge Up, Warning, Down
rouge clair Down (Acknowledged) : pris en charge
orange Unusual : valeur inhabituelle pour ce jour et cette heure
bleu, gris Paused (maintenance), Unknown

3. Les capteurs

Capteur Protocole Ce qu’il mesure
Ping ICMP joignabilité
WMI CPU Load, WMI Memory, WMI Free Disk Space WMI processeur, mémoire, disques Windows
WMI Service WMI un service Windows (DNS, NTDS)
SNMP Linux Load Average, Disk Free, Meminfo SNMP charge, disques, mémoire Linux
HTTP Advanced HTTP code, temps de réponse et contenu d’une page

Chaque canal a des limites (seuils d’avertissement et d’erreur). Les capteurs SSH supervisent Linux sans SNMP, mais il faut alors confier un compte à PRTG.

4. Les notifications

  • Le modèle de notification dit comment : courriel, SMS, application mobile, webhook, ticket interne.
  • Le déclencheur de notification, posé sur un capteur ou un groupe (et hérité), dit quand : Down depuis plus de 60 s, seuil sur un canal ; avec escalade si l’état dure.

5. Forces et limites

Forces Limites
installation et découverte très rapides serveur central sous Windows uniquement
interface complète, cartes, rapports coût par capteur : on hésite à tout surveiller
sans agent : WMI, SNMP, SSH, HTTP WMI demande des droits d’administrateur
sondes distantes, support de l’éditeur logiciel fermé, dépendance à l’éditeur

Nagios Core Zabbix PRTG Centreon Prometheus + Grafana

Éditeur Nagios Enterprises (États-Unis) Zabbix SIA (Lettonie) Paessler (Allemagne) Centreon (France) communauté (CNCF), Grafana Labs
Serveur Linux Linux Windows Linux Linux, conteneurs
Configuration fichiers texte interface web, API interface web, API interface web fichiers YAML, découverte

Le choix se justifie par le contexte, avec des critères explicites (comme la fiche de choix du BLOC 1) :

Famille Critères
Besoin types et nombre d’équipements, sites distants, services métier
Coût licences, matériel, temps d’installation et d’exploitation (TCO sur 3 ans)
Compétences Windows ou Linux, temps disponible, formation
Fonctions découverte, escalade, tableaux de bord, rapports, API, lien avec le ticketing
Échelle, pérennité proxys, sondes, haute disponibilité ; communauté, éditeur, LTS, support
Sécurité chiffrement, droits, hébergement des données, souveraineté

Pas de « meilleur outil »

Une PME de 30 personnes avec un administrateur Windows à mi-temps, une ESN qui supervise 400 serveurs chez ses clients et une jeune entreprise qui déploie des microservices sur Kubernetes ne choisiront pas le même outil, et elles auront toutes raison. Ce qui compte, c’est la cohérence entre le contexte, les critères et le choix.

7. À retenir

Points clés

  • PRTG : commercial, serveur sous Windows, découverte, licence par capteurs (100 gratuits).
  • Sonde → Groupe → Appareil → Capteur → Canal ; les réglages s’héritent.
  • WMI pour Windows, SNMP ou SSH pour Linux, HTTP Advanced pour le contenu d’une page.
  • Notification = modèle (comment) + déclencheur (quand).
  • Choisir = critères explicites, adaptés au contexte.

Quiz

  1. Sur quel système le serveur central de PRTG s’installe-t-il ?
  2. Qu’est-ce qu’un capteur dans PRTG ? Pourquoi est-ce l’unité de la licence ?
  3. Une entreprise veut superviser 12 serveurs avec une quinzaine de contrôles chacun. La version gratuite suffit-elle ?
  4. À quoi sert une sonde distante ?
  5. Où règle-t-on les identifiants Windows utilisés par les capteurs WMI, et pourquoi à cet endroit ?
  6. Que signifie un capteur orange (Unusual) ?
  7. Quelle différence entre un modèle de notification et un déclencheur de notification ?
  8. Quel inconvénient de sécurité présente la supervision des machines Windows par WMI ?
  9. Citez un contexte où vous recommanderiez PRTG, un où vous recommanderiez Zabbix, et un où vous recommanderiez Prometheus.
  10. Pourquoi Centreon est-il souvent cité dans les entreprises et administrations françaises ?
Voir la correction
  1. Windows (Windows Server 2016 à 2025, Windows 10 ou 11).
  2. Un contrôle sur un appareil, avec un état et des canaux. La licence est vendue par nombre de capteurs : plus on surveille, plus on paie.
  3. Non : 12 × 15 = 180 capteurs, au-delà des 100 de la version gratuite.
  4. À superviser un site ou un réseau distant : elle réalise les contrôles localement et envoie les résultats au serveur central par une seule connexion chiffrée.
  5. Sur un groupe (ou la racine) : ils sont hérités par tous les appareils du groupe, on ne les saisit qu’une fois.
  6. Une valeur inhabituelle par rapport à l’historique du même jour et de la même heure, sans seuil franchi.
  7. Le modèle dit comment prévenir (courriel, SMS, ticket…) ; le déclencheur dit quand (état, seuil, durée), sur quel objet.
  8. Il faut un compte administrateur des machines (ou une délégation fine, compliquée) : le serveur de supervision détient des identifiants très puissants.
  9. Par exemple : PRTG pour une PME Windows avec peu de temps et un petit budget pour quelques dizaines de capteurs ; Zabbix pour une infrastructure Linux et Windows de plusieurs centaines de machines avec une équipe compétente ; Prometheus pour des applications en conteneurs sur Kubernetes.
  10. Éditeur français, héritier du modèle Nagios (plugins), avec une version libre et un support commercial ; il répond aux exigences de souveraineté et d’hébergement des données.
