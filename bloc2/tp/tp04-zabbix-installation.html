TP 4 : Installer Zabbix et ses agents

Vous installez Zabbix 7.0 LTS sur sup-lnx-01 (serveur, base MariaDB, interface web), vous installez l'agent 2 sur srv-lnx-01 et srv-win-01, puis vous raccordez les deux serveurs avec les modèles fournis : système, nginx, PHP-FPM, MariaDB, services Windows. À la fin, vous comparez l'effort et le résultat avec Nagios.

Durée3 h
Machines virtuellessup-lnx-01, srv-lnx-01, srv-win-01
Cours associéSéance 4 : Zabbix : architecture et agents

Contexte

Nagios fonctionne, mais le responsable informatique voudrait des graphiques, un historique pour anticiper, et une configuration moins fastidieuse. Vous installez Zabbix à côté de Nagios, sur sup-lnx-01, pour les comparer.

Organisation

Socle : parties A à F. Facultatif : partie G (chiffrement de l’agent) et « Pour aller plus loin ».

Comptez cinq minutes d’attente pendant l’import du schéma de la base : profitez-en pour lire la partie E.

Partie A. Préparer sup-lnx-01 (10 min)

  1. Snapshot 04-avant-zabbix de sup-lnx-01.
  2. Créez la locale française, nécessaire à l’interface de Zabbix en français :
Machine : sup-lnx-01 (sysadmin)
sudo sed -i 's/^# fr_FR.UTF-8 UTF-8/fr_FR.UTF-8 UTF-8/' /etc/locale.gen
sudo locale-gen
locale -a | grep fr_FR

Partie B. Installer le serveur Zabbix (40 min)

B.1, Le dépôt et les paquets

Machine : sup-lnx-01 (sysadmin)
cd /tmp
curl -fsSLO https://repo.zabbix.com/zabbix/7.0/debian/pool/main/z/zabbix-release/zabbix-release_latest_7.0+debian13_all.deb
sudo dpkg -i zabbix-release_latest_7.0+debian13_all.deb
sudo apt update
sudo apt install -y mariadb-server zabbix-server-mysql zabbix-frontend-php zabbix-apache-conf zabbix-sql-scripts zabbix-agent2 zabbix-get
apt policy zabbix-server-mysql | head -4

La dernière commande montre que le paquet vient de repo.zabbix.com (version 7.0.x la plus récente), et non de Debian.

B.2, La base de données

Choisissez un mot de passe pour le compte zabbix de la base (ici Zabbix-Lab-Mdp! ; notez le vôtre) :

Machine : sup-lnx-01 (sysadmin)
sudo mariadb <<'SQL'
CREATE DATABASE zabbix CHARACTER SET utf8mb4 COLLATE utf8mb4_bin;
CREATE USER zabbix@localhost IDENTIFIED BY 'Zabbix-Lab-Mdp!';
GRANT ALL PRIVILEGES ON zabbix.* TO zabbix@localhost;
SET GLOBAL log_bin_trust_function_creators = 1;
SQL
time zcat /usr/share/zabbix-sql-scripts/mysql/server.sql.gz | mariadb --default-character-set=utf8mb4 -uzabbix -p zabbix
sudo mariadb -e "SET GLOBAL log_bin_trust_function_creators = 0;"
sudo mariadb -e "SELECT COUNT(*) AS tables FROM information_schema.tables WHERE table_schema='zabbix';"

mariadb -p demande le mot de passe du compte zabbix. L’import dure quelques minutes et n’affiche rien tant qu’il n’est pas fini : n’interrompez pas. Résultat attendu : environ 200 tables. L’option log_bin_trust_function_creators n’est utile que pendant l’import ; on la remet à 0.

B.3, Démarrer le serveur

Dans /etc/zabbix/zabbix_server.conf, trouvez la ligne # DBPassword= (avec Ctrl+W dans nano), retirez le # et indiquez le mot de passe :

Machine : sup-lnx-01 (sysadmin)
sudo nano /etc/zabbix/zabbix_server.conf
sudo grep -E '^DB(Name|User|Password)=' /etc/zabbix/zabbix_server.conf
sudo systemctl enable --now zabbix-server zabbix-agent2
sudo systemctl restart apache2
sudo tail -n 5 /var/log/zabbix/zabbix_server.log

Résultat attendu : les lignes server #… started […]. Une erreur Access denied for user 'zabbix' signale un mot de passe différent de celui de la base.

Partie C. L’assistant de l’interface web (15 min)

Depuis votre PC, ouvrez http://PROXMOX:1N080/zabbix :

Étape Réglage
Welcome (Bienvenue) langue par défaut : Français (fr_FR)
Vérification des prérequis tout doit être OK
Configurer la connexion à la base de données type MySQL, hôte localhost, port 0 (par défaut), base zabbix, utilisateur zabbix, son mot de passe ; Stocker les informations d’identification dans : Texte brut
Paramètres nom du serveur Zabbix : Hexalog ; fuseau horaire par défaut : Europe/Paris ; thème au choix
Résumé pré-installation, Installer l’assistant écrit /etc/zabbix/web/zabbix.conf.php

Connectez-vous avec Admin / zabbix, puis changez immédiatement ce mot de passe pour le mot de passe de lab : Paramètres utilisateur → Profil → Changer le mot de passe (User settings → Profile). Le mot de passe par défaut de Zabbix est connu de tous les attaquants.

Ouvrez Surveillance → Hôtes (Monitoring → Hosts) : l’hôte Zabbix server (sup-lnx-01 elle-même) est déjà supervisé par son agent ; sa pastille ZBX doit devenir verte en une minute.

Partie D. L’agent 2 sur srv-lnx-01 (25 min)

D.1, Installer et régler l’agent

Debian fournit l’agent 2 en version 7.0 : il est compatible avec le serveur 7.0 du dépôt de Zabbix (un agent ne doit jamais être plus récent que son serveur).

Machine : srv-lnx-01 (sysadmin)
sudo apt install -y zabbix-agent2
sudo tee /etc/zabbix/zabbix_agent2.d/hexalog.conf > /dev/null <<'EOF'
# Hexalog : serveur Zabbix autorisé, et nom de l'hôte dans Zabbix
Server=10.20.N.40
ServerActive=10.20.N.40
Hostname=srv-lnx-01
EOF
sudo sed -i 's/10\.20\.N\./10.20.3./g' /etc/zabbix/zabbix_agent2.d/hexalog.conf     # votre numéro
sudo zabbix_agent2 -T -c /etc/zabbix/zabbix_agent2.conf
sudo systemctl restart zabbix-agent2
sudo ss -tlnp | grep 10050
zabbix_agent2 -t agent.hostname -c /etc/zabbix/zabbix_agent2.conf
zabbix_agent2 -t 'web.page.get[localhost,basic_status,80]' -c /etc/zabbix/zabbix_agent2.conf

Résultat attendu : Validation successful, l’agent écoute sur 10050, agent.hostname vaut srv-lnx-01, et l’agent lit la page d’état de nginx (préparée par le script d’installation de l’intranet).

D.2, Un compte de supervision pour MariaDB

Le modèle MariaDB lit les compteurs de la base avec un compte en lecture seule, qui ne voit aucune donnée des tables :

Machine : srv-lnx-01 (sysadmin)
sudo mariadb <<'SQL'
CREATE USER 'zbx_monitor'@'localhost' IDENTIFIED BY 'Zbx-Monitor-Lab!';
GRANT REPLICATION CLIENT, PROCESS, SHOW DATABASES, SHOW VIEW ON *.* TO 'zbx_monitor'@'localhost';
SQL
zabbix_agent2 -t 'mysql.ping["tcp://localhost:3306","zbx_monitor","Zbx-Monitor-Lab!"]' -c /etc/zabbix/zabbix_agent2.conf

Résultat attendu : [s|1].

D.3, Tester depuis le serveur

Machine : sup-lnx-01 (sysadmin)
zabbix_get -s 10.20.N.20 -k agent.version
zabbix_get -s 10.20.N.20 -k 'system.cpu.load[all,avg1]'
zabbix_get -s 10.20.N.20 -k 'vfs.fs.size[/,pused]'
zabbix_get -s 10.20.N.20 -k 'proc.num[nginx]'

Partie E. Raccorder srv-lnx-01 (25 min)

Collecte de données → Hôtes (Data collection → Hosts) → Créer un hôte :

Champ Valeur
Nom de l’hôte srv-lnx-01 (identique à Hostname= de l’agent)
Nom visible SRV-LNX-01 intranet
Modèles Linux by Zabbix agent, Nginx by Zabbix agent, PHP-FPM by Zabbix agent, MySQL by Zabbix agent 2, ICMP Ping
Groupes d’hôtes tapez Hexalog/Linux et choisissez (nouveau)
Interfaces Ajouter → Agent : IP 10.20.N.20, port 10050

Onglet Macros (Macros) : ajoutez les trois macros du modèle MariaDB :

Macro Valeur Type
{$MYSQL.DSN} tcp://localhost:3306 Texte
{$MYSQL.USER} zbx_monitor Texte
{$MYSQL.PASSWORD} Zbx-Monitor-Lab! Texte secret

Cliquez sur Ajouter. Puis :

  1. Surveillance → Hôtes : la pastille ZBX de srv-lnx-01 passe au vert en une à deux minutes.
  2. Surveillance → Dernières données, filtre sur l’hôte srv-lnx-01 : retrouvez la charge, la mémoire disponible, l’espace utilisé de /, les connexions actives de nginx, les processus actifs de PHP-FPM, l’état de MariaDB. Cliquez sur Graphique à côté d’une valeur.
  3. Collecte de données → Hôtes : notez, sur la ligne de srv-lnx-01, le nombre d’éléments, de déclencheurs, de graphiques et de règles de découverte créés par les cinq modèles. Combien de lignes de configuration Nagios auraient été nécessaires pour la même chose ?

Partie F. L’agent 2 sur srv-win-01 (35 min)

  1. Sur srv-win-01 (console Proxmox), ouvrez Edge et téléchargez le programme d’installation de l’agent 2 pour Windows : https://cdn.zabbix.com/zabbix/binaries/stable/7.0/latest/zabbix_agent2-7.0-latest-windows-amd64-openssl.msi
  2. Lancez-le et renseignez :
Écran de l’installateur Valeur
Host name srv-win-01 (en minuscules, comme dans Zabbix)
Zabbix server IP/DNS 10.20.N.40
Agent listen port 10050
Server or Proxy for active checks 10.20.N.40
Enable PSK non coché (voir partie G)
  1. Vérifiez le service : services.msc → Zabbix Agent 2 → En cours d’exécution, démarrage Automatique.
  2. Pare-feu : wf.msc → Règles de trafic entrant. S’il n’existe pas de règle pour l’agent, créez-en une : Nouvelle règle → Port → TCP 10050 → Autoriser la connexion → profil Domaine, nom Zabbix agent, puis dans ses propriétés, onglet Étendue, limitez l’adresse IP distante à 10.20.N.40.
  3. Test depuis le serveur :
Machine : sup-lnx-01 (sysadmin)
zabbix_get -s 10.20.N.10 -k agent.version
zabbix_get -s 10.20.N.10 -k 'service.info[DNS,state]'
zabbix_get -s 10.20.N.10 -k 'service.info[NTDS,state]'

Résultat attendu : la version de l’agent, puis 0 pour les deux services (0 = en cours d’exécution).

  1. Dans Zabbix, créez l’hôte srv-win-01 : nom visible SRV-WIN-01 controleur de domaine, modèles Windows by Zabbix agent et ICMP Ping, groupe Hexalog/Windows (nouveau), interface Agent 10.20.N.10:10050.
  2. Après quelques minutes, dans Dernières données de srv-win-01, filtrez sur le nom DNS puis NTDS : la découverte a créé un élément d’état pour chaque service Windows en démarrage automatique.

Partie G. Chiffrer les échanges avec l’agent de srv-lnx-01 (facultatif, 20 min)

Par défaut, les échanges entre serveur et agent circulent en clair. On les chiffre avec une clé partagée (PSK).

Machine : srv-lnx-01 (sysadmin)
openssl rand -hex 32 | sudo tee /etc/zabbix/hexalog.psk
sudo chown zabbix:zabbix /etc/zabbix/hexalog.psk
sudo chmod 640 /etc/zabbix/hexalog.psk
sudo tee -a /etc/zabbix/zabbix_agent2.d/hexalog.conf > /dev/null <<'EOF'
TLSConnect=psk
TLSAccept=psk
TLSPSKIdentity=PSK-SRV-LNX-01
TLSPSKFile=/etc/zabbix/hexalog.psk
EOF
sudo systemctl restart zabbix-agent2
sudo cat /etc/zabbix/hexalog.psk

Dans Zabbix : hôte srv-lnx-01 → onglet Chiffrement : Connexion à l’hôte PSK, Connexion de l’hôte : cochez PSK (et décochez Pas de chiffrement), identité PSK-SRV-LNX-01, clé PSK : la valeur affichée. Vérifiez que la pastille ZBX reste verte. Puis :

Machine : sup-lnx-01 (sysadmin)
zabbix_get -s 10.20.N.20 -k agent.version

Sans les options de chiffrement, zabbix_get est maintenant refusé. Avec : zabbix_get -s 10.20.N.20 -k agent.version --tls-connect psk --tls-psk-identity PSK-SRV-LNX-01 --tls-psk-file <fichier contenant la clé>.

Vérifications

Questions

  1. Pourquoi installer le serveur depuis le dépôt de Zabbix plutôt que depuis Debian ? Pourquoi a-t-on pu installer l’agent de Debian sur srv-lnx-01 ?
  2. À quoi sert le compte zbx_monitor ? Pourquoi ne pas utiliser le compte root de MariaDB, ou le compte intranet de l’application ?
  3. Pourquoi le mot de passe de zbx_monitor est-il une macro de type Texte secret ?
  4. Les contrôles de srv-lnx-01 sont passifs : quelle machine ouvre les connexions, vers quel port ? Quelle règle de pare-feu faudrait-il si srv-lnx-01 avait UFW ?
  5. Combien d’éléments les modèles ont-ils créés pour srv-lnx-01 ? Sont-ils tous utiles ? Citez-en un qui vous paraît superflu.
  6. Un déclencheur Number of installed packages has been changed apparaît dans Surveillance → Problèmes après l’installation de l’agent. Est-ce une panne ? Que faudrait-il en faire ?

Dépannage

Symptôme Piste
L’assistant indique une locale manquante, ou le français n’est pas proposé partie A non faite ; puis sudo systemctl restart apache2
L’assistant ne peut pas se connecter à la base mot de passe ou nom de base différents ; hôte localhost
Le tableau de bord affiche Zabbix server is not running sudo systemctl status zabbix-server ; sudo tail /var/log/zabbix/zabbix_server.log (souvent DBPassword manquant ou faux)
zabbix_get : Received empty response… access permissions l’adresse de sup-lnx-01 n’est pas dans Server= (N mal remplacé ?), ou chiffrement PSK exigé
zabbix_get : Connection refused ou délai dépassé agent arrêté ; sous Windows, pare-feu (port 10050)
Pastille ZBX rouge, message Get value from agent failed adresse ou port de l’interface, pare-feu, Server=
Pastille ZBX grise l’hôte n’a pas encore été contrôlé : attendre une minute
Éléments MariaDB en Non supporté macros {$MYSQL.*} absentes ou fausses ; tester mysql.ping avec zabbix_agent2 -t (D.2)
Éléments nginx ou PHP-FPM en Non supporté page d’état inaccessible : curl http://localhost/basic_status et curl http://localhost/status sur srv-lnx-01
Pas de valeurs ICMP fping absent du serveur, ou ICMP refusé par le pare-feu Windows (TP 1, F.6)

Pour aller plus loin

  • Enregistrement automatique : avec une action d’autoregistration et HostMetadata=hexalog-linux dans la configuration de l’agent, un nouvel agent actif crée lui-même son hôte dans Zabbix, avec les bons modèles. Testez-le à la séance 8 avec srv-lnx-02.
  • L’API : Zabbix se pilote entièrement par une API JSON-RPC (/zabbix/api_jsonrpc.php). Créez un jeton d’API (Utilisateurs → Tokens API) et listez vos hôtes avec curl et la méthode host.get.
