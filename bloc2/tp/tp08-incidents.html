Vous créez srv-lnx-02, vous y installez GLPI 11, vous organisez le centre de services d'Hexalog (groupes, techniciens, demandeurs, catégories, priorités, délais), puis vous traitez une série de demandes comme le ferait le support : enregistrer, qualifier, attribuer, escalader, résoudre, relier, capitaliser. Contexte

Chez Hexalog, les demandes arrivent par téléphone, par courriel, dans le couloir ; certaines se perdent, personne ne sait combien de temps prend une réparation. La direction décide d’un point de contact unique et d’un outil de tickets : GLPI.

Organisation

Socle : parties A à D. Recommandé : partie E (Zabbix ouvre les tickets). Facultatif : C.4 (délais), partie F et « Pour aller plus loin ».

A.2, La supervision et les journaux, dès la naissance

Une machine qui entre en production entre aussi dans la supervision et dans la centralisation des journaux, le jour même.

Machine : srv-lnx-02 (sysadmin)
sudo apt install -y zabbix-agent2 rsyslog
sudo tee /etc/zabbix/zabbix_agent2.d/hexalog.conf > /dev/null <<'EOF'
# Hexalog : serveur Zabbix autorisé, et nom de l'hôte dans Zabbix
Server=10.20.N.40
ServerActive=10.20.N.40
Hostname=srv-lnx-02
EOF
sudo tee /etc/rsyslog.d/90-vers-sup-lnx-01.conf > /dev/null <<'EOF'
# Hexalog : copie de tous les journaux vers le serveur central
action(type="omfwd" target="10.20.N.40" port="514" protocol="tcp"
       queue.type="LinkedList" queue.filename="vers-sup-lnx-01"
       queue.maxDiskSpace="100m" queue.saveOnShutdown="on"
       action.resumeRetryCount="-1")
EOF
sudo sed -i 's/10\.20\.N\./10.20.3./' /etc/zabbix/zabbix_agent2.d/hexalog.conf /etc/rsyslog.d/90-vers-sup-lnx-01.conf
sudo rsyslogd -N1 && sudo systemctl restart rsyslog zabbix-agent2
logger "TP8 : srv-lnx-02 entre en service"

Dans Zabbix, créez l’hôte srv-lnx-02 (nom visible SRV-LNX-02 GLPI), groupe Hexalog/Linux, modèles Linux by Zabbix agent et ICMP Ping, interface agent 10.20.N.21:10050. Vérifiez la pastille ZBX, et l’arrivée du message dans /var/log/hexalog/srv-lnx-02/ sur sup-lnx-01.

B.2, La base de données

Choisissez le mot de passe du compte glpi de la base (ici Glpi-Lab-Mdp!, notez le vôtre) :

Machine : srv-lnx-02 (sysadmin)
sudo mariadb <<'SQL'
CREATE DATABASE glpi CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'glpi'@'localhost' IDENTIFIED BY 'Glpi-Lab-Mdp!';

SQL

La dernière commande charge les fuseaux horaires dans MariaDB : GLPI s’en sert pour afficher les dates dans le fuseau de chaque utilisateur.

B.3, Les fichiers de GLPI

Vérifiez sur https://github.com/glpi-project/glpi/releases la dernière version 11.0.x et adaptez la première ligne.

Machine : srv-lnx-02 (sysadmin)
VERSION=11.0.8
cd /tmp
curl -fsSLO https://github.com/glpi-project/glpi/releases/download/$VERSION/glpi-$VERSION.tgz
sudo tar -xzf glpi-$VERSION.tgz -C /var/www/
sudo mkdir -p /etc/glpi /var/lib/glpi /var/log/glpi
sudo mv /var/www/glpi/config/* /etc/glpi/ 2>/dev/null ; sudo rmdir /var/www/glpi/config
sudo mv /var/www/glpi/files /var/lib/glpi/
sudo chown -R www-data:www-data /var/www/glpi /etc/glpi /var/lib/glpi /var/log/glpi

On sépare, comme le recommande GLPI, le code (/var/www/glpi), la configuration (/etc/glpi), les données (/var/lib/glpi/files : documents joints, sessions, cache) et les journaux (/var/log/glpi). Seul le dossier public sera servi par le serveur web : le reste n’est pas accessible depuis un navigateur. Deux petits fichiers indiquent à GLPI où sont rangées les choses :

Machine : srv-lnx-02 (sysadmin)
sudo tee /var/www/glpi/inc/downstream.php > /dev/null <<'EOF'
<?php
define('GLPI_CONFIG_DIR', '/etc/glpi/');
if (file_exists(GLPI_CONFIG_DIR . '/local_define.php')) {
    require_once GLPI_CONFIG_DIR . '/local_define.php';
}
EOF
sudo tee /etc/glpi/local_define.php > /dev/null <<'EOF'
<?php
define('GLPI_VAR_DIR', '/var/lib/glpi/files');
define('GLPI_LOG_DIR', '/var/log/glpi');
EOF
sudo chown www-data:www-data /var/www/glpi/inc/downstream.php /etc/glpi/local_define.php
cd /var/www/glpi && sudo -u www-data php bin/console system:check_requirements | grep -E 'REQUIRED|SECURITY' | grep -v OK

La dernière commande vérifie les prérequis : il ne doit rester que la ligne Security configuration for sessions (réglée en B.4), éventuellement marquée SKIPPED.

B.4, Le site web

Machine : srv-lnx-02 (sysadmin)
sudo tee /etc/apache2/sites-available/glpi.conf > /dev/null <<'EOF'
# GLPI d'Hexalog : seul le dossier public est servi
<VirtualHost *:80>
    ServerName glpi.hexalog.local
    DocumentRoot /var/www/glpi/public

    <Directory /var/www/glpi/public>
        Require all granted
        RewriteEngine On
        # transmettre l'en-tête Authorization à PHP (utilisé par l'API)
        RewriteCond %{HTTP:Authorization} ^(.+)$
        RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]
        # tout ce qui n'est pas un fichier existant passe par le routeur de GLPI
        RewriteCond %{REQUEST_FILENAME} !-f
        RewriteRule ^(.*)$ index.php [QSA,L]
    </Directory>

    <FilesMatch \.php$>
        SetHandler "proxy:unix:/run/php/php8.4-fpm.sock|fcgi://localhost/"
    </FilesMatch>

    ErrorLog ${APACHE_LOG_DIR}/glpi-erreurs.log
    CustomLog ${APACHE_LOG_DIR}/glpi-acces.log combined
</VirtualHost>
EOF
sudo a2enmod rewrite proxy_fcgi setenvif
sudo a2enconf php8.4-fpm
sudo a2dissite 000-default
sudo a2ensite glpi
sudo sed -i 's/^session.cookie_httponly =.*/session.cookie_httponly = On/; s/^session.cookie_samesite =.*/session.cookie_samesite = Lax/' /etc/php/8.4/fpm/php.ini
grep -E '^session.cookie_(httponly|samesite)' /etc/php/8.4/fpm/php.ini
sudo apache2ctl configtest
sudo systemctl restart php8.4-fpm apache2

Résultat attendu : session.cookie_httponly = On, session.cookie_samesite = Lax, Syntax OK. Les deux réglages de PHP empêchent un script malveillant de lire le cookie de session, et le navigateur de l’envoyer depuis un autre site.

Partie E. Zabbix ouvre les tickets (35 min, recommandé)

Les pannes graves doivent arriver dans GLPI sans que personne n’ait à les recopier. On utilise le type de média GLPi de Zabbix, qui passe par l’API de GLPI (cours, partie 9).

E.1, Dans GLPI : l’API, un client et un compte dédiés

  1. Configuration → Générale → API : Activer l’API : Oui → Sauvegarder.
  2. Configuration → Clients OAuth → Ajouter : nom Zabbix, Grants : Password, Scopes : api → Ajouter. Notez l’identifiant et le secret du client affichés sur la fiche (traitez le secret comme un mot de passe).
  3. Administration → Profils → Ajouter : nom Zabbix (API), Interface du profil : Interface standard → Ajouter. Puis onglet Assistance du profil : ligne Tickets : Créer, Mettre à jour, Voir tous les tickets ; ligne Suivis : Ajouter (demandeur) → Sauvegarder.
  4. Administration → Utilisateurs → Ajouter : identifiant zabbix-api, un mot de passe long, profil Zabbix (API) sur l’entité racine (récursif).

Ce compte ne peut que créer et mettre à jour des tickets : si ses identifiants fuient, l’attaquant ne peut ni lire la configuration, ni administrer GLPI. C’est le moindre privilège appliqué à une intégration.

E.2, Dans Zabbix : le type de média, le destinataire, l’action

  1. Administration → Macros : ajoutez la macro globale {$ZABBIX.URL} = http://10.20.N.40/zabbix (elle sert à mettre un lien vers le problème dans le ticket).
  2. Alertes → Types de média → GLPi : renseignez les paramètres, puis cochez Activé → Actualiser :
Paramètre Valeur
glpi_url http://10.20.N.21 (sans chemin)
glpi_legacy_api false
glpi_client_id, glpi_client_secret les valeurs notées en E.1
glpi_username, glpi_password zabbix-api et son mot de passe
  1. Utilisateurs → Utilisateurs → Admin → Média → Ajouter : type GLPi, envoyer à glpi (n’importe quelle valeur), sévérités Haut et Désastre seulement.
  2. Ouvrez l’action Report problems to Zabbix administrators (TP 5) → onglet Opérations : modifiez l’opération et choisissez Envoyer uniquement à : Courriel. Sinon, elle enverrait aussi vers GLPI, et chaque panne créerait deux tickets.
  3. Alertes → Actions → Actions de déclencheur → Créer une action : nom Tickets GLPI, condition Sévérité du déclencheur est supérieure ou égale à Haut. Onglet Opérations : envoyer à l’utilisateur Admin, uniquement à GLPi ; Opérations de récupération et Opérations de mise à jour : Notifier toutes les personnes concernées → Ajouter.
