Contexte

Avant d’installer un outil, le responsable informatique d’Hexalog veut savoir quoi surveiller et comment l’obtenir. Vous testez les méthodes de collecte vues en cours sur le lab, et vous produisez la matrice de supervision : pour chaque service, les indicateurs, la méthode, les seuils et les personnes à prévenir.

Organisation

Commencez par terminer le TP 1 si besoin (parties H et I). Socle : parties B à F. Facultatif : D.4 (noms des MIB).

Ce que vous construisez

Vous testez depuis sup-lnx-01 les trois façons d’obtenir une information : tester de l’extérieur, interroger un agent SNMP, et écrire votre propre plugin.

Partie A. Point de départ (5 min)

Machine : sup-lnx-01 (sysadmin)
ping -c 2 10.20.N.10
ping -c 2 10.20.N.20
curl -s http://10.20.N.20/sante.php
getent hosts intranet.hexalog.local

Les quatre commandes doivent réussir. Sinon, terminez le TP 1.

Partie B. Les plugins à la main (50 min)

B.1, Installer les plugins

Machine : sup-lnx-01 (sysadmin)
sudo apt install -y monitoring-plugins
ls /usr/lib/nagios/plugins/

B.2, Tester les services d’Hexalog

Lancez chaque commande, puis echo $? pour voir le code retour. Notez dans un tableau de votre journal : la commande, la ligne affichée, le code, l’état correspondant. Votre Debian étant installée en français, certains messages des plugins peuvent s’afficher en français : seul le code retour compte pour l’outil de supervision.

Machine : sup-lnx-01 (sysadmin)
cd /usr/lib/nagios/plugins
./check_ping -H 10.20.N.20 -w 100,20% -c 500,60% ; echo "code $?"
./check_ssh -H 10.20.N.20 ; echo "code $?"
./check_tcp -H 10.20.N.20 -p 80 ; echo "code $?"
./check_tcp -H 10.20.N.20 -p 3306 ; echo "code $?"
./check_http -I 10.20.N.20 -u /sante.php -s BASE-OK ; echo "code $?"
./check_http -I 10.20.N.20 -u /sante.php -s TOTO ; echo "code $?"
./check_dns -H intranet.hexalog.local -s 10.20.N.10 -a 10.20.N.20 ; echo "code $?"
./check_tcp -H 10.20.N.10 -p 389 ; echo "code $?"
./check_tcp -H 10.20.N.10 -p 88 ; echo "code $?"

Points à observer :

  • check_tcp -p 3306 est CRITIQUE : MariaDB n’écoute que sur la machine elle-même (127.0.0.1). Ce n’est pas une panne, c’est un réglage de sécurité. On ne supervise donc pas la base « de l’extérieur » par son port, mais par la page de santé, ou par un agent (TP 3 et 4).
  • La sixième commande cherche un texte absent : le service répond, mais pas comme attendu.
  • check_dns vérifie à la fois que le DNS répond et que la réponse est la bonne (-a).

B.3, Seuils et données de performance

Machine : sup-lnx-01 (sysadmin)
cd /usr/lib/nagios/plugins
./check_ping -H 10.20.N.20 -w 0.1,20% -c 500,60% ; echo "code $?"
./check_http -I 10.20.N.20 -u / -w 0.001 -c 2 ; echo "code $?"
./check_disk -w 20% -c 10% -p / ; echo "code $?"
./check_load -r -w 0.8,0.7,0.6 -c 1.5,1.2,1.0 ; echo "code $?"
./check_procs -C apache2 -c 1: ; echo "code $?"
  1. Les deux premières commandes passent en WARNING : le seuil d’avertissement est volontairement irréaliste (0,1 ms de temps de réponse au ping, 1 ms pour une page web). Changez-le pour obtenir OK.
  2. Repérez, dans chaque ligne, les données de performance après la barre verticale. Pour check_disk, expliquez les quatre nombres qui suivent la valeur.
  3. check_procs -C apache2 -c 1: est CRITIQUE : il n’y a aucun processus apache2 sur sup-lnx-01 (il viendra avec Nagios). Expliquez la notation 1:.

B.4, Écrire votre plugin

Un plugin n’est qu’un programme qui respecte le contrat du cours. Écrivez check_intranet : il charge la page de santé, vérifie le code HTTP et le texte, mesure le temps de réponse, et répond selon les règles suivantes.

Situation État Code
code 200, BASE-OK, moins de 1 s OK 0
code 200, BASE-OK, 1 s ou plus WARNING 1
autre code, ou BASE-OK absent CRITICAL 2
aucune réponse (délai dépassé, connexion refusée) CRITICAL 2
argument manquant UNKNOWN 3
Fichier : /usr/local/lib/nagios/check_intranet
#!/bin/bash
# check_intranet : teste la page de santé de l'intranet d'Hexalog
# Usage : check_intranet <adresse>
HOTE="$1"
if [ -z "$HOTE" ]; then
    echo "UNKNOWN - usage : $0 <adresse>"
    exit 3
fi
RES=$(curl -s -m 5 -o /tmp/sante.$$ -w "%{http_code} %{time_total}" "http://$HOTE/sante.php")
CODE=${RES% *}
TEMPS=${RES#* }
CORPS=$(cat /tmp/sante.$$ 2>/dev/null) ; rm -f /tmp/sante.$$
PERF="temps=${TEMPS}s;1;5;0"
if [ "$CODE" = "000" ]; then
    echo "CRITICAL - intranet injoignable | $PERF"
    exit 2
fi
if [ "$CODE" != "200" ] || ! echo "$CORPS" | grep -q BASE-OK; then
    echo "CRITICAL - code HTTP $CODE, réponse : $CORPS | $PERF"
    exit 2
fi
if [ "$(echo "$TEMPS >= 1" | bc)" = "1" ]; then
    echo "WARNING - intranet lent : ${TEMPS} s | $PERF"
    exit 1
fi
echo "OK - $CORPS en ${TEMPS} s | $PERF"
exit 0
Machine : sup-lnx-01 (sysadmin)
sudo apt install -y bc
sudo mkdir -p /usr/local/lib/nagios
sudo nano /usr/local/lib/nagios/check_intranet      # coller le script ci-dessus
sudo chmod 755 /usr/local/lib/nagios/check_intranet
/usr/local/lib/nagios/check_intranet 10.20.N.20 ; echo "code $?"
/usr/local/lib/nagios/check_intranet ; echo "code $?"
/usr/local/lib/nagios/check_intranet 10.20.N.99 ; echo "code $?"

Provoquez enfin une vraie panne et observez votre plugin passer en CRITIQUE, puis revenir à OK :

Machine : srv-lnx-01 (sysadmin)
sudo systemctl stop mariadb
Machine : sup-lnx-01 (sysadmin)
/usr/local/lib/nagios/check_intranet 10.20.N.20 ; echo "code $?"

Partie C. Un agent SNMP sur srv-lnx-01 (30 min)

C.1, Installer et configurer snmpd

La configuration de Debian n’écoute que sur la machine elle-même. On la remplace par une configuration courte et explicite :

Machine : srv-lnx-01 (sysadmin)
sudo apt install -y snmpd
sudo cp /etc/snmp/snmpd.conf /etc/snmp/snmpd.conf.origine
sudo nano /etc/snmp/snmpd.conf

Remplacez tout le contenu par (avec votre numéro à la place de N) :

Fichier : /etc/snmp/snmpd.conf (srv-lnx-01)
# Agent SNMP de SRV-LNX-01 (Hexalog)
sysLocation    Hexalog, serveur virtuel Proxmox
sysContact     Service informatique <informatique@hexalog.local>
agentaddress   udp:161

# SNMPv2c : lecture seule, depuis la machine elle-même et le serveur de supervision
rocommunity    hexalog-lecture 127.0.0.1
rocommunity    hexalog-lecture 10.20.N.40

# SNMPv3 : utilisateur authentifié et chiffré, lecture seule
rouser         supervision authpriv

C.2, Créer l’utilisateur SNMPv3

L’utilisateur v3 se déclare, service arrêté, dans le fichier de données de snmpd (et non dans le fichier de configuration) : au démarrage, snmpd remplace cette ligne par une version où les mots de passe n’apparaissent plus en clair. Choisissez deux mots de passe d’au moins 8 caractères (notez-les dans votre journal, ils resserviront) ; ici Snmp-Auth-Hexalog et Snmp-Chiff-Hexalog.

Machine : srv-lnx-01 (sysadmin)
sudo systemctl stop snmpd
echo 'createUser supervision SHA-256 "Snmp-Auth-Hexalog" AES "Snmp-Chiff-Hexalog"' | sudo tee -a /var/lib/snmp/snmpd.conf
sudo systemctl start snmpd
sudo ss -ulnp | grep 161
sudo grep -E 'createUser|usmUser' /var/lib/snmp/snmpd.conf

Résultat attendu : snmpd écoute sur 0.0.0.0:161 ; dans le fichier de données, la ligne createUser a disparu au profit d’une ligne usmUser (clés dérivées, mots de passe illisibles). Si la ligne createUser est encore là, snmpd n’a pas été redémarré.

C.3, Tester sur la machine elle-même

Machine : srv-lnx-01 (sysadmin)
sudo apt install -y snmp
snmpget -v2c -c hexalog-lecture 127.0.0.1 .1.3.6.1.2.1.1.5.0 .1.3.6.1.2.1.1.3.0

Partie D. Interroger en SNMP depuis sup-lnx-01 (40 min)

D.1, SNMPv2c

Machine : sup-lnx-01 (sysadmin)
sudo apt install -y snmp
snmpget -v2c -c hexalog-lecture 10.20.N.20 .1.3.6.1.2.1.1.5.0
snmpwalk -v2c -c hexalog-lecture 10.20.N.20 .1.3.6.1.2.1.1
snmpwalk -v2c -c hexalog-lecture 10.20.N.20 .1.3.6.1.4.1.2021.10.1.3
snmpwalk -v2c -c hexalog-lecture 10.20.N.20 .1.3.6.1.2.1.25.2.3.1.3
  1. Identifiez dans le parcours de system : la description, le temps de fonctionnement, le contact, le nom, l’emplacement.
  2. Quelles sont les trois valeurs de charge ?
  3. La dernière commande liste les espaces de stockage : notez l’index de la ligne /. Lisez sa taille et son utilisation (en blocs, dont la taille est donnée par .1.3.6.1.2.1.25.2.3.1.4) et calculez le pourcentage utilisé :
Machine : sup-lnx-01 (sysadmin)
I=31        # remplacer par l'index de la ligne « / »
snmpget -v2c -c hexalog-lecture 10.20.N.20 .1.3.6.1.2.1.25.2.3.1.4.$I .1.3.6.1.2.1.25.2.3.1.5.$I .1.3.6.1.2.1.25.2.3.1.6.$I

Comparez avec df -h / sur srv-lnx-01.

D.2, Ce qui doit échouer

Machine : sup-lnx-01 (sysadmin)
snmpget -v2c -c public 10.20.N.20 .1.3.6.1.2.1.1.5.0
snmpget -v2c -c mauvaise 10.20.N.20 .1.3.6.1.2.1.1.5.0

Les deux échouent par Timeout : un agent SNMP v2c ne répond pas du tout à une communauté inconnue. Le message ne dit pas « refusé » : en diagnostic, un délai dépassé peut donc venir d’une machine éteinte, d’un pare-feu, d’un service arrêté ou d’une mauvaise communauté.

D.3, SNMPv3 authentifié et chiffré

Machine : sup-lnx-01 (sysadmin)
snmpget -v3 -l authPriv -u supervision -a SHA-256 -A "Snmp-Auth-Hexalog" -x AES -X "Snmp-Chiff-Hexalog" 10.20.N.20 .1.3.6.1.2.1.1.5.0
snmpget -v3 -l authPriv -u supervision -a SHA-256 -A "mauvais-mot-de-passe" -x AES -X "Snmp-Chiff-Hexalog" 10.20.N.20 .1.3.6.1.2.1.1.5.0

La seconde commande répond Authentication failure : contrairement à v2c, SNMPv3 signale l’erreur d’authentification. Pour éviter de répéter les paramètres, on peut les ranger dans ~/.snmp/snmp.conf (fichier lisible par vous seul) :

Fichier : ~/.snmp/snmp.conf (sup-lnx-01)
defVersion 3
defSecurityName supervision
defSecurityLevel authPriv
defAuthType SHA-256
defAuthPassphrase Snmp-Auth-Hexalog
defPrivType AES
defPrivPassphrase Snmp-Chiff-Hexalog
Machine : sup-lnx-01 (sysadmin)
chmod 600 ~/.snmp/snmp.conf
snmpwalk 10.20.N.20 .1.3.6.1.2.1.1

D.4, Les noms des MIB (facultatif)

Les MIB standard sont dans le dépôt non-free de Debian. Ouvrez le fichier des dépôts (/etc/apt/sources.list.d/debian.sources sur une installation Debian 13 ; /etc/apt/sources.list sur une installation plus ancienne) et ajoutez non-free après main sur chaque ligne Components: (par exemple Components: main non-free non-free-firmware). Puis installez le paquet et autorisez le chargement des MIB :

Machine : sup-lnx-01 (sysadmin)
sudo nano /etc/apt/sources.list.d/debian.sources
sudo apt update
sudo apt install -y snmp-mibs-downloader
sudo sed -i 's/^mibs :/#mibs :/' /etc/snmp/snmp.conf
snmpwalk 10.20.N.20 system
snmpwalk 10.20.N.20 hrStorageDescr
snmptranslate -On HOST-RESOURCES-MIB::hrStorageUsed
snmptranslate -Td UCD-SNMP-MIB::laLoad

Les OID s’affichent maintenant avec leur nom. snmptranslate traduit dans les deux sens et affiche la description d’un objet.

D.5, Ce que voit quelqu’un qui écoute

Sur srv-lnx-01, écoutez le port 161 pendant que sup-lnx-01 envoie une requête v2c, puis une requête v3 :

Machine : srv-lnx-01 (sysadmin)
sudo apt install -y tcpdump
sudo tcpdump -i ens18 -n -A -c 4 udp port 161

En v2c, la communauté hexalog-lecture et le nom de la machine apparaissent en clair dans le paquet. En v3 authPriv, on ne lit que le nom d’utilisateur ; le contenu est chiffré.

Partie E. Le plugin check_snmp (15 min)

check_snmp lit un OID et le compare à des seuils : c’est ainsi que Nagios supervise un équipement en SNMP.

Machine : sup-lnx-01 (sysadmin)
cd /usr/lib/nagios/plugins
./check_snmp -H 10.20.N.20 -P 2c -C hexalog-lecture -o .1.3.6.1.4.1.2021.10.1.5.1 -w 80 -c 150 -l "charge x100" ; echo "code $?"
./check_snmp -H 10.20.N.20 -P 3 -L authPriv -U supervision -a SHA-256 -A "Snmp-Auth-Hexalog" -x AES -X "Snmp-Chiff-Hexalog" -o .1.3.6.1.2.1.1.3.0 -l "fonctionne depuis" ; echo "code $?"

L’OID …2021.10.1.5.1 donne la charge sur 1 minute multipliée par 100 (un entier, plus facile à comparer). Pendant qu’une commande tourne, quelqu’un qui lance ps aux sur sup-lnx-01 voit les mots de passe dans la ligne de commande : à la séance 3, ils seront rangés dans un fichier protégé de Nagios.

Dépannage

Symptôme Piste
check_http: Invalid hostname/address -I attend une adresse ; -H un nom (envoyé dans l’en-tête Host)
check_dns répond CRITICAL avec la bonne adresse l’option -a attend exactement l’adresse renvoyée ; vérifiez N
Le plugin écrit bc: command not found sudo apt install -y bc
