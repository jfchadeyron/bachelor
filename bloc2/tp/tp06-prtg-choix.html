TP 6 : PRTG, puis comparer les trois outils

Vous installez PRTG sur un serveur Windows dédié, vous laissez la découverte automatique trouver le réseau d'Hexalog, vous supervisez le contrôleur de domaine en WMI, srv-lnx-01 en SNMPv3 et l'intranet en HTTP, avec seuils et notifications. Puis, avec votre expérience des trois outils, vous construisez une grille de comparaison et recommandez un outil pour trois entreprises.

Durée3 h (dont 45 min de TD)
Machines virtuellessup-win-01 (créée dans ce TP), srv-win-01, srv-lnx-01, sup-lnx-01
Cours associéSéance 6 : PRTG et le choix d'un outil

Contexte

Un cabinet de conseil a proposé PRTG à la direction d’Hexalog : « opérationnel en une heure, sans Linux ». Le responsable informatique veut le voir à l’œuvre avant de trancher entre Nagios, Zabbix et PRTG.

Organisation

Socle : parties A à E et G. Facultatif : partie F.

sup-win-01 demande 4 Go de mémoire sur le serveur partagé : éteignez-la à la fin de la séance. Elle ne resservira pas.

M. CHADEYRON fournit le programme d’installation de PRTG et une clé de licence d’essai (sinon : formulaire d’essai sur le site de Paessler, avec une adresse électronique).

Partie A. Créer sup-win-01 (25 min)

  1. Clonez 9001 (TPL-WS2025) : ID N41, nom sup-win-01, clone lié, pool etuN. Matériel : 4096 Mio, 2 cœurs, une carte réseau sur hexaN (VirtIO, sans pare-feu).
  2. Démarrez-la, faites la première configuration (France, Français, clavier Français, mot de passe de lab pour Administrateur).
  3. ncpa.cpl : adresse 10.20.N.41/24, passerelle 10.20.N.1, DNS préféré 10.20.N.10. sysdm.cpl : nom SUP-WIN-01, redémarrer. La machine reste hors du domaine : un outil de supervision n’a pas besoin d’y être, et un serveur de supervision compromis ne doit pas offrir une porte d’entrée dans l’annuaire.
  4. Vérifiez dans une invite de commandes : ping 10.20.N.10, nslookup intranet.hexalog.local.

Partie B. Installer PRTG (25 min)

  1. Copiez le programme d’installation sur sup-win-01 (téléchargement depuis le lien donné par M. CHADEYRON) et lancez-le.
  2. Langue : Français (ou English) ; acceptez la licence ; adresse électronique de l’administrateur : informatique@hexalog.local ; clé de licence : celle fournie ; mode d’installation Express.
  3. L’installation dure dix minutes environ ; PRTG ouvre ensuite son interface dans le navigateur de la VM. La découverte automatique (auto-discovery) parcourt aussitôt le réseau 10.20.N.0/24.
  4. Connectez-vous : identifiant prtgadmin, mot de passe prtgadmin. Changez ce mot de passe immédiatement : Setup → Account Settings → My Account (Configuration → Paramètres du compte → Mon compte), mot de passe de lab.
  5. Depuis votre PC, ouvrez https://PROXMOX:1N443/ (certificat autosigné à accepter) : vous retrouvez la même interface.

Les menus de PRTG

L’interface existe en français (Setup → Account Settings → My Account → Language), mais la documentation, les noms des capteurs et la plupart des ressources sont en anglais : le TP donne les menus en anglais, avec la traduction quand elle aide.

Partie C. Ce que la découverte a trouvé (15 min)

Ouvrez Devices (Appareils). Sous la sonde locale, PRTG a créé des groupes et des appareils pour les machines qui répondent sur 10.20.N.0/24.

  1. Combien d’appareils ? Lesquels sont reconnus correctement (nom, type) ?
  2. Combien de capteurs ont été créés ? Combien sont gris, rouges, verts ? Pourquoi la plupart des capteurs Windows et Linux sont-ils absents ou en erreur ? (Indice : PRTG n’a encore aucun identifiant.)
  3. Combien de capteurs restent disponibles sur les 100 de la licence gratuite ? (Setup → License ; pendant l’essai, le nombre est illimité.)

Pour partir sur une base propre, créez sous Local Probe un groupe Hexalog (Add Group), dans lequel vous ajouterez vos appareils. Vous pouvez supprimer les appareils créés par la découverte, ou les laisser pour comparer.

Partie D. Superviser Windows, Linux et l’intranet (50 min)

D.1, Les identifiants, une fois pour toutes

Groupe Hexalog → onglet Settings → décochez Inherit from… dans les sections suivantes et renseignez :

Section Réglages
Credentials for Windows Systems domaine HEXALOG, utilisateur Administrateur, mot de passe de lab
Credentials for SNMP Devices version SNMP v3, authentification SHA-256, utilisateur supervision, mot de passe Snmp-Auth-Hexalog, chiffrement AES-128, clé Snmp-Chiff-Hexalog (TP 2)

Save. Tous les appareils du groupe en hériteront.

Un compte d'administrateur du domaine pour superviser

L’accès WMI à distance demande des droits d’administrateur sur la machine supervisée ; sur un contrôleur de domaine, cela revient à un compte administrateur du domaine. Dans le lab, on utilise Administrateur faute de temps. En entreprise, on crée un compte de service dédié, avec un mot de passe long, interdit d’ouverture de session interactive, et on lui délègue les seuls droits WMI et DCOM nécessaires, ou on préfère un agent. C’est le principal reproche fait à la supervision Windows sans agent.

D.2, Ouvrir WMI sur le contrôleur de domaine

Sur srv-win-01 : wf.msc → Règles de trafic entrant → activez les règles du groupe Infrastructure de gestion Windows (WMI) pour le profil Domaine (sélectionnez-les toutes, clic droit → Activer la règle). Pour aller plus loin, limitez-les à l’adresse distante 10.20.N.41 (onglet Étendue).

D.3, srv-win-01

Groupe Hexalog → Add Device : nom srv-win-01, adresse 10.20.N.10, Device Icon au choix, Sensor Management : Manual → OK. Puis sur l’appareil → Add Sensor, et cherchez chaque type par son nom :

Capteur Réglage particulier
Ping
WMI CPU Load
WMI Memory
WMI Free Disk Space (Multi Disk)
WMI Service cochez DNS Server et Active Directory Domain Services (un capteur par service)
DNS v2 nom à résoudre : intranet.hexalog.local

D.4, srv-lnx-01 en SNMPv3

Groupe Hexalog → Add Device : srv-lnx-01, 10.20.N.20, Manual. Puis les capteurs SNMP Linux Load Average, SNMP Linux Disk Free, SNMP Linux Meminfo, SNMP Traffic (interface eth0). Ils utilisent l’utilisateur SNMPv3 créé au TP 2 : rien à changer sur srv-lnx-01.

D.5, L’intranet

Sur l’appareil srv-lnx-01 → Add Sensor → HTTP Advanced :

Champ Valeur
Sensor Name Intranet - sante
URL http://10.20.N.20/sante.php
Content Changes / Require Keyword mot-clé requis : BASE-OK (si absent : état Down)

Ajoutez un second HTTP Advanced Intranet - accueil sur http://10.20.N.20/ avec le mot-clé Hexalog.

Notez le nombre total de capteurs utilisés.

Partie E. Seuils et notifications (30 min)

E.1, Une limite sur un canal

Capteur SNMP Linux Disk Free de srv-lnx-01 → canal du système de fichiers / (Free Bytes %) → icône d’engrenage du canal → Enable alerting based on limits : Lower Warning Limit 30, Lower Error Limit 15 (pourcentages d’espace libre).

Provoquez un remplissage comme au TP 5 (fichier fallocate d’environ 75 % du disque) et observez le capteur passer en Warning, puis supprimez le fichier.

E.2, Un ticket quand l’intranet tombe

Dans le lab, sup-win-01 n’a pas de messagerie : on utilise les tickets internes de PRTG.

  1. Setup → Account Settings → Notification Templates → Add Notification Template : nom Ticket astreinte, méthode Assign Ticket, attribué à l’utilisateur PRTG System Administrator. Save.
  2. Groupe Hexalog → onglet Notification Triggers → Add State Trigger : When sensor state is Down for at least 60 seconds, perform Ticket astreinte ; When sensor state is Up again… perform Ticket astreinte. Save. Le déclencheur est hérité par tous les capteurs du groupe.
  3. Sur srv-lnx-01 : sudo systemctl stop mariadb. Le capteur Intranet - sante passe Down ; après une minute, un ticket apparaît dans le menu Tickets. Clic droit sur le capteur → Acknowledge Alarm (« pris en charge »), puis redémarrez MariaDB.
  4. Comparez avec Zabbix sur la même panne : délai d’affichage, nombre d’alertes, information donnée.

Partie F. Une carte d’Hexalog (facultatif, 20 min)

Maps → Add Map : nom Hexalog. Glissez les appareils srv-win-01, srv-lnx-01 et sup-lnx-01 (ajoutez-le s’il n’existe pas) depuis l’arbre de gauche ; reliez-les par des connecteurs ; ajoutez un objet d’état (Status icon) pour le capteur Intranet - sante. Ouvrez la carte en lecture seule : elle se met à jour toute seule. Pour qui une telle carte est-elle utile ?

Avant de passer à la suite : snapshot 06-prtg de sup-win-01, puis arrêtez sup-win-01 (bouton Arrêter de Proxmox).

Partie G. Comparer et choisir

G.1, La grille de comparaison (20 min)

Avec votre expérience des TP 3 à 6, complétez la grille suivante dans votre journal de bord (une note de 1 à 4 et une justification courte par case). Pour Centreon et Prometheus, appuyez-vous sur le cours et sur leur documentation.

G.2, Trois entreprises, trois choix (25 min)

Pour chaque entreprise, recommandez un outil en dix lignes au plus, en vous appuyant sur la grille (modèle « Fiche de choix » de la page Modèles de livrables) :

  1. Cabinet Delmas, expertise comptable, 35 salariés : 3 serveurs Windows (annuaire, fichiers, logiciel comptable), un pare-feu, deux commutateurs, un NAS. Un seul technicien, à mi-temps, à l’aise avec Windows, pas avec Linux. Budget annuel informatique serré.
  2. Infogérance Limousin, ESN de 40 personnes : elle supervise, pour 25 clients, environ 400 serveurs Windows et Linux et leurs équipements réseau, dans leurs locaux. L’équipe d’exploitation (6 personnes) est compétente sous Linux. Les clients demandent des rapports mensuels de disponibilité.
  3. Colis Express, jeune entreprise de 20 développeurs : son application de suivi de colis est découpée en microservices déployés sur Kubernetes dans le cloud ; les développeurs veulent suivre les temps de réponse et les erreurs de chaque microservice.

Vérifications

Questions

  1. Combien de capteurs avez-vous utilisés pour deux serveurs et l’intranet ? Extrapolez pour les 60 serveurs d’une entreprise moyenne.
  2. Pourquoi n’avez-vous rien eu à installer sur srv-lnx-01 pour PRTG ? Et sur srv-win-01 ?
  3. Pourquoi les identifiants sont-ils réglés sur le groupe plutôt que sur chaque appareil ?
  4. Quel risque prend Hexalog en confiant le compte Administrateur du domaine à PRTG ? Que proposez-vous ?
  5. Quelles différences voyez-vous entre l’acquittement dans PRTG, dans Zabbix et dans Nagios ?

Dépannage

Symptôme Piste
L’installation échoue ou bloque mémoire insuffisante (4 Go), ou programme d’installation incomplet : relancer ; voir le journal dans C:\ProgramData\Paessler
https://PROXMOX:1N443/ ne répond pas sup-win-01 éteinte, adresse différente de .41, ou pare-feu de sup-win-01 (règle PRTG créée à l’installation ?)
Capteurs WMI : The RPC server is unavailable (0x800706BA) règles WMI non activées sur srv-win-01 (D.2), ou mauvaise adresse
Capteurs WMI : Access denied (0x80070005) identifiants Windows du groupe faux, ou non hérités (case Inherit restée cochée sur l’appareil)
Capteurs SNMP : No response paramètres v3 différents de ceux du TP 2, snmpd arrêté ; tester depuis sup-lnx-01 avec snmpget
HTTP Advanced : Required keyword not found mot-clé avec une faute ; c’est aussi exactement le symptôme quand la base est arrêtée
La découverte crée des dizaines de capteurs inutiles normal : on garde ce qui sert et on supprime le reste (licence)
