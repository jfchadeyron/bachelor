TP 1 : Prendre en main Proxmox et construire le lab

Vous vous connectez au serveur Proxmox, vous fabriquez vos premières VM à partir des modèles en quelques minutes grâce à cloud-init, vous y accédez depuis votre PC par SSH avec rebond, vous installez l'intranet d'Hexalog, puis vous recréez le contrôleur de domaine hexalog.local. À la fin, le lab est prêt à être supervisé.

Durée3 h
Machines virtuellessup-lnx-01, srv-lnx-01, srv-win-01 (créées dans ce TP)

Contexte

Hexalog a migré son infrastructure sur un serveur Proxmox VE. Vous recréez le cœur du système d’information dans votre espace : un serveur Linux qui porte l’intranet de suivi des expéditions (nginx, PHP, MariaDB), le contrôleur de domaine hexalog.local, et le futur serveur de supervision, qui sera aussi votre point d’entrée pour l’administration.

Organisation

Socle (indispensable pour la séance 2) : parties A à E, et la partie F jusqu’à la création du domaine (F.4). Les parties F.5 à F.7 peuvent être terminées au début de la séance 2. La partie G est facultative.

Notez dès maintenant vos valeurs dans votre journal de bord : votre numéro N, l’adresse PROXMOX, l’adresse DNS-SECOURS, le mot de passe de lab.

Architecture visée

Partie A. Prendre en main Proxmox (15 min)

A.1, Se connecter

  1. Ouvrez https://PROXMOX:8006 dans votre navigateur et acceptez le certificat (il est autosigné, comme celui de l’intranet du BLOC 1).
  2. Nom d’utilisateur etuN, mot de passe donné par M. CHADEYRON, domaine : Proxmox VE authentication server, langue : Français.
  3. Changez votre mot de passe : en haut à droite, menu de votre compte → Mot de passe.

A.2, Se repérer

  1. En haut de l’arborescence de gauche, choisissez la Vue Pool : votre pool etuN est vide pour l’instant.
  2. Revenez à la Vue serveur et dépliez le nœud : vous voyez les deux modèles (icône différente des VM), 9000 (TPL-DEB13) et 9001 (TPL-WS2025), les stockages auxquels vous avez accès, et votre zone réseau hexa avec votre VNet hexaN.
  3. Cliquez sur le modèle 9000 → Matériel : notez le disque, la mémoire, et l’absence de carte réseau. Onglet Cloud-Init : les champs sont vides, ils seront remplis sur chaque clone.

Partie B. Créer sup-lnx-01 (30 min)

B.1, Préparer votre clé SSH

Les VM Debian refusent les connexions SSH par mot de passe : vous vous connecterez avec la clé de votre PC, créée au TP 10 du BLOC 1 (perso-pc). Affichez la clé publique :

Machine : PC (Windows, PowerShell)
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub

Sous Linux : cat ~/.ssh/id_ed25519.pub. Si le fichier n’existe pas, créez la paire : ssh-keygen -t ed25519 -C perso-pc (avec une phrase de passe). La ligne commence par ssh-ed25519 AAAA : c’est elle que vous collerez dans Proxmox. La clé privée (id_ed25519, sans extension) ne quitte jamais votre PC.

B.2, Cloner le modèle

Clic droit sur 9000 (TPL-DEB13) → Cloner :

Champ Valeur
ID de VM N40 (par exemple 340 pour l’étudiant 3)
Nom sup-lnx-01
Mode Clone lié
Pool de ressources etuN

Cliquez sur Cloner : quelques secondes suffisent, car un clone lié ne copie rien (voir le cours).

B.3, Ajuster le matériel

Sélectionnez sup-lnx-01 → Matériel :

  1. Mémoire → Modifier → 3072 Mio.
  2. Processeurs → Modifier → 2 cœurs.
  3. Disque dur (scsi0) → Action du disque → Redimensionner → incrément de 10 Gio (le disque passe à 20 Gio ; le système l’agrandira tout seul au démarrage).
  4. Ajouter → Périphérique réseau : pont hexaN, modèle VirtIO (paravirtualisé), case Pare-feu décochée → Ajouter.

B.4, Remplir l’onglet Cloud-Init

Champ Valeur
Utilisateur sysadmin
Mot de passe le mot de passe de lab
Domaine DNS hexalog.local
Serveurs DNS 10.20.N.10 DNS-SECOURS (les deux adresses séparées par une espace)
Clé publique SSH la ligne ssh-ed25519 AAAA… perso-pc de B.1
Mettre à niveau les paquets Oui
Config. IP (net0) IPv4 Statique : 10.20.N.40/24, passerelle 10.20.N.1

Cliquez sur Régénérer l’image.

B.5, Premier démarrage

  1. Démarrer, puis Console : la VM démarre sur une console texte (xterm.js). Appuyez sur Entrée si l’écran reste vide.
  2. Connectez-vous avec sysadmin et le mot de passe de lab, puis attendez la fin de cloud-init (il installe les mises à jour : deux à cinq minutes) :
Machine : sup-lnx-01 (console Proxmox) (sysadmin)
cloud-init status --wait
hostnamectl
ip -br a
ip route
resolvectl status eth0
ping -c 2 deb.debian.org

Résultat attendu : status: done, nom d’hôte sup-lnx-01, adresse 10.20.N.40/24 sur eth0, route par défaut via 10.20.N.1, serveurs DNS 10.20.N.10 et DNS-SECOURS, et le ping répond. Le contrôleur de domaine n’existe pas encore : c’est le DNS de secours qui répond pour l’instant.

Partie C. Créer srv-lnx-01 (15 min)

Même méthode, avec ces valeurs :

Réglage Valeur
ID de VM, nom N20, srv-lnx-01
Mémoire, processeurs 1024 Mio, 1 cœur
Disque on le laisse à 10 Gio
Carte réseau pont hexaN, VirtIO, sans pare-feu
Cloud-Init mêmes champs, adresse 10.20.N.20/24

Démarrez-la et vérifiez comme en B.5 (cloud-init status --wait, ip -br a).

Partie D. Accéder aux VM depuis votre PC (20 min)

D.1, Première connexion par la redirection de port

Machine : PC
ssh -p 1N022 sysadmin@PROXMOX

Votre PC ne connaît pas encore ce serveur : il affiche l’empreinte de sa clé d’hôte. Avant de répondre yes, comparez-la avec celle que donne la VM elle-même (console Proxmox de sup-lnx-01) :

Machine : sup-lnx-01 (console Proxmox) (sysadmin)
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

Une fois connecté, hostname doit répondre sup-lnx-01. La connexion s’est faite par clé : la phrase de passe demandée est celle de votre clé, pas le mot de passe de lab.

D.2, Le fichier de configuration SSH

Créez ou complétez le fichier de configuration SSH de votre PC avec le bloc de la page du lab (sous Windows : C:\Users\<vous>\.ssh\config, sans extension ; le Bloc-notes ajoute volontiers .txt). Puis :

Machine : PC
ssh sup-lnx-01 hostname
ssh srv-lnx-01 hostname

La seconde commande rebondit par sup-lnx-01 (ProxyJump, vu au TP 12 du BLOC 1) : srv-lnx-01 n’est pas joignable directement depuis votre PC.

D.3, Les droits de sysadmin

Machine : srv-lnx-01 (sysadmin)
id
sudo -l

Le compte créé par cloud-init est membre de sudo et peut l’utiliser sans mot de passe (NOPASSWD: ALL) : c’est le réglage des images cloud, pratique pour le lab. En production, on exigerait une authentification (ou une clé matérielle) pour élever ses privilèges.

Partie E. Installer l’intranet sur srv-lnx-01 (15 min)

L’intranet est une petite application PHP de suivi des expéditions, avec sa base MariaDB. Le script d’installation est sur le site du cours : lisez-le avant de l’exécuter (c’est une bonne habitude avant tout sudo bash).

Machine : srv-lnx-01 (sysadmin)
curl -fsSLO https://jfchadeyron.github.io/bachelor/bloc2/fichiers/installer-intranet.sh
less installer-intranet.sh
sudo bash installer-intranet.sh

Si curl répond par une erreur, le site du cours n’est pas joignable depuis la VM : téléchargez le fichier depuis votre PC (ou prenez-le sur la clé de M. CHADEYRON), puis envoyez-le avec scp installer-intranet.sh srv-lnx-01: et lancez les deux dernières commandes.

Le script installe nginx, PHP-FPM et MariaDB, crée la base intranet et son compte, l’application dans /var/www/intranet, et une page de santé /sante.php qui répond BASE-OK si l’application arrive à lire la base, BASE-KO (avec le code HTTP 500) sinon. Il prépare aussi deux pages d’état lisibles seulement depuis la machine elle-même, qui serviront à Zabbix (/basic_status pour nginx, /status pour PHP-FPM).

Vérifiez :

Machine : sup-lnx-01 (sysadmin)
curl -s http://10.20.N.20/sante.php
curl -s -o /dev/null -w "code %{http_code} en %{time_total} s\n" http://10.20.N.20/
curl -s -o /dev/null -w "basic_status depuis sup-lnx-01 : code %{http_code}\n" http://10.20.N.20/basic_status

Résultat attendu : BASE-OK expeditions=8, code 200, puis code 403 pour la page d’état (réservée à la machine elle-même). Ouvrez enfin l’intranet depuis votre PC, comme un utilisateur : http://PROXMOX:1N020/.

Partie F. Le contrôleur de domaine srv-win-01 (60 min)

F.1, Cloner le modèle Windows

Clic droit sur 9001 (TPL-WS2025) → Cloner : ID N10, nom srv-win-01, clone lié, pool etuN. Puis Matériel : mémoire 3072 Mio, 2 cœurs, et une carte réseau (pont hexaN, VirtIO, sans pare-feu). Démarrer, Console.

F.2, La première configuration de Windows

Le modèle a été généralisé par sysprep : Windows démarre comme un ordinateur neuf. Choisissez la région France, la langue Français, le clavier Français, acceptez la licence, puis saisissez deux fois le mot de passe de lab pour le compte Administrateur.

Pour l’écran de connexion, utilisez le bouton Ctrl-Alt-Suppr du panneau de gauche de la console (la combinaison du clavier serait interceptée par votre PC).

F.3, Adresse fixe et nom

Comme au TP 5 du BLOC 1, en interface graphique :

  1. ncpa.cpl → carte Ethernet → Propriétés → Protocole Internet version 4 : adresse 10.20.N.10, masque 255.255.255.0, passerelle 10.20.N.1, DNS préféré 127.0.0.1, DNS auxiliaire DNS-SECOURS.
  2. sysdm.cpl → Modifier → nom de l’ordinateur SRV-WIN-01 → redémarrer.

Tant que le rôle DNS n’existe pas, Windows résout les noms avec le DNS auxiliaire.

F.4, Créer le domaine hexalog.local

Gestionnaire de serveur → Gérer → Ajouter des rôles et fonctionnalités → rôle Services AD DS → Installer. Puis le drapeau en haut → Promouvoir ce serveur en contrôleur de domaine :

  • Ajouter une nouvelle forêt, domaine racine hexalog.local ;
  • mot de passe du mode de restauration des services d’annuaire (DSRM) : le mot de passe de lab ;
  • nom NetBIOS proposé : HEXALOG ;
  • Installer. Le serveur redémarre (dix minutes environ). Ouvrez ensuite une session HEXALOG\Administrateur.

F.5, Le DNS du domaine

Outils → DNS (dnsmgmt.msc) :

  1. Clic droit sur SRV-WIN-01 → Propriétés → onglet Redirecteurs → Modifier → DNS-SECOURS. Le contrôleur de domaine pourra ainsi résoudre les noms d’Internet pour les autres VM.
  2. Zone hexalog.local → clic droit → Nouvel hôte (A ou AAAA) : srv-lnx-01 → 10.20.N.20 ; srv-lnx-02 → 10.20.N.21 ; sup-lnx-01 → 10.20.N.40 ; sup-win-01 → 10.20.N.41.
  3. Clic droit → Nouvel alias (CNAME) : intranet → srv-lnx-01.hexalog.local ; glpi → srv-lnx-02.hexalog.local.

F.6, Autoriser le ping

Par défaut, le pare-feu de Windows Server ne répond pas au ping : pour la supervision, un serveur qui ne répond pas au ping semblerait éteint. wf.msc → Règles de trafic entrant → activez Partage de fichiers et d’imprimantes (Demande d’écho - Trafic entrant ICMPv4) pour le profil Domaine (clic droit → Activer la règle).

F.7, Vérifier depuis les VM Linux

Machine : sup-lnx-01 (sysadmin)
ping -c 2 10.20.N.10
resolvectl query srv-lnx-01.hexalog.local
resolvectl query intranet.hexalog.local
resolvectl query deb.debian.org

Résultat attendu : le ping répond ; les trois noms sont résolus (le deuxième et le troisième par 10.20.N.10) ; intranet est un alias de srv-lnx-01.

Partie G. Superviser « à la main » (facultatif, 15 min)

Avant d’installer des outils, essayez de savoir si l’intranet va bien avec ce que vous connaissez déjà.

Machine : sup-lnx-01 (sysadmin)
ping -c 3 10.20.N.20
curl -s -o /dev/null -w "code %{http_code} en %{time_total} s\n" http://10.20.N.20/
curl -s http://10.20.N.20/sante.php
Machine : srv-lnx-01 (sysadmin)
uptime
df -h /
free -h
systemctl is-active nginx php8.4-fpm mariadb

Écrivez un petit script ~/verif-intranet.sh qui enchaîne les trois commandes de sup-lnx-01 et affiche « INTRANET OK » ou « INTRANET EN PANNE ». Puis complétez dans votre journal de bord le tableau : que manque-t-il à ce script pour être un outil de supervision ? (pensez à l’historique, aux seuils, aux alertes, au nombre de machines, aux tableaux de bord, à la fiabilité du script lui-même). Les séances 3 à 6 répondent à chacun de ces manques.

Partie H. Snapshots (5 min)

Pour chacune des trois VM : Snapshots → Prendre un snapshot → nom 01-lab-initial, une description courte. Pour srv-win-01, ne cochez pas Inclure la RAM (le snapshot serait beaucoup plus gros).

Vérifications

Questions

  1. Pourquoi la création d’une VM Debian prend-elle deux minutes ici, contre près d’une demi-heure au BLOC 1 ?
  2. Votre clone srv-lnx-01 est un clone lié. Que se passerait-il pour lui si le modèle 9000 était abîmé ? Quel avantage et quel inconvénient a ce choix ?
  3. Dans quel ordre les machines doivent-elles redémarrer après une coupure générale, et pourquoi ?
  4. La page d’état /basic_status répond 403 depuis sup-lnx-01. Est-ce une panne ? Pourquoi l’avoir réglée ainsi ?
  5. Depuis votre PC, pourquoi ne pouvez-vous pas joindre directement 10.20.N.20:22 ? Quel chemin prennent vos paquets avec ssh srv-lnx-01 ?

Dépannage

Symptôme Piste
Le clonage est refusé pool cible etuN oublié, ou numéro de VM déjà pris
La VM démarre sans adresse ni compte sysadmin onglet Cloud-Init rempli après le démarrage : Régénérer l’image, redémarrer
cloud-init status reste sur running longtemps il installe les mises à jour ; si rien ne bouge après 10 minutes : sudo tail -f /var/log/cloud-init-output.log (souvent un problème d’accès à Internet)
ssh -p 1N022 : Connection refused ou timed out sup-lnx-01 éteinte, mauvaise adresse dans Cloud-Init, ou mauvais port (vérifiez N)
Permission denied (publickey) clé publique absente de Cloud-Init, ou ce n’est pas celle du PC utilisé ; la corriger, régénérer l’image, redémarrer
ssh srv-lnx-01 : Could not resolve hostname le bloc Host srv-lnx-01 manque dans le fichier config, ou le fichier s’appelle config.txt
L’installation de l’intranet échoue sur apt pas d’Internet : ip route, resolvectl status eth0, ping -c 2 DNS-SECOURS
La promotion du contrôleur de domaine échoue sur le DNS vérifier l’adresse fixe et le DNS préféré 127.0.0.1 de la carte
resolvectl query intranet.hexalog.local échoue enregistrements non créés (F.5), ou srv-win-01 éteint : le DNS de secours ne connaît pas hexalog.local
Le ping de srv-win-01 échoue alors qu’il est allumé règle ICMPv4 du profil Domaine non activée (F.6)

Pour aller plus loin

  • Lisez le journal de cloud-init (sudo less /var/log/cloud-init-output.log) : retrouvez le moment où le compte, la clé et les mises à jour ont été traités.
  • Faites tourner votre script de la partie G toutes les cinq minutes avec un minuteur systemd (les images cloud de Debian n’ont pas de cron) : un service verif-intranet.service de type oneshot et un minuteur verif-intranet.timer avec OnCalendar=*:0/5. Où lisez-vous ses résultats ? Qui est prévenu en cas de panne ?
