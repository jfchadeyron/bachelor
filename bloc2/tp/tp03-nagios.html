TP 3 : Superviser Hexalog avec Nagios

Vous installez Nagios Core sur sup-lnx-01 et sécurisez son interface, vous déclarez les hôtes et services d'Hexalog avec vos propres modèles, vous installez l'agent NRPE sur srv-lnx-01, vous observez le passage des états SOFT aux états HARD lors d'une vraie panne, et vous recevez les alertes par courriel.

Durée3 h
Machines virtuellessup-lnx-01, srv-lnx-01, srv-win-01
Cours associéSéance 3 : Nagios Core : hôtes, services, états
Sommaire

Contexte

Le responsable informatique veut une première supervision rapidement, avec un outil libre et éprouvé. Vous mettez en place Nagios à partir de la matrice de supervision du TP 2.

Organisation

Socle : parties A à F. Facultatif : partie G (Windows avec NCPA), partie H (SNMP), « Pour aller plus loin ».

Dans les fichiers de configuration, les adresses sont écrites 10.20.N.… : une commande sed remplace N par votre numéro à la fin de la partie C.

Partie A. Installer Nagios (15 min)

Snapshot 03-avant-nagios de sup-lnx-01, puis :

Machine : sup-lnx-01 (sysadmin)
sudo apt install -y nagios4 monitoring-plugins nagios-nrpe-plugin
systemctl status nagios4 apache2 --no-pager
ls /etc/nagios4 /etc/nagios4/objects /etc/nagios4/conf.d

Le paquet installe aussi Apache, qui sert l’interface web. Repérez dans /etc/nagios4 les fichiers décrits dans le cours.

Partie B. Protéger l’interface web (20 min)

Sous Debian, l’interface est livrée sans authentification. On crée un compte nagiosadmin et on l’exige pour toutes les pages.

  1. Créez le compte (mot de passe de lab) :
Machine : sup-lnx-01 (sysadmin)
sudo htdigest -c /etc/nagios4/htdigest.users Nagios4 nagiosadmin
  1. Remplacez la configuration Apache de Nagios :
Machine : sup-lnx-01 (sysadmin)
sudo cp /etc/apache2/conf-available/nagios4-cgi.conf /etc/apache2/conf-available/nagios4-cgi.conf.origine
sudo tee /etc/apache2/conf-available/nagios4-cgi.conf > /dev/null <<'EOF'
# Nagios 4 : interface web protégée par identifiant et mot de passe (Hexalog)
ScriptAlias /cgi-bin/nagios4 /usr/lib/cgi-bin/nagios4
ScriptAlias /nagios4/cgi-bin /usr/lib/cgi-bin/nagios4
Alias /nagios4/stylesheets /etc/nagios4/stylesheets
Alias /nagios4 /usr/share/nagios4/htdocs

<DirectoryMatch (/usr/share/nagios4/htdocs|/usr/lib/cgi-bin/nagios4|/etc/nagios4/stylesheets)>
    Options FollowSymLinks
    DirectoryIndex index.php index.html
    AllowOverride AuthConfig
    AuthDigestDomain "Nagios4"
    AuthDigestProvider file
    AuthUserFile "/etc/nagios4/htdigest.users"
    AuthGroupFile "/etc/group"
    AuthName "Nagios4"
    AuthType Digest
    Require valid-user
</DirectoryMatch>

<Directory /usr/share/nagios4/htdocs>
    Options +ExecCGI
</Directory>
EOF
  1. Activez l’authentification dans Nagios lui-même (pour que les droits de nagiosadmin s’appliquent), activez les modules Apache nécessaires, redémarrez :
Machine : sup-lnx-01 (sysadmin)
sudo sed -i 's/^use_authentication=0/use_authentication=1/' /etc/nagios4/cgi.cfg
sudo a2enmod cgi auth_digest
sudo apache2ctl configtest
sudo systemctl restart apache2 nagios4
curl -s -o /dev/null -w "sans compte : %{http_code}\n" http://localhost/nagios4/

Résultat attendu : Syntax OK, puis 401 (identification exigée). Depuis votre PC, ouvrez http://PROXMOX:1N080/nagios4 et connectez-vous avec nagiosadmin.

  1. Parcourez Tactical Overview, Hosts et Services : Nagios supervise déjà localhost (sup-lnx-01 elle-même). Un service est CRITIQUE : Swap Usage. L’image cloud de Debian n’a pas d’espace d’échange (swap) : c’est une fausse alerte, à supprimer plutôt qu’à tolérer (cours 1, fatigue d’alerte). La commande suivante met en commentaire (un # en début de ligne) le bloc qui définit ce contrôle dans /etc/nagios4/objects/localhost.cfg ; vérifiez le résultat avec grep, puis rechargez :
Machine : sup-lnx-01 (sysadmin)
sudo sed -i '/check the swap usage/,/^}/ s/^/#/' /etc/nagios4/objects/localhost.cfg
grep -n -B4 -A2 "Swap Usage" /etc/nagios4/objects/localhost.cfg
sudo nagios4 -v /etc/nagios4/nagios.cfg | tail -3
sudo systemctl reload nagios4

Partie C. Les hôtes et services d’Hexalog (45 min)

On range la configuration d’Hexalog dans quatre fichiers du dossier conf.d. Copiez chaque bloc tel quel (les $ sont des macros de Nagios, à ne pas modifier).

C.1, Contacts et modèles

Machine : sup-lnx-01 (sysadmin)
sudo tee /etc/nagios4/conf.d/hexalog-modeles.cfg > /dev/null <<'EOF'
# Contacts et modèles d'Hexalog
define contact {
    contact_name            astreinte
    use                     generic-contact
    alias                   Astreinte informatique Hexalog
    email                   sysadmin@localhost
}

define contactgroup {
    contactgroup_name       hexalog-admins
    alias                   Administrateurs Hexalog
    members                 astreinte
}

# Un service d'Hexalog est contrôlé toutes les 2 minutes ; en cas de problème,
# il est recontrôlé toutes les minutes et devient HARD au 3e échec.
define service {
    name                    hexalog-service
    use                     generic-service
    check_interval          2
    retry_interval          1
    max_check_attempts      3
    notification_interval   30
    contact_groups          hexalog-admins
    register                0
}

define host {
    name                    hexalog-hote
    use                     generic-host
    check_command           check-host-alive
    check_interval          2
    retry_interval          1
    max_check_attempts      3
    contact_groups          hexalog-admins
    register                0
}
EOF

C.2, Commandes

Votre plugin du TP 2 (check_intranet) devient une commande Nagios.

Machine : sup-lnx-01 (sysadmin)
sudo tee /etc/nagios4/conf.d/hexalog-commandes.cfg > /dev/null <<'EOF'
# Commandes d'Hexalog (préfixe hx- : pas de conflit avec les commandes de Debian)
define command {
    command_name    hx-http-page
    command_line    $USER1$/check_http -I $HOSTADDRESS$ -u $ARG1$ -s $ARG2$
}
define command {
    command_name    hx-tcp
    command_line    $USER1$/check_tcp -H $HOSTADDRESS$ -p $ARG1$
}
define command {
    command_name    hx-dns
    command_line    $USER1$/check_dns -H $ARG1$ -s $HOSTADDRESS$ -a $ARG2$
}
define command {
    command_name    hx-intranet
    command_line    /usr/local/lib/nagios/check_intranet $HOSTADDRESS$
}
define command {
    command_name    hx-nrpe
    command_line    $USER1$/check_nrpe -H $HOSTADDRESS$ -c $ARG1$
}
EOF

C.5, Votre numéro, vérification, chargement

Remplacez 3 par votre numéro dans la première commande :

Machine : sup-lnx-01 (sysadmin)
sudo sed -i 's/10\.20\.N\./10.20.3./g' /etc/nagios4/conf.d/hexalog-*.cfg
grep -n "10.20" /etc/nagios4/conf.d/hexalog-*.cfg
sudo nagios4 -v /etc/nagios4/nagios.cfg | grep -E "Checked (hosts|services)|Total"
sudo systemctl reload nagios4

Résultat attendu : 3 hôtes (avec localhost), Total Warnings: 0, Total Errors: 0. Si votre plugin du TP 2 n’est pas dans /usr/local/lib/nagios/check_intranet, le service Intranet - sante restera en UNKNOWN : reprenez la partie B.4 du TP 2.

Dans l’interface, les nouveaux services sont d’abord PENDING, puis passent à OK en deux minutes au plus. Pour ne pas attendre : page de l’hôte → Schedule a check of all services on this host.

Partie D. L’agent NRPE sur srv-lnx-01 (30 min)

D.1, Installer et configurer l’agent

Machine : srv-lnx-01 (sysadmin)
sudo apt install -y nagios-nrpe-server monitoring-plugins
sudo tee /etc/nagios/nrpe.d/hexalog.cfg > /dev/null <<'EOF'
# Hexalog : serveur de supervision autorisé et commandes proposées
allowed_hosts=127.0.0.1,::1,10.20.N.40
command[hx_disque_racine]=/usr/lib/nagios/plugins/check_disk -w 20% -c 10% -p /
command[hx_charge]=/usr/lib/nagios/plugins/check_load -r -w 0.8,0.7,0.6 -c 1.5,1.2,1.0
command[hx_nginx]=/usr/lib/nagios/plugins/check_procs -C nginx -c 1:
command[hx_phpfpm]=/usr/lib/nagios/plugins/check_procs -C php-fpm8.4 -c 1:
command[hx_mariadb]=/usr/lib/nagios/plugins/check_procs -C mariadbd -c 1:
command[hx_maj]=/usr/lib/nagios/plugins/check_apt
EOF
sudo sed -i 's/10\.20\.N\./10.20.3./' /etc/nagios/nrpe.d/hexalog.cfg     # votre numéro
sudo systemctl restart nagios-nrpe-server
sudo ss -tlnp | grep 5666

Le fichier ajouté est lu après le fichier principal : sa ligne allowed_hosts remplace celle de nrpe.cfg. On ne modifie pas le fichier fourni par le paquet.

D.2, Tester depuis sup-lnx-01

Machine : sup-lnx-01 (sysadmin)
/usr/lib/nagios/plugins/check_nrpe -H 10.20.N.20
for c in hx_disque_racine hx_charge hx_nginx hx_phpfpm hx_mariadb hx_maj ; do
  /usr/lib/nagios/plugins/check_nrpe -H 10.20.N.20 -c $c ; echo "  -> code $?"
done
/usr/lib/nagios/plugins/check_nrpe -H 10.20.N.20 -c commande_inconnue

Résultat attendu : la version de NRPE, puis un résultat par commande. hx_maj est probablement en WARNING ou CRITICAL : des mises à jour attendent (séance 7). Une commande inconnue est refusée.

Partie E. Observer SOFT et HARD sur une vraie panne (25 min)

Gardez ouverte la page Services de srv-lnx-01 (elle s’actualise toute seule toutes les 90 secondes ; F5 pour forcer). Notez l’heure, puis :

Machine : srv-lnx-01 (sysadmin)
date ; sudo systemctl stop nginx

Pendant cinq minutes, relevez dans un tableau l’heure, l’état et le type d’état (State Type : SOFT ou HARD, et le numéro d’essai, Current Attempt) des services Intranet - accueil, Intranet - sante et Processus nginx. Puis :

Machine : srv-lnx-01 (sysadmin)
date ; sudo systemctl start nginx
  1. Combien de temps s’est écoulé entre l’arrêt de nginx et le passage en HARD ? Comparez avec la formule du cours.
  2. Le service SSH a-t-il changé d’état ? Et Processus PHP-FPM ? Que montre cette panne sur l’intérêt de superviser à la fois de l’extérieur et de l’intérieur ?
  3. Ouvrez Event Log : retrouvez les lignes SERVICE ALERT (SOFT, puis HARD) et le rétablissement.

Partie F. Les alertes par courriel (25 min)

F.1, Une messagerie locale

Postfix, configuré en « local uniquement », remet les courriels dans les boîtes des comptes de sup-lnx-01, sans rien envoyer à l’extérieur.

Machine : sup-lnx-01 (sysadmin)
echo "postfix postfix/main_mailer_type select Local only" | sudo debconf-set-selections
echo "postfix postfix/mailname string sup-lnx-01.hexalog.local" | sudo debconf-set-selections
sudo apt install -y postfix mailutils
echo "Message de test" | mail -s "Test de messagerie" sysadmin@localhost
mail

Dans mail, tapez le numéro du message pour le lire, d pour le supprimer, q pour quitter.

F.2, Recevoir une alerte

Arrêtez de nouveau nginx sur srv-lnx-01. Quand le service passe en HARD, une notification part : lisez-la avec mail sur sup-lnx-01. Redémarrez nginx : un message RECOVERY arrive à son tour.

F.3, Acquitter et planifier un arrêt

  1. Arrêtez MariaDB sur srv-lnx-01. Quand Intranet - sante est CRITICAL HARD, depuis la page du service : Acknowledge this service problem, avec un commentaire (« pris en charge par … »). Que change l’acquittement dans Problems et Unhandled ? Redémarrez MariaDB.
  2. Vous devez redémarrer srv-lnx-01 pour une maintenance. Page de l’hôte → Schedule downtime for this host and all services, pour 15 minutes. Redémarrez la VM (sudo reboot). Avez-vous reçu des notifications ? Que montre Event Log ?

Partie G. Windows avec NCPA (facultatif, 30 min)

  1. Sur srv-win-01, téléchargez l’agent NCPA (https://assets.nagios.com/downloads/ncpa3/ncpa-latest.exe) avec le navigateur, puis installez-le. Pendant l’installation, choisissez un jeton (token) long, par exemple Jeton-NCPA-Hexalog-2027, et laissez le port 5693.
  2. wf.msc : vérifiez qu’une règle de trafic entrant autorise le port TCP 5693 ; sinon, créez-la en la limitant à l’adresse distante 10.20.N.40.
  3. Sur sup-lnx-01 :
Machine : sup-lnx-01 (sysadmin)
sudo curl -fsSL -o /usr/lib/nagios/plugins/check_ncpa.py https://raw.githubusercontent.com/NagiosEnterprises/ncpa/master/client/check_ncpa.py
sudo chmod 755 /usr/lib/nagios/plugins/check_ncpa.py
echo '$USER9$=Jeton-NCPA-Hexalog-2027' | sudo tee -a /etc/nagios4/resource.cfg
P=/usr/lib/nagios/plugins/check_ncpa.py ; T=Jeton-NCPA-Hexalog-2027
python3 $P -H 10.20.N.10 -t $T -M system/agent_version
python3 $P -H 10.20.N.10 -t $T -M cpu/percent -q aggregate=avg -w 80 -c 95
python3 $P -H 10.20.N.10 -t $T -M memory/virtual/percent -w 85 -c 95
python3 $P -H 10.20.N.10 -t $T -M 'disk/logical/C:|/used_percent' -w 80 -c 90
python3 $P -H 10.20.N.10 -t $T -M services -q service=NTDS,status=running
python3 $P -H 10.20.N.10 -t $T -M services -q service=DNS,status=running
  1. Déclarez la commande et les services :
Machine : sup-lnx-01 (sysadmin)
sudo tee /etc/nagios4/conf.d/hexalog-ncpa.cfg > /dev/null <<'EOF'
define command {
    command_name    hx-ncpa
    command_line    /usr/bin/python3 $USER1$/check_ncpa.py -H $HOSTADDRESS$ -t $USER9$ $ARG1$
}
define service {
    use                     hexalog-service
    host_name               srv-win-01
    service_description     Processeur
    check_command           hx-ncpa!-M cpu/percent -q aggregate=avg -w 80 -c 95
}
define service {
    use                     hexalog-service
    host_name               srv-win-01
    service_description     Service NTDS
    check_command           hx-ncpa!-M services -q service=NTDS,status=running
}
define service {
    use                     hexalog-service
    host_name               srv-win-01
    service_description     Service DNS
    check_command           hx-ncpa!-M services -q service=DNS,status=running
}
EOF
sudo nagios4 -v /etc/nagios4/nagios.cfg | grep Total
sudo systemctl reload nagios4

Partie H. SNMP dans Nagios (facultatif, 15 min)

Rangez les identifiants SNMPv3 du TP 2 dans resource.cfg (lisible par Nagios seulement), puis utilisez-les dans une commande :

Machine : sup-lnx-01 (sysadmin)
sudo tee -a /etc/nagios4/resource.cfg > /dev/null <<'EOF'
# SNMPv3 vers srv-lnx-01
$USER3$=supervision
$USER4$=Snmp-Auth-Hexalog
$USER5$=Snmp-Chiff-Hexalog
EOF
sudo tee /etc/nagios4/conf.d/hexalog-snmp.cfg > /dev/null <<'EOF'
define command {
    command_name    hx-snmp-charge
    command_line    $USER1$/check_snmp -H $HOSTADDRESS$ -P 3 -L authPriv -U $USER3$ -a SHA-256 -A $USER4$ -x AES -X $USER5$ -o .1.3.6.1.4.1.2021.10.1.5.1 -w $ARG1$ -c $ARG2$ -l "charge x100"
}
define service {
    use                     hexalog-service
    host_name               srv-lnx-01
    service_description     Charge SNMP
    check_command           hx-snmp-charge!150!300
}
EOF
ls -l /etc/nagios4/resource.cfg
sudo nagios4 -v /etc/nagios4/nagios.cfg | grep Total
sudo systemctl reload nagios4

Vérifications

Questions

  1. Pourquoi les hôtes sont-ils déclarés par leur adresse IP plutôt que par leur nom DNS ?
  2. Quel serait le délai maximal de détection avec le modèle generic-service de Debian ? Proposez des valeurs pour un service critique, et dites ce que vous y perdez.
  3. Pourquoi une seule panne (nginx arrêté) a-t-elle fait passer plusieurs services en CRITICAL ? Comment éviter de recevoir plusieurs alertes pour une seule cause ?
  4. NRPE refuse commande_inconnue. Pourquoi est-ce important pour la sécurité ?
  5. Pourquoi supprimer le contrôle Swap Usage plutôt que de s’habituer à le voir rouge ?
  6. Quelle différence d’usage entre acquitter un problème et planifier un arrêt ?

Dépannage

Symptôme Piste
nagios4 -v : contains one or more illegal characters apostrophe, parenthèse ou autre caractère interdit dans host_name ou service_description
nagios4 -v : Duplicate definition found for command deux commandes portent le même nom (par exemple une redéfinition de check_http)
Could not find any host matching '…' le service désigne un hôte mal orthographié, ou le fichier des hôtes n’est pas dans conf.d
L’interface demande le mot de passe en boucle mot de passe différent de celui créé avec htdigest, ou royaume (Nagios4) différent
L’interface affiche It appears as though you do not have permission use_authentication=1 mais vous n’êtes pas connecté en nagiosadmin
Error: Could not stat() command file en voulant acquitter sudo systemctl restart nagios4 ; vérifier que check_external_commands=1 dans nagios.cfg
CHECK_NRPE: … Connection refused nagios-nrpe-server arrêté sur srv-lnx-01
CHECK_NRPE: (ssl_err != 5) Error - Could not complete SSL handshake ou connexion fermée l’adresse de sup-lnx-01 n’est pas dans allowed_hosts (N mal remplacé ?) ; sudo journalctl -u nagios-nrpe-server sur srv-lnx-01
NRPE: Command '…' not defined nom de commande différent entre Nagios et nrpe.d/hexalog.cfg
Service Intranet - sante en UNKNOWN plugin /usr/local/lib/nagios/check_intranet absent ou non exécutable
