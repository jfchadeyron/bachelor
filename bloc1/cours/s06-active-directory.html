Cours de la séance 6

Active Directory : utilisateurs, groupes et unités d'organisation

L'annuaire est le cœur d'une infrastructure Windows : une identité unique par personne, des groupes pour attribuer les droits, une organisation qui permet de déléguer et d'appliquer des stratégies. Cette séance pose le vocabulaire d'Active Directory, la logique des groupes (AGDLP) et le principe du contrôle d'accès par rôle.

1. Pourquoi un annuaire ?

Sans annuaire, chaque ordinateur gère ses propres comptes : c’est un groupe de travail (workgroup). Si Alice utilise trois ordinateurs et deux serveurs, elle a cinq comptes, cinq mots de passe, et quand elle quitte l’entreprise il faut penser à les supprimer tous.

Avec un annuaire, chaque personne a une seule identité, stockée à un endroit central. Les ordinateurs et les serveurs membres du domaine font confiance à l’annuaire pour vérifier les mots de passe et connaître les groupes de chacun.

Groupe de travail Domaine Active Directory
Comptes locaux, sur chaque machine centralisés dans l’annuaire
Mot de passe un par machine un seul, partout
Droits gérés machine par machine gérés par groupes, centralement
Départ d’un salarié supprimer N comptes désactiver un compte
Stratégies (sécurité, configuration) machine par machine centralisées (GPO)
Taille adaptée moins de 10 postes au-delà

2. Le vocabulaire d’Active Directory

Active Directory Domain Services (AD DS) est le service d’annuaire de Microsoft. Il s’appuie sur trois protocoles :

  • LDAP pour lire et écrire dans l’annuaire ;
  • Kerberos pour l’authentification (par tickets, séance 11) ;
  • DNS pour que les machines trouvent les contrôleurs de domaine (enregistrements SRV).
Terme Définition
Domaine ensemble d’objets (utilisateurs, ordinateurs, groupes) partageant la même base et les mêmes règles. Nom DNS : hexalog.lan ; nom court (NetBIOS) : HEXALOG
Contrôleur de domaine (DC) serveur qui héberge une copie de la base de l’annuaire et authentifie les utilisateurs. En production, au moins deux DC qui se répliquent
Forêt ensemble d’un ou plusieurs domaines partageant un même schéma ; le premier domaine créé crée la forêt
Schéma la définition de tous les types d’objets et de leurs attributs
Objet un élément de l’annuaire : utilisateur, groupe, ordinateur, OU, imprimante…
Attribut une propriété d’un objet : nom, identifiant, service, fonction, adresse e-mail, appartenance aux groupes…
SID identifiant de sécurité unique d’un compte ou d’un groupe. Les droits sont attribués au SID, pas au nom : un compte supprimé puis recréé avec le même nom n’a plus les mêmes droits

L'heure compte

Kerberos refuse l’authentification si l’horloge d’un poste diffère de plus de 5 minutes de celle du contrôleur de domaine. Une machine à la mauvaise heure ne peut plus ouvrir de session.

Nommer un utilisateur

Un même compte peut être désigné de plusieurs façons :

  • HEXALOG\a.martin : domaine NetBIOS + identifiant (sAMAccountName) ;
  • a.martin@hexalog.lan : nom d’utilisateur principal (UPN), au format d’une adresse e-mail ;
  • CN=Alice Martin,OU=Comptabilite,OU=Utilisateurs,OU=HEXALOG,DC=hexalog,DC=lan : nom distinctif (DN), le chemin complet dans l’annuaire, lu de droite à gauche.

3. Les unités d’organisation

Une unité d’organisation (OU) est un dossier de l’annuaire. Elle sert à :

  1. organiser les objets de façon lisible ;
  2. déléguer l’administration (le service informatique d’un site gère l’OU de ce site) ;
  3. appliquer des stratégies de groupe (GPO) à un ensemble d’utilisateurs ou d’ordinateurs.

Une OU ne donne aucun droit

Placer Alice dans l’OU « Comptabilite » ne lui donne pas accès aux fichiers de la comptabilité. Les droits d’accès passent par les groupes. Les OU organisent, les groupes autorisent.

Les dossiers par défaut Users et Computers ne sont pas des OU (ce sont des conteneurs) : on ne peut pas y lier de GPO. On crée donc sa propre arborescence. Celle d’Hexalog :

Les OU sont par défaut protégées contre la suppression accidentelle : pour en supprimer une, il faut d’abord décocher cette option (onglet Objet, avec l’affichage des fonctionnalités avancées).

4. Les groupes

Types

  • Groupe de sécurité : peut recevoir des droits (sur un dossier, une imprimante, une stratégie). C’est celui qu’on utilise.
  • Groupe de distribution : sert uniquement de liste de diffusion de messagerie.

Étendues

Étendue Peut contenir Utilisable pour des droits Usage
Globale des comptes et groupes globaux du même domaine dans toute la forêt regrouper des personnes par rôle ou service
Domaine local des comptes et groupes globaux ou universels de toute la forêt dans son domaine recevoir les permissions sur une ressource
Universelle comptes et groupes de toute la forêt dans toute la forêt forêts à plusieurs domaines

La méthode AGDLP

Accounts → Global groups → Domain Local groups → Permissions.

  1. On met les comptes dans des groupes globaux qui représentent des rôles : GG_Comptabilite.
  2. On crée pour chaque ressource et chaque niveau d’accès un groupe de domaine local : DL_Compta_RW (lecture-écriture), DL_Compta_RO (lecture seule).
  3. On met les groupes globaux dans les groupes de domaine local : GG_Comptabilite dans DL_Compta_RW, GG_Direction dans DL_Compta_RO.
  4. On donne les permissions au groupe de domaine local, et à lui seul.

Pourquoi ce détour ? Parce que les choses changent :

  • une nouvelle comptable arrive : on l’ajoute à GG_Comptabilite, rien d’autre ;
  • la direction doit lire un nouveau dossier : on crée DL_NouveauDossier_RO, on y met GG_Direction ;
  • un auditeur demande « qui peut modifier la compta ? » : on lit le contenu de DL_Compta_RW.

Donner des droits directement à des utilisateurs fonctionne le premier jour, puis devient ingérable : personne ne sait plus pourquoi Paul a accès au dossier RH.

Conventions de nommage d’Hexalog

Élément Convention Exemple
Utilisateur p.nom (initiale du prénom, point, nom, sans accent) a.martin
Compte d’administration adm.pnom adm.nfournier
Groupe global GG_Service GG_Exploitation
Groupe de domaine local DL_Ressource_Niveau (RW = lecture-écriture, RO = lecture seule) DL_RH_RW

Les groupes intégrés

Active Directory crée des groupes par défaut, dont certains très puissants : Admins du domaine (Domain Admins), Administrateurs de l’entreprise, Administrateurs du schéma, Opérateurs de compte, Opérateurs de sauvegarde. Leur appartenance doit être réduite au strict minimum et surveillée (séance 13). Utilisateurs du domaine contient automatiquement tous les comptes.

Les noms de ces groupes dépendent de la langue d’installation. Dans un script, on peut les désigner par leur SID, qui ne change pas : le groupe Admins du domaine a toujours un SID qui se termine par -512.

5. Le contrôle d’accès basé sur les rôles (RBAC)

Le RBAC (Role-Based Access Control) consiste à attribuer les droits à des rôles, et les rôles à des personnes, jamais les droits directement aux personnes. Dans Active Directory, le rôle est un groupe global, la permission est portée par un groupe de domaine local : AGDLP est une mise en œuvre du RBAC.

Les bénéfices :

  • arrivée d’un salarié : on lui donne son rôle, il a tous ses accès, pas plus ;
  • mobilité : on change son rôle, ses anciens accès disparaissent ;
  • départ : on désactive le compte ;
  • audit : on peut répondre à « qui a accès à quoi, et pourquoi ».

Le RBAC va avec le principe du moindre privilège : chacun reçoit uniquement les droits nécessaires à son travail. Même l’administrateur utilise un compte normal pour son travail courant et un compte d’administration séparé (adm.nfournier) pour les tâches d’administration.

6. La politique de mots de passe du domaine

La Default Domain Policy (stratégie de domaine par défaut) fixe pour tous les comptes du domaine :

Paramètre Signification
Longueur minimale nombre minimal de caractères
Complexité au moins trois catégories parmi majuscules, minuscules, chiffres, symboles, et pas le nom du compte
Durée de vie maximale au-delà, changement obligatoire
Historique nombre d’anciens mots de passe interdits
Seuil de verrouillage nombre d’échecs avant verrouillage du compte
Durée de verrouillage temps pendant lequel le compte reste verrouillé
Machine : SRV-WIN-01
Get-ADDefaultDomainPasswordPolicy

Des politiques plus strictes pour certains groupes (les administrateurs, par exemple) sont possibles avec les stratégies de mot de passe affinées (FGPP). C’est l’objet de la séance 11.

Les commandes PowerShell essentielles :

Machine : SRV-WIN-01
New-ADOrganizationalUnit -Name "Comptabilite" -Path "OU=Utilisateurs,OU=HEXALOG,DC=hexalog,DC=lan"
New-ADGroup -Name "GG_Comptabilite" -GroupScope Global -GroupCategory Security -Path "OU=Globaux,OU=Groupes,OU=HEXALOG,DC=hexalog,DC=lan"
New-ADUser -Name "Alice Martin" -GivenName Alice -Surname Martin -SamAccountName a.martin `
    -UserPrincipalName a.martin@hexalog.lan -Department Comptabilite `
    -Path "OU=Comptabilite,OU=Utilisateurs,OU=HEXALOG,DC=hexalog,DC=lan" `
    -AccountPassword (Read-Host -AsSecureString "Mot de passe") -Enabled $true
Add-ADGroupMember -Identity GG_Comptabilite -Members a.martin
Get-ADGroupMember GG_Comptabilite                       # qui est dans le groupe ?
Get-ADPrincipalGroupMembership a.martin                 # dans quels groupes est a.martin ?
Get-ADUser -Filter * -SearchBase "OU=Utilisateurs,OU=HEXALOG,DC=hexalog,DC=lan" | Measure-Object

Le caractère ` (accent grave) en fin de ligne permet de couper une longue commande PowerShell sur plusieurs lignes.

8. Installer un domaine

Avant de promouvoir un serveur en contrôleur de domaine :

  • son nom est définitif (le renommer ensuite est délicat) ;
  • son adresse IP est fixe ;
  • son heure est correcte ;
  • le mot de passe de l’Administrateur local est robuste : il devient celui de l’administrateur du domaine.

La promotion installe l’annuaire et le serveur DNS, crée la zone hexalog.lan avec les enregistrements SRV, puis redémarre. Le serveur utilise ensuite lui-même comme DNS (127.0.0.1) et transfère les requêtes externes à un redirecteur.

Choisir le nom du domaine

En production, on utilise un sous-domaine d’un nom public que l’entreprise possède (ad.hexalog.fr). On évite .local, réservé à un autre protocole. Dans le lab, hexalog.lan suffit.

Pour qu’un ordinateur rejoigne le domaine, son DNS doit être le contrôleur de domaine. Sinon il ne le trouve pas : c’est la cause numéro un des échecs de jonction.

9. À retenir

Points clés

  • Un annuaire = une identité unique par personne, des droits gérés centralement.
  • AD DS repose sur LDAP, Kerberos et DNS. Au moins deux contrôleurs de domaine en production. L’heure doit être synchronisée.
  • OU : organiser, déléguer, appliquer des GPO. Groupes : donner des droits.
  • AGDLP : comptes → groupes globaux (rôles) → groupes de domaine local (accès à une ressource) → permissions.
  • RBAC et moindre privilège : des droits par rôle, un compte d’administration séparé.
  • Un poste ne peut rejoindre le domaine que si son DNS est le contrôleur de domaine.

Voir la correction
  1. Groupe de travail : comptes locaux sur chaque machine. Domaine : comptes centralisés dans un annuaire, une identité unique.
  2. LDAP, Kerberos, DNS.
  3. L’authentification Kerberos échoue (tolérance de 5 minutes) : l’utilisateur ne peut pas ouvrir de session.
  4. Utilisateur Julien Moreau, dans l’OU Exploitation, dans l’OU Utilisateurs, dans l’OU HEXALOG, du domaine hexalog.lan.
  5. Non : les OU organisent, ce sont les groupes qui donnent les droits.
  6. Le groupe de domaine local reçoit les permissions ; le groupe global contient les utilisateurs.
  7. On crée son compte dans l’OU RH et on l’ajoute au groupe global GG_RH. Rien d’autre.
  8. Moindre privilège : le compte courant (messagerie, navigation) n’a pas de droits d’administration ; s’il est compromis, le domaine ne l’est pas.
  9. Le nom dépend de la langue d’installation (Admins du domaine / Domain Admins), le SID (terminé par -512) ne change pas.
  10. Que son serveur DNS est le contrôleur de domaine.
