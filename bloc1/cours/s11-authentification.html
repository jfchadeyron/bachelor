Cours de la séance 11

Authentification : AD, LDAP, SSO, MFA et politiques

Prouver qui l'on est, puis obtenir les bons droits : cette séance clarifie le vocabulaire (identification, authentification, autorisation), les facteurs et l'authentification multifacteur, le fonctionnement des annuaires LDAP et de Kerberos, l'authentification unique (SSO), et la façon de fixer des politiques de mots de passe et de verrouillage sous Windows et Linux.

Objectifs de la séance

  • Distinguer identification, authentification, autorisation et traçabilité.
  • Classer les facteurs d’authentification et évaluer les méthodes MFA.
  • Expliquer le rôle de LDAP, de Kerberos et du SSO, sans entrer dans leurs détails avancés.
  • Connaître les attaques courantes sur les mots de passe et les parades.
  • Mettre en place une politique de mots de passe et de verrouillage sous Windows (GPO, stratégie affinée) et sous Linux (chage, PAM).
  • Choisir et justifier des mécanismes d’authentification pour un cas d’entreprise.

1. Quatre notions à ne pas confondre

Notion Question Exemple
Identification qui prétendez-vous être ? saisir l’identifiant a.martin
Authentification prouvez-le mot de passe, clé SSH, code reçu sur le téléphone
Autorisation qu’avez-vous le droit de faire ? Alice peut modifier le dossier Comptabilite, pas le dossier RH
Traçabilité qu’avez-vous fait, et quand ? journal : Alice s’est connectée à 8 h 02 depuis CLI-WIN-01

On parle parfois d’AAA : Authentication, Authorization, Accounting. Une authentification réussie ne donne aucun droit par elle-même : les droits viennent de l’autorisation (groupes, ACL, sudoers).

2. Les facteurs d’authentification

Catégorie Principe Exemples
Ce que je sais un secret mot de passe, code PIN, phrase de passe
Ce que je possède un objet téléphone (application, SMS), clé de sécurité FIDO2, carte à puce, clé SSH sur le poste
Ce que je suis une caractéristique physique empreinte digitale, visage

L’authentification multifacteur (MFA) combine au moins deux catégories différentes. Un mot de passe et un code PIN, ce sont deux secrets de la même catégorie : ce n’est pas du MFA.

Méthode de second facteur Niveau Remarques
Code par SMS faible détournement de ligne (SIM swapping), interception
Code temporaire à 6 chiffres (TOTP) dans une application correct fonctionne hors ligne ; le code peut être hameçonné s’il est saisi sur un faux site
Notification à valider sur le téléphone correct attaque par saturation (l’utilisateur finit par accepter) : exiger la saisie d’un nombre affiché
Clé FIDO2, passkey, carte à puce fort résiste à l’hameçonnage : la clé vérifie l’adresse du site

Où l’exiger en priorité : accès à distance (VPN, bureau à distance), messagerie et applications cloud, comptes d’administration, consoles cloud.

3. Les mots de passe

Comment ils sont attaqués

  • Force brute et dictionnaire : essayer des combinaisons ou des mots de passe courants.
  • Pulvérisation (password spraying) : essayer un mot de passe courant (Hexalog123!) sur tous les comptes, pour ne pas déclencher le verrouillage.
  • Réutilisation (credential stuffing) : réutiliser des identifiants volés sur un autre site.
  • Hameçonnage : faire saisir le mot de passe sur une fausse page.
  • Vol de la base puis cassage des empreintes hors ligne.

Comment ils sont stockés

Jamais en clair : on stocke une empreinte (hachage), avec un sel aléatoire pour que deux mots de passe identiques n’aient pas la même empreinte, et un algorithme volontairement lent (yescrypt sous Debian, bcrypt, Argon2) pour ralentir le cassage. Windows stocke une empreinte NT (sans sel), d’où l’importance de protéger les contrôleurs de domaine.

Une bonne politique

Les recommandations actuelles (ANSSI, CNIL, NIST) convergent :

  • privilégier la longueur : au moins 12 caractères de plusieurs types, ou une phrase de passe plus longue ;
  • interdire les mots de passe connus ou compromis (listes noires) ;
  • ne pas imposer de changement périodique aux utilisateurs sans raison, mais changer immédiatement en cas de soupçon de compromission ;
  • limiter le nombre d’essais (verrouillage ou ralentissement) ;
  • encourager un gestionnaire de mots de passe et un mot de passe différent par service ;
  • ajouter le MFA partout où c’est possible, et imposer des règles plus fortes aux comptes d’administration.

Le verrouillage a un revers

Un seuil trop bas (3 essais, verrouillage long) permet à un attaquant de bloquer tous les comptes exprès, en tapant de faux mots de passe. On règle le seuil (5 à 10 essais), la durée et la fenêtre d’observation, et on surveille les verrouillages.

4. Annuaires et protocoles d’authentification

LDAP

LDAP (Lightweight Directory Access Protocol) est le protocole standard pour interroger et modifier un annuaire : chercher un utilisateur, lire ses attributs, lister les membres d’un groupe. Il utilise le port 389 (ou 636 pour LDAPS, chiffré par TLS). Active Directory parle LDAP ; sous Linux, l’annuaire libre de référence est OpenLDAP.

Un client LDAP se connecte (bind) avec un compte, puis fait des recherches : « à partir de OU=Utilisateurs,OU=HEXALOG,DC=hexalog,DC=local, donne-moi les objets dont department=Comptabilite ». De nombreuses applications (GLPI, Nextcloud, équipements réseau) s’appuient sur l’annuaire de l’entreprise par LDAP pour vérifier les comptes.

Kerberos

Dans un domaine Active Directory, l’ouverture de session utilise Kerberos, un protocole à tickets, sur le port 88. Le principe :

  • Le mot de passe n’est jamais envoyé sur le réseau.
  • Le TGT évite de redemander le mot de passe à chaque accès : c’est l’authentification unique à l’intérieur du domaine.
  • Les tickets sont horodatés : d’où l’exigence d’une heure synchronisée (5 minutes de tolérance).
  • L’ancien protocole NTLM existe encore pour la compatibilité ; il est moins sûr et Microsoft prévoit de l’abandonner.

Analogie : le bracelet de festival

À l’entrée du festival, vous montrez votre billet et votre pièce d’identité une fois : on vous pose un bracelet (le TGT). Ensuite, à chaque scène, vous montrez le bracelet et on vous donne un jeton pour cette scène (le ticket de service). Personne ne vous redemande votre pièce d’identité.

L’authentification unique (SSO)

Le SSO (Single Sign-On) permet de s’authentifier une fois et d’accéder ensuite à de nombreuses applications. Deux familles :

  • dans le domaine : Kerberos, pour les ressources Windows et les applications intégrées à AD ;
  • pour les applications web et cloud : un fournisseur d’identité (IdP : Microsoft Entra ID, Okta, Keycloak…) authentifie l’utilisateur et remet à l’application un jeton signé, avec les protocoles SAML 2.0 ou OpenID Connect.

Avantages : moins de mots de passe, MFA appliqué à un seul endroit, désactivation centralisée au départ d’un salarié. Risque : le fournisseur d’identité devient un point critique, qu’il faut protéger au maximum.

Dans une infrastructure hybride, les comptes de l’AD local sont souvent synchronisés vers Microsoft Entra ID (outil Entra Connect), pour que les salariés utilisent la même identité sur site et dans Microsoft 365.

5. Politiques sous Windows

La stratégie de domaine

Les règles de mot de passe et de verrouillage de tous les comptes du domaine se règlent dans la Default Domain Policy, une stratégie de groupe (GPO) liée au domaine :

gpmc.msc → Forêt → Domaines → hexalog.local → Default Domain Policy → Modifier → Configuration ordinateur → Stratégies → Paramètres Windows → Paramètres de sécurité → Stratégies de comptes → Stratégie de mot de passe / Stratégie de verrouillage du compte.

Paramètre Exemple Hexalog (utilisateurs)
Longueur minimale 12
Complexité activée
Historique 12 mots de passe
Durée de vie maximale 365 jours
Durée de vie minimale 1 jour (empêche de repasser tout de suite à l’ancien)
Seuil de verrouillage 5 tentatives
Durée de verrouillage / réinitialisation du compteur 15 minutes

Les stratégies de mot de passe affinées

Pour appliquer des règles plus strictes à un groupe (les administrateurs), on crée une stratégie de mot de passe affinée (FGPP, objet PSO). Elle s’applique à des utilisateurs ou des groupes globaux ; si plusieurs s’appliquent, la priorité (Precedence) la plus faible gagne.

On la crée dans le Centre d’administration Active Directory : hexalog (local) → System → Password Settings Container → Nouveau → Paramètres de mot de passe, puis on indique à quel groupe elle s’applique (S’applique directement à). Pour savoir quelle stratégie s’applique à un compte : clic droit sur le compte → Afficher les paramètres de mot de passe résultants.

Gérer les comptes verrouillés

Tout se fait dans Utilisateurs et ordinateurs Active Directory :

Besoin Où
le compte est-il verrouillé ? le déverrouiller propriétés du compte → onglet Compte → case Déverrouiller le compte
réinitialiser le mot de passe clic droit sur le compte → Réinitialiser le mot de passe ; cocher L’utilisateur doit changer le mot de passe à la prochaine ouverture de session pour un mot de passe temporaire
désactiver ou réactiver clic droit → Désactiver le compte / Activer le compte
d’où viennent les échecs ? Observateur d’événements du contrôleur → journal Sécurité → filtrer sur l’ID 4740

Événements du journal Sécurité du contrôleur de domaine : 4625 (échec d’ouverture de session), 4771 (échec de pré-authentification Kerberos), 4776 (validation NTLM), 4740 (compte verrouillé, avec le nom de l’ordinateur d’où viennent les échecs), 4767 (compte déverrouillé), 4724 (mot de passe réinitialisé).

6. Politiques sous Linux

Expiration

  • /etc/login.defs : valeurs par défaut pour les nouveaux comptes (PASS_MAX_DAYS, PASS_MIN_DAYS, PASS_WARN_AGE).
  • chage : règles d’un compte existant.
ExempleMachine : SRV-LNX-01à lire, pas à taper
sudo chage -l amartin                      # état
sudo chage -M 365 -m 1 -W 14 amartin       # max 365 j, min 1 j, avertissement 14 j avant
sudo passwd -e amartin                     # expire tout de suite : changement obligatoire à la prochaine connexion

PAM

PAM (Pluggable Authentication Modules) est la chaîne de modules que traversent toutes les authentifications Linux (console, su, sudo, SSH par mot de passe). Chaque programme a son fichier dans /etc/pam.d/, qui inclut les fichiers communs de Debian (common-auth, common-password…). Les modules sont regroupés en quatre étapes :

Étape Rôle Exemples de modules
auth vérifier l’identité pam_unix (mot de passe local), pam_faillock (verrouillage), pam_sss (annuaire)
account le compte est-il autorisé maintenant ? expiration, horaires
password changement de mot de passe pam_pwquality (qualité)
session ouverture de session création du dossier personnel, limites

La qualité des mots de passe se règle avec pam_pwquality (/etc/security/pwquality.conf), le verrouillage après échecs avec pam_faillock (/etc/security/faillock.conf et la commande faillock).

PAM est sensible

Une erreur dans /etc/pam.d/ peut empêcher toute authentification, y compris sudo. On modifie PAM avec un snapshot, une session root ouverte à côté, et on teste dans une autre session avant de fermer.

7. Procédures d’exploitation

Une politique ne vaut que par les procédures qui l’accompagnent :

  • Déverrouillage et réinitialisation par le support : vérifier l’identité du demandeur (rappel sur son numéro connu, question au responsable) avant toute action ; mot de passe temporaire à usage unique et changement obligatoire.
  • Compte suspect (connexions inhabituelles, verrouillages répétés) : désactiver, réinitialiser, révoquer les sessions et les clés, analyser les journaux.
  • Comptes d’administration : nominatifs, séparés des comptes courants, MFA, politique renforcée, usage tracé.

8. À retenir

Points clés

  • Identification ≠ authentification ≠ autorisation ≠ traçabilité.
  • MFA = deux catégories différentes (savoir, posséder, être). FIDO2 résiste à l’hameçonnage, le SMS est le plus faible.
  • Longueur plutôt que complexité, listes noires, pas de changement périodique sans raison, verrouillage raisonnable, MFA.
  • LDAP interroge l’annuaire (389/636) ; Kerberos authentifie par tickets (88), exige une heure juste ; SSO = une authentification, plusieurs applications (Kerberos, SAML, OpenID Connect).
  • Windows : Default Domain Policy (GPO) pour tous, FGPP pour un groupe ; 4625, 4740, 4767.
  • Linux : chage, PAM (pam_pwquality, pam_faillock), prudence avec /etc/pam.d/.
