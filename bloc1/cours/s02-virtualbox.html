VirtualBox : snapshots, clones et modes réseau

Maîtriser l'outil de travail du bloc : régler une VM, protéger son travail avec des snapshots, fabriquer des serveurs en série avec des clones, tenir un inventaire, et surtout choisir le bon mode réseau selon ce qu'on veut autoriser.

1. Les réglages d’une VM

Dans Configuration, chaque rubrique correspond à un composant de la machine virtuelle :

Rubrique Ce qu’on y règle Conseil pour le lab
Général nom, type de système, description, presse-papiers partagé mettre le rôle de la VM dans la description
Système RAM, ordre d’amorçage, EFI, nombre de vCPU ne jamais dépasser la moitié de la RAM du PC pour l’ensemble des VM allumées
Affichage mémoire vidéo, contrôleur graphique valeurs par défaut
Stockage contrôleurs (SATA, NVMe), disques, lecteur optique un disque système, parfois un disque de données séparé
Réseau jusqu’à 4 cartes : mode d’accès, type de carte, adresse MAC, câble branché voir la partie 5
Dossiers partagés partage de dossiers entre hôte et VM nécessite les Additions invité ; non utilisé ici

Dimensionnement retenu pour le lab :

VM vCPU RAM Disque
Serveur Debian sans interface graphique 1 1 Go 20 Go dynamique
Windows Server avec interface graphique 2 4 Go (3 Go si le PC a 8 Go) 50 Go dynamique
Poste Windows 11 (optionnel) 2 4 Go 64 Go dynamique

La RAM est la ressource la plus limitée

Un PC de 16 Go peut faire tourner Windows (hôte) + un Windows Server + deux ou trois Debian. Au-delà, le PC se met à utiliser son disque comme mémoire (swap) et tout devient très lent. N’allumez que les VM nécessaires au TP du jour.

2. Les snapshots

Fonctionnement

Quand vous prenez un snapshot, VirtualBox fige le disque virtuel : il devient en lecture seule. Toutes les écritures suivantes partent dans un nouveau fichier, un disque différentiel, qui ne contient que les blocs modifiés. Si la VM était allumée, l’état de la mémoire est enregistré aussi.

  • Restaurer un snapshot : la VM revient exactement à l’état photographié. Tout ce qui a été fait depuis est perdu (VirtualBox propose d’abord de prendre un snapshot de l’état actuel).
  • Supprimer un snapshot : ne supprime pas le travail, VirtualBox fusionne le différentiel avec son parent. L’opération peut être longue.
  • On peut créer une arborescence : revenir à un ancien snapshot puis partir dans une autre direction.

Bonnes pratiques

  • Un snapshot avant chaque opération risquée : modification de la configuration SSH, du pare-feu, promotion d’un contrôleur de domaine, mise à jour majeure.
  • Des noms numérotés et explicites (03-ip-fixe, 06-avant-promotion-ad) avec une description.
  • Pas trop de snapshots en chaîne : chaque niveau ajoute un fichier à lire et ralentit les accès disque.

Snapshot n’est pas sauvegarde

Snapshot Sauvegarde
Emplacement à côté du disque de la VM sur un autre support (disque externe, NAS, cloud)
Si le disque du PC meurt perdu avec la VM toujours disponible
Autonome non, dépend du disque de base oui
Usage retour arrière rapide après une erreur reprise après sinistre, perte, vol

Pour sauvegarder une VM VirtualBox : l’exporter au format OVA (Open Virtualization Appliance, un fichier unique, importable dans d’autres hyperviseurs) ou copier son dossier VM éteinte, sur un autre support.

3. Les clones

Un clone est une copie d’une VM. C’est la façon la plus rapide de créer plusieurs serveurs identiques à partir d’un modèle installé une fois.

Clone intégral Clone lié
Disque copie complète et indépendante disque différentiel qui s’appuie sur un snapshot du modèle
Espace utilisé autant que l’original très faible au départ
Création quelques minutes quelques secondes
Dépendance aucune le modèle et son snapshot ne doivent jamais être supprimés
Usage serveur durable VM de test, poste client

Ce qu’un clone copie en trop

Un clone est une copie exacte. Certaines informations devraient pourtant être uniques sur un réseau :

Élément dupliqué Problème Correction
Adresse MAC deux cartes identiques sur le même réseau : conflits option « Générer de nouvelles adresses MAC » au clonage
Nom d’hôte deux machines portent le même nom hostnamectl set-hostname
Identifiant de machine (/etc/machine-id) le DHCP peut donner la même IP aux deux clones, journaux mélangés régénérer le fichier
Clés d’hôte SSH tous les clones ont la même identité SSH : on ne peut plus les distinguer, et c’est une faiblesse de sécurité régénérer les clés
Identifiant de sécurité Windows (SID machine) problèmes avec Active Directory généraliser avec Sysprep avant de cloner

Cette opération s’appelle généraliser un clone. Vous utiliserez un petit script pour la faire sous Linux dans le TP.

4. Nommer et inventorier

Dans une entreprise, un serveur mal nommé ou absent de l’inventaire est un serveur que personne ne maintient. Le lab applique une convention simple : TYPE-SYSTÈME-NUMÉRO.

Préfixe Signification Exemples
SRV serveur SRV-WIN-01, SRV-LNX-01
CLI poste client CLI-LNX-01, CLI-WIN-01
BST bastion d’administration BST-LNX-01
TPL modèle, jamais utilisé directement TPL-DEB13

Sous Linux, le nom d’hôte s’écrit en minuscules (srv-lnx-01). Windows l’affiche en majuscules.

L’inventaire recense pour chaque machine : nom, système et version, rôle, ressources, réseau et adresse IP, comptes d’administration, snapshots importants, date de dernière mise à jour. Un modèle est fourni sur la page Modèles de livrables.

5. Les modes réseau de VirtualBox

Chaque carte réseau d’une VM est « branchée » sur un type de réseau virtuel. C’est le réglage Mode d’accès réseau (Attached to).

NAT

C’est le mode par défaut. Chaque VM a son propre petit routeur NAT privé, comme si chacune avait sa box.

  • La VM reçoit toujours 10.0.2.15, sa passerelle est 10.0.2.2 et son DNS 10.0.2.3.
  • Elle sort sur Internet par la connexion de l’hôte (au lycée : une fois le PC identifié sur le portail du pare-feu).
  • Elle ne voit pas les autres VM, même si elles sont aussi en NAT (elles ont toutes 10.0.2.15, chacune dans sa bulle).
  • On ne peut la joindre que par une redirection de ports configurée sur sa carte.

Réseau NAT

Un routeur NAT partagé entre plusieurs VM, sur un réseau que vous définissez (par exemple 10.10.10.0/24).

  • Les VM du même réseau NAT se voient entre elles.
  • Elles sortent sur Internet par l’hôte.
  • Un serveur DHCP intégré peut distribuer les adresses (désactivable).
  • L’accès depuis l’hôte se fait par des redirections de ports définies sur le réseau.

C’est le mode retenu pour le lab : LAB-HEXALOG, 10.10.10.0/24, passerelle 10.10.10.1.

Accès par pont (Bridged)

La carte virtuelle est « soudée » à la carte physique de l’hôte : la VM apparaît sur le réseau physique comme une machine de plus. Elle reçoit une adresse du DHCP de l’établissement ou de la box, et tout le monde sur ce réseau peut la joindre.

Au lycée : pas d'Internet en ligne de commande en mode pont

Au lycée, l’accès à Internet passe par un pare-feu FortiGate qui demande de s’identifier sur une page web (identifiant et mot de passe) : c’est un portail captif. Votre PC s’identifie dans son navigateur.

  • En NAT et en Réseau NAT, le trafic de la VM sort avec l’adresse de votre PC, déjà identifié : Internet fonctionne.
  • En pont, la VM a sa propre adresse sur le réseau du lycée. Pour le pare-feu, c’est une nouvelle machine qui doit s’identifier à son tour. Une VM serveur, sans interface graphique, n’a pas de navigateur pour le faire : apt et curl n’atteignent pas Internet.

C’est l’une des raisons pour lesquelles le lab utilise le Réseau NAT.

En pont, la VM est aussi exposée à tout le réseau du lycée, et un service mal configuré peut perturber les autres postes. On ne lance jamais de serveur DHCP sur une carte en pont.

Réseau interne

Un réseau fermé entre les VM qui portent le même nom de réseau interne. Ni l’hôte ni Internet n’y ont accès, et il n’y a pas de DHCP par défaut. Idéal pour simuler un réseau isolé (un réseau de production derrière un pare-feu, par exemple).

Réseau privé hôte (Host-only)

Un réseau entre les VM et l’hôte, sans accès à Internet. VirtualBox crée sur l’hôte une carte réseau virtuelle (souvent 192.168.56.1) et peut fournir un DHCP.

Récapitulatif

Mode VM → hôte Hôte → VM VM ↔︎ VM VM → Internet Réseau physique → VM
NAT oui redirection de ports non oui redirection de ports
Réseau NAT oui redirection de ports oui oui redirection de ports
Accès par pont oui oui oui oui (au lycée : non, portail captif) oui
Réseau interne non non oui non non
Réseau privé hôte oui oui oui non non

Les autres réglages d’une carte

  • Type de carte : Intel PRO/1000 par défaut, reconnue par tous les systèmes. Le type virtio-net est plus performant mais demande des pilotes sous Windows.
  • Adresse MAC : identifiant de la carte, doit être unique sur un même réseau.
  • Câble branché : décocher revient à débrancher le câble, pratique pour simuler une panne.
  • Sous Debian, la carte 1 s’appelle en général enp0s3, la carte 2 enp0s8.

6. À retenir

Points clés

  • Un snapshot fige le disque et redirige les écritures vers un différentiel ; restaurer fait perdre ce qui a été fait après.
  • Un snapshot n’est pas une sauvegarde : il disparaît avec le disque de la VM.
  • Un clone lié est rapide et léger mais dépend du modèle ; un clone intégral est autonome.
  • Un clone doit être généralisé : MAC, nom, machine-id, clés SSH (Sysprep sous Windows).
  • NAT : chaque VM isolée. Réseau NAT : les VM se voient et sortent sur Internet. Pont : la VM est sur le réseau physique ; au lycée, le portail captif la prive d’Internet. Interne : VM entre elles seulement. Privé hôte : VM et hôte, sans Internet.

Voir la correction
  1. Ils sont perdus : la VM revient exactement à l’état du snapshot.
  2. Le snapshot est stocké à côté du disque de la VM, sur le même support. Si ce support meurt, tout disparaît.
  3. Les clones liés ne démarrent plus : leur disque s’appuie sur celui du modèle. Les clones intégraux ne sont pas touchés.
  4. Le /etc/machine-id (et l’identifiant DHCP qui en découle) a été copié à l’identique : il faut généraliser les clones.
  5. Ce n’est pas un conflit : chaque VM NAT est dans sa propre bulle. Mais elles ne peuvent pas communiquer.
  6. Le Réseau NAT.
  7. Le Réseau interne.
  8. En pont, la VM a sa propre adresse sur le réseau du lycée : le pare-feu FortiGate la traite comme une nouvelle machine et attend qu’elle s’identifie sur sa page web, ce qu’une VM sans navigateur ne peut pas faire. En NAT, son trafic sort avec l’adresse du PC, déjà identifié dans le navigateur.
