Linux : distributions et administration de base

Panorama des distributions Linux utilisées en entreprise, puis les gestes d'administration de tous les jours : l'arborescence, les paquets, les services avec systemd, les journaux avec journalctl, le réseau et le stockage. Chaque notion est mise en parallèle avec ce que vous avez vu sous Windows Server.

1. Noyau et distributions

Linux est, au sens strict, un noyau : le cœur du système qui gère le processeur, la mémoire, les disques et le réseau. Il est libre (licence GPL) et développé depuis 1991 par une large communauté.

Une distribution assemble ce noyau avec des milliers de logiciels (outils GNU, gestionnaire de services, serveur web, bibliothèques…), un gestionnaire de paquets, un installateur, une politique de mises à jour et, parfois, un support commercial. Choisir un Linux, c’est choisir une distribution.

Linux fait tourner la très grande majorité des serveurs web, du cloud public, des conteneurs et des équipements réseau. En entreprise, on le trouve partout où il faut de la stabilité, de l’automatisation et peu de coûts de licence.

Les grandes familles

Famille Distributions Paquets Remarques
Debian Debian, Ubuntu (Server, LTS), Linux Mint .deb, apt Debian : communautaire, très stable. Ubuntu : éditeur Canonical, support commercial possible
Red Hat RHEL, Rocky Linux, AlmaLinux, Oracle Linux, CentOS Stream, Fedora .rpm, dnf RHEL : support commercial, référence des grands comptes ; Rocky et Alma : reconstructions gratuites compatibles ; Fedora : laboratoire des nouveautés
SUSE SLES, openSUSE Leap, openSUSE Tumbleweed .rpm, zypper présent dans l’industrie et l’informatique de gestion (SAP)
Indépendantes Arch Linux, Alpine Linux, Gentoo pacman, apk… Arch : rolling release ; Alpine : très légère, courante dans les conteneurs

Les modèles de publication

  • Version fixe (Debian, RHEL, Ubuntu LTS) : une version majeure tous les 2 à 3 ans, puis uniquement des correctifs pendant toute sa durée de vie. On sait ce qu’on a, rien ne change sans qu’on le décide. C’est ce que veut un serveur.
  • LTS (Long Term Support) : version fixe avec un support long (5 ans et plus chez Ubuntu, 10 ans chez Red Hat).
  • Rolling release (Arch, openSUSE Tumbleweed) : pas de version, le système est mis à jour en continu vers les dernières versions des logiciels. Idéal pour un poste de passionné, risqué pour un serveur.

Critères de choix en entreprise

  1. Support : qui appelle-t-on en cas de problème ? (éditeur, prestataire, communauté)
  2. Durée de vie : combien d’années de correctifs de sécurité ?
  3. Compatibilité : le logiciel métier est-il certifié pour cette distribution ?
  4. Compétences de l’équipe et homogénéité du parc.
  5. Coût : abonnement de support ou gratuité.
  6. Écosystème : images cloud, documentation, outils d’automatisation.

2. L’arborescence Linux

Sous Linux, il n’y a pas de lettres de lecteur : tout part de la racine /, et les disques sont « montés » dans des dossiers.

Dossier Contenu Équivalent Windows approché
/etc fichiers de configuration du système et des services le registre, C:\ProgramData
/var données qui varient : journaux (/var/log), sites web (/var/www), files d’attente
/home dossiers personnels des utilisateurs C:\Users
/root dossier personnel de l’administrateur root
/usr programmes et bibliothèques (/usr/bin, /usr/sbin, /usr/lib) C:\Program Files, C:\Windows
/srv données servies par la machine (partages, sites) C:\Partages
/tmp fichiers temporaires (en mémoire sous Debian 13) %TEMP%
/opt logiciels tiers installés hors paquets
/dev périphériques (/dev/sda = premier disque)
/proc, /sys fichiers virtuels exposant l’état du noyau
/boot noyau et chargeur de démarrage

Sous Linux, tout est fichier : la configuration est du texte qu’on lit avec cat ou less et qu’on modifie avec nano ou vim. D’où l’importance de faire une copie (sudo cp fichier fichier.bak) avant chaque modification.

Rappels de ligne de commande

Besoin Commande
où suis-je, lister, se déplacer pwd, ls -l, cd
lire un fichier cat, less, head -n 20, tail -n 20, tail -f (suivre)
chercher du texte, un fichier grep -i motif fichier, find /etc -name "*.conf"
copier, déplacer, supprimer cp, mv, rm, mkdir -p, rmdir
enchaîner et rediriger commande1 | commande2, > fichier (écrase), >> fichier (ajoute), 2> (erreurs)
aide man commande, commande --help
agir en administrateur sudo commande

3. Les paquets

Un paquet est une archive qui contient un logiciel, ses fichiers de configuration, et la liste de ses dépendances (les autres paquets dont il a besoin). Les paquets sont téléchargés depuis des dépôts : des serveurs de la distribution qui publient les logiciels et leurs mises à jour, signés pour garantir leur authenticité.

Action Debian, Ubuntu RHEL, Rocky, Alma
mettre à jour la liste des paquets sudo apt update (automatique)
installer les mises à jour sudo apt upgrade / sudo apt full-upgrade sudo dnf upgrade
installer sudo apt install nginx sudo dnf install nginx
supprimer (garder la config) sudo apt remove nginx sudo dnf remove nginx
supprimer avec la config sudo apt purge nginx
rechercher, informations apt search, apt show dnf search, dnf info
paquets installés apt list --installed, dpkg -l dnf list installed, rpm -qa
fichiers d’un paquet dpkg -L nginx rpm -ql nginx
historique /var/log/apt/history.log dnf history

Sous Debian 13, les dépôts sont déclarés dans /etc/apt/sources.list.d/debian.sources. Le paquet unattended-upgrades permet d’installer automatiquement les mises à jour de sécurité.

4. Les services avec systemd

systemd est le premier programme lancé au démarrage (PID 1). Il démarre et surveille tous les services, appelés unités (units) : nginx.service, ssh.service…

Action Commande
état détaillé (actif ? erreurs récentes ?) systemctl status nginx
démarrer, arrêter, redémarrer sudo systemctl start / stop / restart nginx
recharger la configuration sans couper sudo systemctl reload nginx
lancer au démarrage de la machine, ou non sudo systemctl enable / disable nginx
les deux d’un coup sudo systemctl enable --now nginx
est-il actif ? activé ? systemctl is-active nginx, systemctl is-enabled nginx
services démarrés, services en échec systemctl list-units --type=service --state=running, systemctl --failed
lire le fichier d’unité systemctl cat nginx
interdire tout démarrage sudo systemctl mask / unmask

Correspondance avec Windows : enable = type de démarrage Automatique, disable = Manuel, mask = Désactivé.

5. Les journaux

Le service journald collecte les messages du noyau et de tous les services. On les lit avec journalctl :

Machine : SRV-LNX-01
journalctl -u nginx                   # journaux d'un service
journalctl -u nginx -n 50 --no-pager  # les 50 dernières lignes, sans pagination
journalctl -u ssh -f                  # suivre en direct (Ctrl+C pour quitter)
journalctl -p err -b                  # erreurs depuis le dernier démarrage
journalctl --since "1 hour ago"       # dernière heure
journalctl -k                         # messages du noyau
journalctl -t sudo                    # messages d'un programme (identifiant)

Certains logiciels écrivent aussi leurs propres fichiers dans /var/log : /var/log/nginx/access.log et error.log, /var/log/apt/history.log, /var/log/dpkg.log.

Debian 13 et /var/log/auth.log

Depuis Debian 12, le service rsyslog n’est plus installé par défaut : les fichiers historiques /var/log/syslog et /var/log/auth.log n’existent pas. Tout est dans le journal de systemd, accessible avec journalctl. Les anciennes commandes last et lastlog ont aussi disparu de Debian 13 (remplacées par wtmpdb et lastlog2).

7. Le stockage

  1. Repérer le disque : lsblk (le deuxième disque est sdb).
  2. Créer une table de partitions et une partition : parted ou fdisk.
  3. Créer un système de fichiers : mkfs.ext4 (Debian) ou mkfs.xfs (RHEL).
  4. Créer un point de montage (mkdir /srv/partages) et monter : mount.
  5. Rendre le montage permanent dans /etc/fstab, en désignant le disque par son UUID (identifiant stable, contrairement à sdb qui peut changer).
  6. Vérifier : df -h, et un redémarrage.
Fichier : /etc/fstab (exemple)
# <périphérique>                           <point de montage>  <type> <options>         <dump> <ordre fsck>
UUID=5d1c7a52-8f0e-4f2b-9d0c-1b2a3c4d5e6f  /srv/partages       ext4   defaults,nofail   0      2

L’option nofail évite que le serveur reste bloqué au démarrage si ce disque de données est absent. Pour des besoins plus souples (agrandir un volume à chaud, regrouper plusieurs disques), on utilise LVM (volumes logiques), vu dans un autre bloc.

8. Méthode de dépannage d’un service

Les erreurs les plus fréquentes : faute de syntaxe dans un fichier de configuration, port déjà utilisé par un autre service, fichier ou dossier inexistant, droits insuffisants, disque plein (df -h).

9. À retenir

Points clés

  • Linux est un noyau ; une distribution l’assemble avec des logiciels, des paquets, un cycle de support.
  • Familles Debian (apt), Red Hat (dnf), SUSE (zypper). Version fixe et LTS pour les serveurs, rolling release à éviter en production.
  • /etc = configuration, /var/log = journaux, /srv = données servies, /home = utilisateurs.
  • apt update puis apt upgrade ; systemctl status/start/enable ; journalctl -u service.
  • Disque : lsblk, partitionner, mkfs, monter, /etc/fstab par UUID avec nofail.
  • Dépannage : status, journal, test de configuration, ports, pare-feu.

Voir la correction
  1. Le noyau gère le matériel ; la distribution l’assemble avec des logiciels, un gestionnaire de paquets et une politique de mises à jour.
  2. RHEL, Rocky Linux, AlmaLinux, Fedora : dnf.
  3. Les logiciels changent en permanence de version : risque de régression et d’incompatibilité, pas de stabilité garantie.
  4. /etc/nginx ; /var/log/nginx (et journalctl -u nginx).
  5. update rafraîchit la liste des paquets disponibles ; upgrade installe les mises à jour.
  6. sudo systemctl enable nginx.
  7. journalctl -p err -b.
  8. rsyslog n’est plus installé par défaut : les journaux sont dans journald (journalctl).
  9. Le nom sdb peut changer (ordre de détection), l’UUID est propre au système de fichiers.
  10. systemctl status nginx, journalctl -u nginx -n 50, sudo nginx -t.
