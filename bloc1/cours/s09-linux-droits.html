Cours de la séance 9

Linux : comptes, permissions, ACL et sudo

Sous Linux, chaque fichier appartient à un utilisateur et à un groupe, avec trois jeux de droits. Cette séance explique comment sont stockés les comptes, comment lire et modifier les permissions, comment faire des dossiers partagés propres avec le bit setgid et les ACL, et comment déléguer des tâches d'administration précises avec sudo.

1. Utilisateurs et groupes

Où sont stockés les comptes

Fichier Contenu Lisible par
/etc/passwd la liste des comptes tout le monde
/etc/shadow les mots de passe hachés et leurs règles d’expiration root seulement
/etc/group les groupes et leurs membres tout le monde

Une ligne de /etc/passwd :

ExempleFichier : /etc/passwdà lire, pas à taper
amartin:x:1002:1002:Alice Martin:/home/amartin:/bin/bash
# identifiant : x (mot de passe dans shadow) : UID : GID du groupe principal : commentaire : dossier personnel : shell
  • UID 0 : root, tous les droits. 1 à 999 : comptes système (services : www-data pour nginx, sshd…). 1000 et plus : utilisateurs.
  • Chaque utilisateur a un groupe principal (souvent un groupe à son nom) et des groupes secondaires qui lui donnent des droits supplémentaires.
  • Un compte de service a souvent le shell /usr/sbin/nologin : il ne peut pas ouvrir de session.
  • Le mot de passe n’est jamais stocké en clair : /etc/shadow contient une empreinte (hachage) calculée avec un algorithme lent (yescrypt sous Debian) et un sel aléatoire.

Les commandes

Action Commande
qui suis-je, mes groupes id, id amartin, groups amartin
infos d’un compte ou d’un groupe getent passwd amartin, getent group compta
créer un utilisateur (Debian, interactif) sudo adduser amartin
créer un utilisateur (toutes distributions) sudo useradd -m -s /bin/bash -c "Alice Martin" amartin
définir un mot de passe sudo passwd amartin
créer un groupe sudo groupadd compta
ajouter à un groupe secondaire sudo usermod -aG compta amartin ou sudo gpasswd -a amartin compta
retirer d’un groupe sudo gpasswd -d amartin compta
verrouiller / déverrouiller sudo usermod -L amartin / sudo usermod -U amartin
expiration du mot de passe sudo chage -l amartin, sudo chage -M 90 amartin
supprimer (avec le dossier personnel) sudo userdel -r amartin

Le piège de usermod -G

usermod -G compta amartin remplace tous les groupes secondaires d’Alice par compta : elle perd les autres (dont sudo si elle l’avait). Il faut toujours -aG (append).

Le dossier /etc/skel contient les fichiers copiés dans chaque nouveau dossier personnel ; /etc/login.defs fixe les valeurs par défaut (plages d’UID, durée de vie des mots de passe, umask).

Comme sous Windows, un changement de groupe ne s’applique qu’à la prochaine ouverture de session de l’utilisateur.

2. Les permissions Unix

Lire ls -l

ExempleMachine : SRV-LNX-01à lire, pas à taper
-rw-r-----  1 amartin compta  2048  bilan.ods
drwxrws---  2 root    compta  4096  compta
│└┬┘└┬┘└┬┘     └──┬──┘ └──┬─┘
│ │  │  │        │       └ groupe propriétaire
│ │  │  │        └ utilisateur propriétaire
│ │  │  └ droits des autres (others)
│ │  └ droits du groupe (group)
│ └ droits du propriétaire (user)
└ type : - fichier, d dossier, l lien symbolique

Ce que signifient r, w, x

Droit Sur un fichier Sur un dossier
r (lecture) lire le contenu lister les noms des fichiers
w (écriture) modifier le contenu créer, renommer, supprimer des fichiers dedans (même ceux des autres !)
x (exécution) exécuter le fichier (programme, script) traverser le dossier (y entrer, accéder à son contenu)

Linux vérifie les droits dans l’ordre : si vous êtes le propriétaire, seuls les droits du propriétaire comptent ; sinon, si vous êtes dans le groupe, seuls ceux du groupe ; sinon, ceux des autres. root n’est pas concerné : il a tous les droits.

Notation octale

Chaque droit vaut un nombre : r = 4, w = 2, x = 1. On additionne pour chaque catégorie.

Octal Symbolique Usage typique
644 rw-r--r-- fichier lisible par tous, modifiable par le propriétaire
640 rw-r----- fichier lisible par le groupe seulement
600 rw------- fichier privé (clé SSH privée)
755 rwxr-xr-x dossier ou programme accessible à tous
750 rwxr-x--- dossier réservé au propriétaire et au groupe
700 rwx------ dossier privé
ExempleMachine : SRV-LNX-01à lire, pas à taper
chmod 640 bilan.ods                  # octal
chmod u+x script.sh                  # symbolique : ajouter x au propriétaire
chmod g-w,o= rapport.txt             # retirer w au groupe, tout retirer aux autres
sudo chown amartin:compta bilan.ods  # changer propriétaire et groupe
sudo chgrp -R compta /srv/partages/compta   # changer le groupe, récursivement

Le umask

Le umask retire des droits aux fichiers et dossiers au moment de leur création. Un fichier est créé au maximum en 666, un dossier en 777, moins le umask.

umask Fichier créé Dossier créé
022 (défaut) 644 755
027 640 750
077 600 700
ExempleMachine : SRV-LNX-01à lire, pas à taper
umask            # afficher (0022)
umask 027        # pour la session en cours

3. Les bits spéciaux

Bit Octal Sur un fichier Sur un dossier Affichage
setuid 4000 le programme s’exécute avec les droits de son propriétaire (ex. passwd s’exécute en root) sans effet rws côté propriétaire
setgid 2000 s’exécute avec les droits du groupe les nouveaux fichiers héritent du groupe du dossier rws côté groupe
sticky 1000 sans effet seul le propriétaire d’un fichier peut le supprimer t côté autres

Le setgid sur un dossier partagé est indispensable : sans lui, un fichier créé par Alice dans /srv/partages/compta appartiendrait à son groupe principal (amartin), et ses collègues de compta n’y auraient pas accès. Le sticky bit est celui de /tmp (drwxrwxrwt) : tout le monde peut y écrire, mais personne ne supprime les fichiers des autres.

ExempleMachine : SRV-LNX-01à lire, pas à taper
sudo chmod 2770 /srv/partages/compta     # rwxrws--- : setgid + groupe en lecture-écriture
sudo chmod 3770 /srv/partages/commun     # setgid + sticky

4. Les ACL POSIX

Les droits Unix ne connaissent qu’un propriétaire et un groupe. Pour donner en plus la lecture à la Direction sur le dossier de la comptabilité, il faut des listes de contrôle d’accès (ACL).

ExempleMachine : SRV-LNX-01à lire, pas à taper
sudo apt install -y acl                                   # outils getfacl et setfacl
sudo setfacl -m g:direction:rx /srv/partages/compta       # ajouter : groupe direction en lecture
getfacl /srv/partages/compta                              # afficher
ls -ld /srv/partages/compta                               # un + apparaît : drwxrws---+
sudo setfacl -x g:direction /srv/partages/compta          # retirer une entrée
sudo setfacl -b /srv/partages/compta                      # retirer toutes les ACL

Les ACL par défaut : l’héritage sous Linux

Une ACL posée avec -m ne concerne que le dossier lui-même. Pour que les fichiers et dossiers créés ensuite reçoivent automatiquement des droits, on pose une ACL par défaut avec -d : c’est l’équivalent de l’héritage NTFS.

ExempleMachine : SRV-LNX-01à lire, pas à taper
sudo setfacl -d -m g::rwx,g:direction:rx,o::--- /srv/partages/compta
getfacl /srv/partages/compta        # lignes "default:..."

Effet utile : quand un dossier a une ACL par défaut, le umask n’est plus appliqué aux nouveaux fichiers, ce sont les droits par défaut qui décident. Avec default:group::rwx, les fichiers créés par Alice sont modifiables par Thomas, son collègue du groupe compta, même si leur umask est 022.

La ligne mask de getfacl limite les droits maximaux de toutes les entrées de groupe et d’utilisateurs nommés ; un chmod sur un fichier qui a des ACL modifie ce masque.

5. Déléguer avec sudo

Le principe

sudo permet à un utilisateur autorisé d’exécuter une commande en tant qu’un autre utilisateur (root par défaut), avec son propre mot de passe, et journalise chaque commande. On n’a donc jamais besoin de partager le mot de passe root (qui est d’ailleurs verrouillé sur nos Debian).

Les règles sont dans /etc/sudoers et surtout dans des fichiers séparés de /etc/sudoers.d/. On les modifie toujours avec visudo, qui vérifie la syntaxe avant d’enregistrer : une erreur dans sudoers peut supprimer tout accès administrateur.

La syntaxe

ExempleRègles sudoersà lire, pas à taper
# qui          sur quelle machine = (en tant que qui)  quelles commandes
# Règle présente par défaut dans /etc/sudoers : le groupe sudo peut tout faire
%sudo          ALL=(ALL:ALL) ALL

# Fichier /etc/sudoers.d/web-ops : le rôle opérateurs web gère nginx, et rien d'autre
Cmnd_Alias NGINX = /usr/bin/systemctl restart nginx, /usr/bin/systemctl reload nginx, \
                   /usr/bin/systemctl status nginx, /usr/sbin/nginx -t
%web-ops       ALL=(root) NGINX
  • % désigne un groupe : on délègue à un rôle, pas à une personne (RBAC, comme AGDLP).
  • Les commandes s’écrivent avec leur chemin complet. Si des arguments sont indiqués, seuls ceux-là sont permis.
  • NOPASSWD: supprime la demande de mot de passe : à réserver à des automatismes précis.
ExempleMachine : SRV-LNX-01à lire, pas à taper
sudo visudo -f /etc/sudoers.d/web-ops        # créer ou modifier un fichier de règles
sudo visudo -c                               # vérifier toute la configuration
sudo -l                                      # ce que j'ai le droit de faire
sudo -l -U nfournier                         # ce qu'un autre a le droit de faire
sudo journalctl _COMM=sudo -n 20             # qui a lancé quoi avec sudo

Les commandes qui donnent tout

Autoriser sudo vi, sudo less, sudo find, sudo tar, sudo python3, sudo bash ou sudo cp, c’est en pratique donner un accès root complet : ces programmes permettent de lancer un shell ou d’écrire n’importe quel fichier. Le site GTFOBins recense ces détournements. Pour modifier un fichier protégé, on délègue sudoedit fichier, qui fait travailler l’éditeur avec les droits de l’utilisateur sur une copie.

7. À retenir

Points clés

  • /etc/passwd (comptes), /etc/shadow (empreintes des mots de passe, root seulement), /etc/group.
  • usermod -aG, jamais -G seul. Changement de groupe effectif à la prochaine session.
  • rwx pour propriétaire, groupe, autres ; sur un dossier, w = créer et supprimer, x = traverser.
  • Octal : r=4, w=2, x=1. umask 022 → fichiers 644, dossiers 755.
  • Dossier partagé = groupe propriétaire + setgid (2770) + ACL par défaut pour l’héritage.
  • sudo : délégation par groupe, commandes précises, visudo, traces dans le journal.

Voir la correction
  1. Dans /etc/shadow, lisible uniquement par root.
  2. Il remplace tous les groupes secondaires par compta. Il fallait usermod -aG compta amartin.
