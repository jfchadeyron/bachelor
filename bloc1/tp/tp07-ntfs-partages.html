TP 7 : Le serveur de fichiers Hexalog

À partir d'une matrice des droits validée par la direction, vous créez l'arborescence des partages sur le volume DATA, les groupes de domaine local, les permissions NTFS et le partage. Puis vous prouvez, compte par compte, que chacun accède à ce qu'il doit, et à rien d'autre.

Contexte

Aujourd’hui, chez Hexalog, tout le monde peut tout lire sur l’ancien serveur, y compris les bulletins de paie. La direction a validé la matrice ci-dessous. Votre mission : l’implémenter sur SRV-WIN-01 selon la méthode AGDLP, puis fournir la preuve qu’elle est respectée.

La matrice des droits

Dossier Direction RH Comptabilité Exploitation Informatique
Commun lecture-écriture lecture-écriture lecture-écriture lecture-écriture lecture-écriture
Direction lecture-écriture
RH lecture seule lecture-écriture
Comptabilite lecture seule lecture-écriture
Exploitation lecture seule lecture-écriture

Case vide = aucun accès, et le dossier ne doit même pas être visible. Le service Informatique n’a pas accès aux données métier : il administre le serveur avec les comptes d’administration.

Architecture visée

Étape 1. Les groupes de domaine local

Faites un snapshot 07-avant-partages de SRV-WIN-01. Dans PowerShell administrateur :

Machine : SRV-WIN-01 (PowerShell administrateur)
$ouDL = "OU=DomaineLocal,OU=Groupes,OU=HEXALOG,DC=hexalog,DC=lan"
"DL_Commun_RW","DL_Direction_RW","DL_RH_RW","DL_RH_RO","DL_Compta_RW","DL_Compta_RO",
"DL_Exploitation_RW","DL_Exploitation_RO" | ForEach-Object {
    New-ADGroup -Name $_ -GroupScope DomainLocal -GroupCategory Security -Path $ouDL
}
Get-ADGroup -Filter 'Name -like "DL_*"' | Select-Object Name, GroupScope

À vous de remplir les groupes de domaine local avec les bons groupes globaux, d’après la matrice. Exemple pour la comptabilité :

Machine : SRV-WIN-01 (PowerShell administrateur)
Add-ADGroupMember -Identity DL_Compta_RW -Members GG_Comptabilite
Add-ADGroupMember -Identity DL_Compta_RO -Members GG_Direction

Écrivez les six autres commandes (attention : DL_Commun_RW reçoit les cinq groupes globaux). Vérifiez avec :

Machine : SRV-WIN-01 (PowerShell administrateur)
Get-ADGroup -Filter 'Name -like "DL_*"' | ForEach-Object {
    "{0,-22} : {1}" -f $_.Name, ((Get-ADGroupMember $_).Name -join ', ')
}

Étape 2. L’arborescence et les permissions NTFS

Machine : SRV-WIN-01 (PowerShell administrateur)
$racine = "E:\Partages"
New-Item -ItemType Directory -Path $racine
"Commun","Direction","RH","Comptabilite","Exploitation" |
    ForEach-Object { New-Item -ItemType Directory -Path "$racine\$_" }

icacls $racine                                 # permissions héritées de E:\ : à noter dans le journal

On repart de zéro sur la racine : seuls les administrateurs et le système gardent le contrôle total (hérité par tous les sous-dossiers), et les utilisateurs authentifiés peuvent seulement lister la racine (portée « ce dossier seulement », donc non héritée) :

Machine : SRV-WIN-01 (PowerShell administrateur)
icacls $racine /inheritance:r /grant:r "*S-1-5-32-544:(OI)(CI)F" "*S-1-5-18:(OI)(CI)F" "*S-1-5-11:RX"
icacls $racine

Puis chaque dossier reçoit ses groupes de domaine local :

Machine : SRV-WIN-01 (PowerShell administrateur)
icacls "$racine\Commun"       /grant "HEXALOG\DL_Commun_RW:(OI)(CI)M"
icacls "$racine\Direction"    /grant "HEXALOG\DL_Direction_RW:(OI)(CI)M"
icacls "$racine\RH"           /grant "HEXALOG\DL_RH_RW:(OI)(CI)M" "HEXALOG\DL_RH_RO:(OI)(CI)RX"
icacls "$racine\Comptabilite" /grant "HEXALOG\DL_Compta_RW:(OI)(CI)M" "HEXALOG\DL_Compta_RO:(OI)(CI)RX"
icacls "$racine\Exploitation" /grant "HEXALOG\DL_Exploitation_RW:(OI)(CI)M" "HEXALOG\DL_Exploitation_RO:(OI)(CI)RX"
icacls "$racine\RH"

Ouvrez les propriétés de E:\Partages\RH → Sécurité → Avancé : repérez les entrées héritées (colonne Hérité de) et les entrées explicites.

Étape 3. Le partage

On crée un seul partage Partages avec l’énumération basée sur l’accès. Les noms des groupes intégrés sont obtenus à partir de leur SID pour fonctionner quelle que soit la langue :

Machine : SRV-WIN-01 (PowerShell administrateur)
function Get-NomDepuisSid($sid) {
    (New-Object System.Security.Principal.SecurityIdentifier($sid)).Translate([System.Security.Principal.NTAccount]).Value
}
$admins    = Get-NomDepuisSid "S-1-5-32-544"
$authentif = Get-NomDepuisSid "S-1-5-11"
$admins ; $authentif

New-SmbShare -Name "Partages" -Path $racine -FullAccess $admins -ChangeAccess $authentif `
    -FolderEnumerationMode AccessBased -Description "Partages des services Hexalog"
Get-SmbShare -Name Partages | Select-Object Name, Path, FolderEnumerationMode
Get-SmbShareAccess -Name Partages

Étape 4. Les tests

4.1, Accès effectif

Sur E:\Partages\RH → Propriétés → Sécurité → Avancé → Accès effectif : calculez l’accès de c.dubois, s.laurent et a.martin. Faites une capture pour chacun.

4.2, Tests réels depuis CLI-LNX-01

Machine : CLI-LNX-01 (sysadmin)
# Pour ne pas retaper le mot de passe (identique pour tous les salariés dans le lab)
read -s -p "Mot de passe des salariés : " PASSWD ; export PASSWD ; echo

P=//srv-win-01.hexalog.lan/Partages
echo "Bilan provisoire" > /tmp/bilan.txt

# Alice (comptabilité) : que voit-elle à la racine ?
smbclient $P -U 'HEXALOG\a.martin' -c 'ls'
# Alice dépose un fichier dans Comptabilite
smbclient $P -U 'HEXALOG\a.martin' -c 'cd Comptabilite; put /tmp/bilan.txt bilan.txt; ls'
# Claire (direction) lit, mais ne peut pas écrire
smbclient $P -U 'HEXALOG\c.dubois' -c 'cd Comptabilite; get bilan.txt /tmp/bilan-lu.txt'
smbclient $P -U 'HEXALOG\c.dubois' -c 'cd Comptabilite; put /tmp/bilan.txt essai.txt'
# Julien (exploitation) ne voit pas Comptabilite et ne peut pas y entrer
smbclient $P -U 'HEXALOG\j.moreau' -c 'ls'
smbclient $P -U 'HEXALOG\j.moreau' -c 'cd Comptabilite'
# Nicolas (informatique) : que voit-il ?
smbclient $P -U 'HEXALOG\n.fournier' -c 'ls'

Complétez la matrice de tests (au moins 12 tests couvrant chaque ligne de la matrice des droits) :

# Compte Dossier Action Attendu Obtenu Preuve
1 a.martin racine lister voit Commun et Comptabilite capture
2 a.martin Comptabilite déposer un fichier autorisé
3 c.dubois Comptabilite lire un fichier autorisé
4 c.dubois Comptabilite déposer un fichier refusé
5 j.moreau Comptabilite entrer refusé
…

NT_STATUS_ACCESS_DENIED indique un refus. Avec l’ABE, un dossier non autorisé n’apparaît pas dans ls.

Étape 5. Quotas

Machine : SRV-WIN-01 (PowerShell administrateur)
Install-WindowsFeature FS-Resource-Manager -IncludeManagementTools
New-FsrmQuota -Path "E:\Partages\Commun" -Size 200MB -Description "Quota strict du dossier commun"
New-FsrmQuota -Path "E:\Partages\Exploitation" -Size 1GB -SoftLimit -Description "Quota souple"
Get-FsrmQuota | Format-Table Path, Size, SoftLimit, Usage

Testez le quota strict :

Machine : CLI-LNX-01 (sysadmin)
cd ~
fallocate -l 250M gros-fichier.bin          # dans le dossier personnel : /tmp est en mémoire sous Debian 13
smbclient //srv-win-01.hexalog.lan/Partages -U 'HEXALOG\l.roux' -c 'cd Commun; put gros-fichier.bin gros.bin'
rm ~/gros-fichier.bin

Quel message obtenez-vous ? Retrouvez l’événement correspondant dans l’Observateur d’événements (journal Application, source SRMSVC).

Dépannage

Symptôme Piste
icacls : « Mappage entre noms de compte et ID de sécurité non effectué » nom de groupe mal écrit ou groupe inexistant : Get-ADGroup DL_RH_RW
Plus personne n’accède à rien, même l’administrateur héritage supprimé sans avoir remis Administrateurs : se réapproprier le dossier (takeown /f E:\Partages /r /d o) puis réappliquer icacls
NT_STATUS_ACCESS_DENIED pour un compte qui devrait avoir accès le groupe global est-il dans le bon DL ? l’utilisateur dans le bon GG ? Get-ADPrincipalGroupMembership
NT_STATUS_BAD_NETWORK_NAME nom du partage mal écrit (Partages)
NT_STATUS_LOGON_FAILURE identifiant ou mot de passe ; la variable PASSWD est-elle bien exportée ?
Un compte voit tous les dossiers ABE non activée : Set-SmbShare -Name Partages -FolderEnumerationMode AccessBased
