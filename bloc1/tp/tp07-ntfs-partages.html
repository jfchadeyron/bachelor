TP 7 : Partages et permissions, testés depuis le poste

Vous créez sur SRV-WIN-01 le dossier partagé d'Hexalog, avec un sous-dossier par service. Vous donnez les droits aux groupes selon la matrice validée par la direction, puis vous vérifiez depuis CLI-WIN-01, en ouvrant une session avec chaque salarié, que chacun accède à ce qu'il doit, et à rien d'autre.

Contexte

Aujourd’hui, chez Hexalog, tout le monde peut tout lire sur l’ancien serveur, y compris les fichiers de paie. La direction a validé la matrice des droits ci-dessous. Votre mission : la mettre en place sur SRV-WIN-01, puis prouver, compte par compte, qu’elle est respectée.

Avant de commencer

Il faut avoir terminé le TP 6 : Un poste Windows 11 dans le domaine : les comptes et les groupes (étape 3), et CLI-WIN-01 dans le domaine (étape 6). Allumez SRV-WIN-01 d’abord, puis CLI-WIN-01.

Objectifs

  • Créer une arborescence de dossiers et la partager sur le réseau.
  • Retirer les droits trop larges donnés par défaut.
  • Donner des permissions NTFS à des groupes, d’après une matrice des droits.
  • Vérifier les droits avec l’accès effectif, puis avec les vrais comptes.
  • Observer la règle du « plus restrictif » entre partage et NTFS, et le rôle de l’ouverture de session.

La matrice des droits

Dossier Direction RH Comptabilité Exploitation
Commun Modification Modification Modification Modification
Direction Modification
RH Lecture Modification
Comptabilite Lecture Modification
Exploitation Lecture Modification

Case vide = aucun accès. Le dossier Commun est ouvert à tous les salariés, y compris le service Informatique. Le service Informatique n’a pas accès aux autres dossiers : il administre le serveur, il n’a pas besoin de lire la paie.

Ce que vous allez construire

Deux étages : le partage est la porte d’entrée par le réseau, réglée largement ; les permissions NTFS de chaque dossier font le vrai tri.

Étape 1. Créer les dossiers

Faites un snapshot 07-avant-partages de SRV-WIN-01.

Dans l’Explorateur de SRV-WIN-01, créez le dossier C:\Partages, puis dedans les cinq dossiers : Commun, Direction, RH, Comptabilite, Exploitation (sans accent, comme les groupes).

C: ou un disque de données ?

En entreprise, les données partagées sont sur un disque séparé du système (E: par exemple) : une réinstallation de Windows ne les touche pas, et un disque de données plein ne bloque pas le serveur. Dans le lab, on reste sur C: pour simplifier.

Étape 2. Retirer l’accès par défaut

Clic droit sur C:\Partages → Propriétés → onglet Sécurité. Regardez la liste : le groupe Utilisateurs a la lecture. Ces droits viennent de C:\ par héritage, et ce groupe contient tous les comptes du domaine : en l’état, n’importe quel salarié pourrait lire tous les dossiers. On les retire.

  1. Bouton Avancé → Désactiver l’héritage → Convertir les autorisations héritées en autorisations explicites sur cet objet.
  2. Sélectionnez chaque ligne Utilisateurs (il y en a deux ou trois) → Supprimer.
  3. Gardez Administrateurs, Système et CREATEUR PROPRIETAIRE.

Les salariés doivent quand même pouvoir ouvrir Partages et voir la liste des dossiers. Toujours dans la fenêtre Avancé :

  1. Ajouter → Sélectionnez un principal → tapez Utilisateurs du domaine → Vérifier les noms → OK.
  2. S’applique à : Ce dossier seulement. Autorisations de base : laissez Lecture et exécution (avec Affichage du contenu du dossier et Lecture). OK, puis Appliquer et OK.

« Ce dossier seulement » : les salariés peuvent lister Partages, mais ce droit ne descend pas dans les sous-dossiers. Ouvrez les propriétés de C:\Partages\RH → Sécurité : il ne reste que Administrateurs, Système et CREATEUR PROPRIETAIRE, hérités de C:\Partages.

Étape 3. Donner les droits aux groupes

Pour chaque sous-dossier : clic droit → Propriétés → Sécurité → Modifier → Ajouter → tapez le nom du groupe → Vérifier les noms → OK. Sélectionnez le groupe dans la liste et cochez dans la colonne Autoriser la case indiquée, puis Appliquer.

Dossier Groupe Case à cocher (Autoriser)
Commun Utilisateurs du domaine Modification
Direction GG_Direction Modification
RH GG_RH Modification
GG_Direction Lecture et exécution (déjà cochée à l’ajout)
Comptabilite GG_Comptabilite Modification
GG_Direction Lecture et exécution
Exploitation GG_Exploitation Modification
GG_Direction Lecture et exécution

Cocher Modification coche aussi les cases qu’elle contient (lecture, écriture…). Ne cochez jamais Contrôle total pour des utilisateurs, et ne cochez rien dans la colonne Refuser.

Ouvrez ensuite RH → Sécurité → Avancé : la colonne Hérité de montre d’où vient chaque ligne. Administrateurs et Système viennent de C:\Partages ; les deux groupes ont été ajoutés ici (Aucun).

Étape 4. Partager le dossier

Clic droit sur C:\Partages → Propriétés → onglet Partage → Partage avancé :

  1. Cochez Partager ce dossier. Nom du partage : Partages.
  2. Autorisations → Tout le monde : cochez Modifier dans la colonne Autoriser (Lecture est déjà cochée). OK, OK.

Le partage est volontairement large : c’est le NTFS qui fait le tri. Son chemin réseau est \\SRV-WIN-01\Partages.

Vérifiez le partage dans deux consoles :

  • Gestionnaire de serveur → Services de fichiers et de stockage → Partages : la ligne Partages, chemin local C:\Partages, protocole SMB ;
  • Gestion de l’ordinateur (clic droit sur le menu Démarrer) → Dossiers partagés → Partages : Partages apparaît à côté des partages créés par Windows (NETLOGON, SYSVOL, et les partages d’administration C$, ADMIN$).

Étape 5. Vérifier avec l’accès effectif

Avant de tester avec les comptes, Windows peut calculer les droits d’un utilisateur à partir de tous ses groupes. Sur SRV-WIN-01 : propriétés de C:\Partages\RH → Sécurité → Avancé → onglet Accès effectif → Sélectionner un utilisateur → c.dubois → Afficher l’accès effectif.

Recommencez avec s.laurent puis a.martin. Notez dans votre journal ce que chacun peut faire, et faites une capture pour chacun.

Étape 6. Tester avec les vrais comptes, depuis CLI-WIN-01

C’est la seule vraie preuve. Pour chaque salarié : ouvrez sa session sur CLI-WIN-01 (Autre utilisateur, HEXALOG\…), ouvrez l’Explorateur, tapez \\SRV-WIN-01\Partages dans la barre d’adresse, faites les tests, puis déconnectez-vous avant de passer au salarié suivant.

Faites les tests dans l’ordre du tableau : Alice crée le fichier que Claire essaiera ensuite de lire.

# Compte Dossier Action Attendu Obtenu
1 a.martin Comptabilite créer le fichier texte bilan.txt, écrire une ligne, enregistrer autorisé
2 a.martin Commun créer un fichier note-alice.txt autorisé
3 a.martin RH ouvrir le dossier refusé
4 a.martin Direction ouvrir le dossier refusé
5 s.laurent RH créer le fichier paie-octobre.txt autorisé
6 s.laurent Comptabilite ouvrir le dossier refusé
7 c.dubois Comptabilite ouvrir bilan.txt autorisé
8 c.dubois Comptabilite modifier bilan.txt et enregistrer refusé
9 c.dubois RH ouvrir paie-octobre.txt autorisé
10 c.dubois Direction créer un fichier autorisé
11 j.moreau Exploitation créer un fichier autorisé
12 j.moreau Comptabilite ouvrir le dossier refusé
13 j.moreau Commun supprimer note-alice.txt ?

Pour créer un fichier : clic droit dans le dossier → Nouveau → Document texte. Un refus s’affiche par un message du type « Vous n’avez pas l’autorisation d’accéder à ce dossier » ou « Accès refusé ».

Tous les résultats « Obtenu » doivent être égaux aux résultats « Attendu ». Sinon, cherchez l’erreur (voir le dépannage) avant de continuer. Pour le test 13, notez ce qui se passe : la question 3 y revient.

Un lecteur réseau

Pour ne pas retaper le chemin : dans l’Explorateur, Ce PC → menu … → Connecter un lecteur réseau → lettre S:, dossier \\SRV-WIN-01\Partages. En entreprise, cette lettre est souvent attribuée automatiquement par une stratégie de groupe.

Étape 7. Expérience : le plus restrictif l’emporte

  1. Sur SRV-WIN-01 : propriétés de C:\Partages → Partage → Partage avancé → Autorisations → Tout le monde : décochez Modifier (il ne reste que Lecture). OK, OK.
  2. Sur CLI-WIN-01, ouvrez la session de a.martin et essayez de créer un fichier dans Comptabilite. Que se passe-t-il, alors que le NTFS lui donne Modification ?
  3. Remettez Modifier sur le partage, déconnectez a.martin, reconnectez-la et vérifiez qu’elle peut de nouveau écrire.

Retenez : à travers le réseau, l’accès est le plus restrictif des deux étages, partage et NTFS.

Étape 8. Expérience : un changement de poste

Julien Moreau remplace pendant une semaine une collègue des ressources humaines : il doit pouvoir modifier les fichiers RH.

  1. Ouvrez la session de j.moreau sur CLI-WIN-01 et vérifiez qu’il n’a pas accès à RH. Laissez la session ouverte.
  2. Sur SRV-WIN-01, dans dsa.msc, ajoutez j.moreau au groupe GG_RH. C’est la seule modification : on ne touche à aucun dossier.
  3. Sur le poste, réessayez d’ouvrir RH sans vous déconnecter : toujours refusé. Pourquoi ?
  4. Déconnectez j.moreau, reconnectez-le, réessayez : l’accès fonctionne.
  5. Fin du remplacement : retirez j.moreau de GG_RH, déconnectez-le, reconnectez-le, vérifiez qu’il n’a plus accès.

Les groupes d’un utilisateur sont lus à l’ouverture de session : après un changement de groupe, il faut se déconnecter et se reconnecter.

Étape 9. Sauvegarder et documenter

Faites un snapshot 07-partages de chacune des deux VM. Mettez à jour votre inventaire (partage Partages, dossier C:\Partages) et recopiez dans votre journal la matrice des droits et la matrice de tests complétée.

Vérifications

  • Le partage \\SRV-WIN-01\Partages existe, avec Tout le monde : Modifier.
  • Sur C:\Partages : plus d’héritage, plus de groupe Utilisateurs ; Utilisateurs du domaine en lecture sur ce dossier seulement.
  • Chaque sous-dossier a ses groupes, conformes à la matrice ; aucune permission donnée directement à un utilisateur ; aucun Contrôle total ni refus pour les utilisateurs.
  • Les 13 tests sont faits et conformes à l’attendu.
  • j.moreau n’est plus dans GG_RH à la fin du TP.

Questions

  1. Pourquoi a-t-on retiré le groupe Utilisateurs de C:\Partages ? Que se passait-il sinon ?
  2. Que signifie « Ce dossier seulement » pour Utilisateurs du domaine sur C:\Partages ?
  3. Julien a pu supprimer le fichier d’Alice dans Commun (test 13). Pourquoi ? Est-ce souhaitable ?
  4. À l’étape 7, quel étage a bloqué Alice : le partage ou le NTFS ? Que retenez-vous ?
  5. À l’étape 8, pourquoi Julien n’avait-il pas l’accès tant qu’il ne s’était pas reconnecté ?
  6. Une nouvelle comptable arrive. Que faites-vous pour qu’elle ait tous les accès de la comptabilité ? Touchez-vous aux dossiers ?

Dépannage

Symptôme Piste
\\SRV-WIN-01\Partages introuvable depuis le poste SRV-WIN-01 allumé ? nom du partage exact (Partages) ? essayez \\10.10.10.10\Partages ; DNS du poste = 10.10.10.10
Un salarié n’arrive même pas à ouvrir Partages Utilisateurs du domaine absent de C:\Partages, ou mauvaise portée (étape 2, points 4 et 5)
Un salarié voit et ouvre tous les dossiers le groupe Utilisateurs n’a pas été retiré de C:\Partages, ou l’héritage n’a pas été désactivé
Refus pour un compte qui devrait avoir accès le groupe a-t-il la bonne case cochée sur ce dossier ? l’utilisateur est-il dans le bon groupe (onglet Membre de dans dsa.msc) ? s’est-il reconnecté après un changement de groupe ?
Plus personne n’a accès, même l’administrateur Administrateurs supprimé par erreur : propriétés → Sécurité → Avancé → Propriétaire → Modifier → Administrateurs, puis remettez Administrateurs en Contrôle total
« Le nom d’utilisateur ou le mot de passe est incorrect » en ouvrant le partage la session ouverte sur le poste est un compte local (.\localadmin) : ouvrez la session d’un compte du domaine
Vérifier les noms ne trouve pas GG_RH faute de frappe, ou groupe créé sous un autre nom : regardez dans l’OU Groupes
« La relation d’approbation… a échoué » à l’ouverture de session voir le dépannage du TP 6 : Un poste Windows 11 dans le domaine

Livrables

  • La matrice des droits et la matrice de tests complétée.
  • Captures : permissions avancées de C:\Partages et de RH, les autorisations du partage, l’accès effectif de trois comptes, un refus et une réussite depuis CLI-WIN-01, le blocage de l’étape 7.
  • Réponses aux questions.

Pour aller plus loin

Ne montrer que les dossiers autorisés

Pour l’instant, j.moreau voit le dossier Comptabilite, même s’il ne peut pas l’ouvrir. L’énumération basée sur l’accès (ABE) cache à chacun les dossiers qui ne lui sont pas ouverts : Gestionnaire de serveur → Services de fichiers et de stockage → Partages → clic droit sur Partages → Propriétés → Paramètres → cochez Activer l’énumération basée sur l’accès. Reconnectez j.moreau et comparez.

AGDLP sur le dossier RH

Les grandes entreprises ne donnent pas les droits aux groupes globaux, mais à des groupes de domaine local, un par dossier et par niveau d’accès (voir le cours, partie 6). Essayez sur RH :

  1. Dans l’OU Groupes, créez deux groupes d’étendue Domaine local : DL_RH_RW et DL_RH_RO.
  2. Mettez GG_RH dans DL_RH_RW et GG_Direction dans DL_RH_RO.
  3. Sur C:\Partages\RH, remplacez GG_RH par DL_RH_RW (Modification) et GG_Direction par DL_RH_RO (Lecture et exécution).
  4. Refaites les tests 5 et 9 : le résultat est le même. Qu’a-t-on gagné ?

Pour information : les permissions en ligne de commande

Les administrateurs vérifient souvent les permissions avec la commande icacls, plus rapide à lire quand il y a beaucoup de dossiers. Dans l’Invite de commandes de SRV-WIN-01 :

Machine : SRV-WIN-01 (Invite de commandes)
icacls C:\Partages\Comptabilite

Chaque ligne correspond à une ligne de l’onglet Sécurité : M = Modification, RX = Lecture et exécution, F = Contrôle total ; (I) = héritée ; (OI)(CI) = s’applique au dossier, aux sous-dossiers et aux fichiers.
