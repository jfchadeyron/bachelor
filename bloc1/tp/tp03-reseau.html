TP 3 : Adresses fixes, intranet et redirections

Vous donnez aux deux machines Linux du lab une adresse fixe et le DNS du domaine, vous publiez un petit site web interne sur SRV-LNX-01, puis vous le rendez accessible depuis votre PC par redirection de ports. Un réseau de test avec son propre serveur DHCP et DNS, et un défi de diagnostic, sont proposés en option.

Contexte

Hexalog veut un intranet minimal sur SRV-LNX-01. Les serveurs doivent avoir des adresses fixes et documentées, et l’intranet doit être joignable depuis votre PC.

Organisation : ce TP se fait au début de la séance 8

Le TP a été allégé et reporté au mardi 13 octobre, au retour sur Linux.

  • À faire : les étapes 1 à 6. La suite de la partie Linux (TP 4 partie C, TP 8 à 10) et l’évaluation finale s’appuient dessus.
  • Facultatif : le réseau de test avec DHCP et DNS, et le défi de diagnostic (« Pour aller plus loin »).

Objectifs

  • Relever une configuration fournie par DHCP, puis configurer une adresse fixe.
  • Installer un service web et vérifier qu’il écoute.
  • Créer des redirections de ports et les tester depuis votre PC.

Étape 1. Relever la configuration DHCP

Sur SRV-LNX-01, avant de toucher à quoi que ce soit :

Machine : SRV-LNX-01 (sysadmin)
ip -br a
ip route
cat /etc/resolv.conf
cat /etc/network/interfaces

Notez dans votre journal : adresse obtenue, passerelle, serveur(s) DNS (ligne nameserver). Vous réutiliserez ce DNS dans la configuration fixe. La ligne iface enp0s3 inet dhcp indique que l’adresse vient du DHCP.

Étape 2. Adresse fixe sur SRV-LNX-01

Faites un snapshot 03-avant-ip-fixe, puis éditez la configuration :

Machine : SRV-LNX-01 (sysadmin)
sudo cp /etc/network/interfaces /etc/network/interfaces.bak
sudo nano /etc/network/interfaces

Remplacez le bloc de enp0s3 par :

Fichier : /etc/network/interfaces
# Carte 1 : réseau LAB-HEXALOG
auto enp0s3
iface enp0s3 inet static
    address 10.10.10.20/24
    gateway 10.10.10.1

Puis le DNS. Le premier serveur est le contrôleur de domaine SRV-WIN-01 (TP 5) : il connaît les noms du domaine hexalog.local et transmet les autres questions à l’extérieur. Le second, celui relevé à l’étape 1, sert de secours quand SRV-WIN-01 est éteint ; timeout:1 évite d’attendre 5 secondes avant de passer au secours. Remplacez X.X.X.X par la valeur relevée à l’étape 1 :

Machine : SRV-LNX-01 (sysadmin)
sudo nano /etc/resolv.conf
Fichier : /etc/resolv.conf
search hexalog.local
nameserver 10.10.10.10
nameserver X.X.X.X
options timeout:1

Redémarrez et vérifiez :

Machine : SRV-LNX-01 (sysadmin)
sudo reboot
# après redémarrage
ip -br a                    # 10.10.10.20/24
ip route                    # default via 10.10.10.1
ping -c 2 10.10.10.1
ping -c 2 9.9.9.9
dig +short deb.debian.org

Si le ping vers 9.9.9.9 échoue alors que curl -I https://deb.debian.org fonctionne, c’est que le réseau de l’établissement filtre le protocole ICMP (ping). Ce n’est pas une panne de votre configuration.

Étape 3. Un intranet sur SRV-LNX-01

Machine : SRV-LNX-01 (sysadmin)
sudo apt install -y nginx netcat-openbsd
systemctl status nginx --no-pager           # active (running) ?
sudo ss -tlnp | grep ':80'                  # nginx écoute-t-il sur le port 80 ?
echo '<h1>Intranet Hexalog</h1><p>Servi par srv-lnx-01</p>' | sudo tee /var/www/html/index.html
curl http://127.0.0.1                        # test local

Depuis CLI-LNX-01 (encore en DHCP sur LAB-HEXALOG) :

Machine : CLI-LNX-01 (sysadmin)
sudo apt install -y netcat-openbsd
ping -c 2 10.10.10.20
nc -zv 10.10.10.20 80
curl http://10.10.10.20

Étape 4. Redirections de ports

Dans Fichier → Outils → Gestionnaire de réseau → Réseaux NAT → LAB-HEXALOG → Redirection de ports, onglet IPv4, ajoutez :

Nom Protocole IP hôte Port hôte IP invité Port invité
web-srv TCP 127.0.0.1 8080 10.10.10.20 80
ssh-srv TCP 127.0.0.1 2222 10.10.10.20 22

Équivalent en ligne de commande :

Machine : PC hôte
VBoxManage natnetwork modify --netname LAB-HEXALOG --port-forward-4 "web-srv:tcp:[127.0.0.1]:8080:[10.10.10.20]:80"
VBoxManage natnetwork modify --netname LAB-HEXALOG --port-forward-4 "ssh-srv:tcp:[127.0.0.1]:2222:[10.10.10.20]:22"

Une table de traduction de ports

Chaque ligne de ce tableau est une règle de PAT : un port de l’adresse « extérieure » (ici 127.0.0.1, votre PC) est envoyé vers une machine et un port internes. C’est exactement la règle 443 → 192.168.1.100:443 de l’exemple du reverse proxy (cours de la séance 3, partie 7).

Testez depuis le PC hôte :

  • navigateur : http://127.0.0.1:8080 ;
  • terminal ou PowerShell :
Machine : PC hôte Windows (PowerShell)
curl.exe -I http://127.0.0.1:8080
Test-NetConnection 127.0.0.1 -Port 2222
ssh -p 2222 sysadmin@127.0.0.1          # acceptez l'empreinte (yes), puis mot de passe

Sur un hôte Linux, utilisez curl -I, nc -zv 127.0.0.1 2222 et ssh -p 2222 sysadmin@127.0.0.1.

Une fois connecté en SSH, regardez qui a consulté l’intranet :

Machine : SRV-LNX-01 (via SSH)
sudo tail -n 5 /var/log/nginx/access.log

Quelle adresse source apparaît pour les requêtes venues de votre PC ? Expliquez.

Étape 5. Adresse fixe sur CLI-LNX-01

Même travail qu’à l’étape 2, sur CLI-LNX-01, avec l’adresse 10.10.10.101/24 (même passerelle, même DNS). Faites d’abord un snapshot, puis :

Machine : CLI-LNX-01 (sysadmin)
sudo cp /etc/network/interfaces /etc/network/interfaces.bak
sudo nano /etc/network/interfaces     # bloc enp0s3 : address 10.10.10.101/24, gateway 10.10.10.1
sudo nano /etc/resolv.conf            # même contenu que sur SRV-LNX-01
sudo reboot
# après redémarrage
ip -br a                              # 10.10.10.101/24
curl http://10.10.10.20               # l'intranet répond toujours

Le DHCP du réseau LAB-HEXALOG reste activé : il sert pendant l’installation des nouvelles VM, avant qu’on leur donne leur adresse fixe.

Étape 6. Les machines Linux dans le DNS du domaine

Allumez SRV-WIN-01 si ce n’est pas fait. Pour que les noms des serveurs Linux soient connus dans tout le lab, ajoutez-les à la zone DNS du domaine. Sur SRV-WIN-01 : Outils → DNS → SRV-WIN-01 → Zones de recherche directe → hexalog.local :

  1. clic droit sur la zone → Nouvel hôte (A ou AAAA)… → nom srv-lnx-01, adresse 10.10.10.20 → Ajouter un hôte ;
  2. même chose pour cli-lnx-01, adresse 10.10.10.101 ;
  3. clic droit sur la zone → Nouvel alias (CNAME)… → nom de l’alias intranet, nom de domaine complet de l’hôte cible srv-lnx-01.hexalog.local → OK.

Testez depuis CLI-LNX-01 :

Machine : CLI-LNX-01 (sysadmin)
dig +short srv-win-01.hexalog.local   # 10.10.10.10 : réponse du DNS du domaine
ping -c 2 srv-lnx-01                  # nom court complété grâce à la ligne search
curl http://intranet                  # l'intranet par son alias
dig +short deb.debian.org             # les noms d'Internet, toujours

Faites un snapshot 03-ip-fixe des deux VM Linux et mettez à jour l’inventaire (adresses, DNS, service nginx, redirections).

A. Un réseau de test avec DHCP et DNS

On crée un réseau interne isolé LAN-TEST (10.20.20.0/24) où SRV-LNX-01 joue le rôle de serveur DHCP et DNS grâce à dnsmasq.

A.1, Deuxième carte sur SRV-LNX-01

Éteignez SRV-LNX-01. Dans Configuration → Réseau → Adaptateur 2 : activer, Réseau interne, nom LAN-TEST. Démarrez, puis ajoutez la configuration de la carte enp0s8 à la fin de /etc/network/interfaces :

Fichier : /etc/network/interfaces (ajout)
# Carte 2 : réseau de test LAN-TEST
auto enp0s8
iface enp0s8 inet static
    address 10.20.20.1/24

Pas de ligne gateway : une machine n’a qu’une route par défaut, et elle passe par la carte 1.

Machine : SRV-LNX-01 (sysadmin)
sudo ifup enp0s8
ip -br a
ip route

A.2, Installer et configurer dnsmasq

Machine : SRV-LNX-01 (sysadmin)
sudo apt install -y dnsmasq tcpdump
sudo nano /etc/dnsmasq.d/lan-test.conf
Fichier : /etc/dnsmasq.d/lan-test.conf
# N'écouter que sur la carte du réseau de test
interface=enp0s8
bind-interfaces

# DHCP : plage d'adresses et durée du bail
dhcp-range=10.20.20.100,10.20.20.150,255.255.255.0,12h
# Options transmises aux clients : passerelle et DNS
dhcp-option=option:router,10.20.20.1
dhcp-option=option:dns-server,10.20.20.1

# DNS : domaine local, géré ici sans interroger l'extérieur
domain=test.hexalog.local
local=/test.hexalog.local/
no-hosts
host-record=srv-lnx-01.test.hexalog.local,10.20.20.1
cname=intranet.test.hexalog.local,srv-lnx-01.test.hexalog.local
Machine : SRV-LNX-01 (sysadmin)
sudo dnsmasq --test                      # vérifie la syntaxe
sudo systemctl restart dnsmasq
systemctl status dnsmasq --no-pager
sudo ss -ulnp | grep dnsmasq             # ports 53 (DNS) et 67 (DHCP)

A.3, Observer l’échange DHCP

Sur SRV-LNX-01, lancez une capture et laissez-la tourner :

Machine : SRV-LNX-01 (sysadmin)
sudo tcpdump -ni enp0s8 port 67 or port 68

Sur CLI-LNX-01, remettez temporairement l’adresse en DHCP (ligne iface enp0s3 inet dhcp dans /etc/network/interfaces), passez l’adaptateur 1 sur Réseau interne → LAN-TEST, puis :

Machine : CLI-LNX-01 (sysadmin)
sudo ifdown enp0s3 ; sudo ifup enp0s3
ip -br a                          # adresse entre .100 et .150 ?
ip route                          # passerelle 10.20.20.1 ?
cat /etc/resolv.conf              # DNS 10.20.20.1 ?

Dans la capture, repérez les quatre messages DORA. Arrêtez la capture avec Ctrl+C. Consultez aussi les journaux :

Machine : SRV-LNX-01 (sysadmin)
sudo journalctl -u dnsmasq --no-pager | tail -n 20
cat /var/lib/misc/dnsmasq.leases      # baux attribués

A.4, Tester le DNS

Machine : CLI-LNX-01 (sysadmin)
dig srv-lnx-01.test.hexalog.local          # enregistrement A
dig intranet.test.hexalog.local            # alias CNAME puis A
dig cli-lnx-01.test.hexalog.local          # le client a transmis son nom au DHCP : dnsmasq l'a enregistré
dig +short deb.debian.org                # dnsmasq relaie vers le DNS de SRV-LNX-01
curl http://intranet.test.hexalog.local    # l'intranet par son nom
ping -c 2 9.9.9.9                        # échoue : pourquoi ?

Pourquoi pas d'Internet sur LAN-TEST ?

Le client a bien une passerelle (10.20.20.1), mais SRV-LNX-01 n’est pas configuré pour router les paquets d’une carte à l’autre ni pour faire du NAT. Un serveur Linux ne relaie pas le trafic par défaut : c’est une sécurité. Voir « Pour aller plus loin ».

A.5, Remettre le lab en état

  1. Sur SRV-LNX-01 : sudo systemctl disable --now dnsmasq, puis éteignez la VM et désactivez l’adaptateur 2.
  2. Sur CLI-LNX-01 : repassez l’adaptateur 1 sur Réseau NAT → LAB-HEXALOG et remettez dans /etc/network/interfaces le bloc static de l’étape 5, puis redémarrez.

Questions : pourquoi ne faut-il pas de ligne gateway sur la carte enp0s8 ? Que se passerait-il si vous branchiez dnsmasq sur le réseau de l’établissement ?

B. Défi de diagnostic en binôme

Chacun introduit une panne sur le lab de son voisin (en son absence), dans la liste suivante, puis l’autre diagnostique avec la méthode du cours :

  1. passerelle erronée dans /etc/network/interfaces de CLI-LNX-01 (puis redémarrage) ;
  2. mauvais serveur DNS dans /etc/resolv.conf de CLI-LNX-01 ;
  3. service nginx arrêté sur SRV-LNX-01 (sudo systemctl stop nginx) ;
  4. règle web-srv modifiée pour pointer vers 10.10.10.21 ;
  5. câble de l’adaptateur 1 de CLI-LNX-01 débranché dans VirtualBox.

Remplissez une fiche de diagnostic : symptôme observé, hypothèses, tests réalisés et résultats, cause trouvée, correction, vérification. Interdiction de regarder directement le fichier modifié avant d’avoir localisé la couche en panne par des tests.

C. Transformer SRV-LNX-01 en routeur

Pour donner Internet au réseau LAN-TEST :

Transformer SRV-LNX-01 en routeur pour donner Internet au réseau LAN-TEST :

Machine : SRV-LNX-01 (sysadmin)
# 1. autoriser le routage entre cartes
echo 'net.ipv4.ip_forward=1' | sudo tee /etc/sysctl.d/99-routage.conf
sudo sysctl --system
# 2. NAT des adresses 10.20.20.0/24 à la sortie par enp0s3
sudo apt install -y nftables
sudo nft add table ip nat
sudo nft add chain ip nat postrouting '{ type nat hook postrouting priority 100 ; }'
sudo nft add rule ip nat postrouting ip saddr 10.20.20.0/24 oifname "enp0s3" masquerade

Ces règles nft disparaissent au redémarrage : c’est voulu pour un essai. Vous venez de reproduire ce que fait une box Internet.
