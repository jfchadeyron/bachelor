TP 2 : Construire le lab Hexalog

À partir du modèle Debian, vous fabriquez les deux premières machines du lab par clonage, vous les généralisez, puis vous testez un à un les modes réseau de VirtualBox avant de brancher le lab sur son réseau définitif : LAB-HEXALOG.

Contexte

Le modèle TPL-DEB13 est prêt. Hexalog a besoin d’un premier serveur Linux (SRV-LNX-01) et d’un poste Linux pour les tests (CLI-LNX-01). Plutôt que de réinstaller deux fois Debian, vous les créez par clonage. Avant de choisir le réseau du lab, votre responsable veut une démonstration du comportement de chaque mode réseau.

Objectifs

  • Préparer un modèle pour le clonage.
  • Créer un clone intégral et un clone lié, puis les généraliser.
  • Observer concrètement ce que permet chaque mode réseau.
  • Créer le réseau NAT du lab et y raccorder les VM.
  • Tenir l’inventaire des machines.

Architecture en fin de TP

Étape 1. Préparer le modèle

Démarrez TPL-DEB13, connectez-vous avec sysadmin et installez le script de généralisation fourni :

Machine : TPL-DEB13 (sysadmin)
curl -fsSL https://jfchadeyron.github.io/bachelor/bloc1/fichiers/preparer-clone.sh -o /tmp/preparer-clone.sh
less /tmp/preparer-clone.sh                  # lisez-le avant de l'installer (q pour quitter)
sudo install -m 755 /tmp/preparer-clone.sh /usr/local/sbin/preparer-clone.sh

Que fait ce script ?

Il régénère l’identifiant de machine (/etc/machine-id), supprime et recrée les clés d’hôte SSH, change le nom d’hôte (y compris dans /etc/hosts) et oublie les baux DHCP du modèle. Si le téléchargement échoue, recopiez-le à la main avec sudo nano /usr/local/sbin/preparer-clone.sh à partir de ce fichier, puis sudo chmod 755 /usr/local/sbin/preparer-clone.sh.

Éteignez le modèle (sudo poweroff) et prenez un snapshot 02-modele-pret. À partir de maintenant, on ne démarre plus le modèle.

Étape 2. Créer le réseau NAT du lab

Menu Fichier → Outils → Gestionnaire de réseau, onglet Réseaux NAT, bouton Créer, puis dans les propriétés :

Paramètre Valeur
Nom LAB-HEXALOG
Préfixe IPv4 10.10.10.0/24
Activer DHCP coché (pour l’instant)
IPv6 décoché

Équivalent en ligne de commande :

Machine : PC hôte (terminal ou PowerShell)
VBoxManage natnetwork add --netname LAB-HEXALOG --network "10.10.10.0/24" --enable --dhcp on
VBoxManage natnetwork list

Étape 3. Cloner

  1. Clic droit sur TPL-DEB13 → Cloner.
    • Nom : SRV-LNX-01 ;
    • Politique d’adresse MAC : Générer de nouvelles adresses MAC pour toutes les cartes réseau ;
    • Type de clone : Clone intégral ;
    • Snapshots : État actuel de la machine.
  2. Recommencez pour CLI-LNX-01, mais avec le type Clone lié.
  3. Comparez la taille des dossiers SRV-LNX-01 et CLI-LNX-01 sur le disque du PC.

Étape 4. Généraliser les clones

Pour chaque clone, réglez d’abord Configuration → Réseau → Adaptateur 1 → Réseau NAT → LAB-HEXALOG, démarrez-le, connectez-vous avec sysadmin, puis :

Machine : SRV-LNX-01 (sysadmin)
cat /etc/machine-id                          # notez la valeur : identique au modèle
sudo preparer-clone.sh srv-lnx-01
sudo reboot
Machine : CLI-LNX-01 (sysadmin)
sudo preparer-clone.sh cli-lnx-01
sudo reboot

Après redémarrage, vérifiez sur chaque clone :

Machines : SRV-LNX-01 et CLI-LNX-01
hostnamectl                                  # le nouveau nom apparaît
cat /etc/machine-id                          # la valeur a changé
ls -l /etc/ssh/ssh_host_*                    # clés recréées à l'instant
ip -br a                                     # adresse reçue sur enp0s3 (10.10.10.x)

Prenez un snapshot 02-clone-generalise sur chaque clone.

Étape 5. Tester les modes réseau

Avant de commencer : identifier le PC sur le portail du lycée

Ouvrez un site quelconque dans le navigateur de votre PC. Si la page d’authentification du lycée (pare-feu FortiGate) s’affiche, saisissez vos identifiants. Les VM en NAT et en Réseau NAT passent par cette authentification du PC : sans elle, aucune VM n’a Internet. L’authentification expire au bout d’un moment ; si Internet disparaît d’un coup dans les VM, refaites-la dans le navigateur.

Pour chaque mode, réglez l’adaptateur 1 des deux clones sur le mode indiqué (c’est possible VM allumée), puis relancez l’interface réseau dans chaque VM :

Machines : SRV-LNX-01 et CLI-LNX-01
sudo ifdown enp0s3 ; sudo ifup enp0s3        # relance l'interface et redemande une adresse
ip -br a                                     # quelle adresse ?
ip route                                     # quelle passerelle ?

Puis testez depuis chaque VM : ping -c 2 vers l’autre VM, l’accès au web, et depuis le PC hôte un ping vers l’adresse de la VM. Si ifup ne donne pas d’adresse, redémarrez la VM.

Machines : SRV-LNX-01 et CLI-LNX-01
curl -sI http://deb.debian.org/debian/ | head -n 3    # accès web : « HTTP/1.1 200 OK » attendu

Pour la colonne « VM → Internet », c’est ce test qui compte : c’est par le web que passent apt et les téléchargements. Un ping vers Internet peut être filtré même quand le web fonctionne.

5.a, NAT

Les deux clones en NAT. Relevez leurs adresses. Pourquoi ne peuvent-ils pas se joindre alors qu’ils ont la même adresse ?

5.b, Réseau interne

Les deux clones en Réseau interne, nom intnet-test. Aucun serveur DHCP ne répond : attribuez des adresses temporaires à la main.

Machine : SRV-LNX-01 (sysadmin)
sudo ip addr flush dev enp0s3
sudo ip addr add 192.168.100.1/24 dev enp0s3
Machine : CLI-LNX-01 (sysadmin)
sudo ip addr flush dev enp0s3
sudo ip addr add 192.168.100.2/24 dev enp0s3
ping -c 2 192.168.100.1
ping -c 2 deb.debian.org                     # que se passe-t-il ?

Une adresse ajoutée avec ip addr add disparaît au redémarrage : c’est un test, pas une configuration.

5.c, Réseau privé hôte

Les deux clones en Réseau privé hôte (carte VirtualBox Host-Only Ethernet Adapter ou vboxnet0). Relancez l’interface : le DHCP de VirtualBox donne une adresse en 192.168.56.x. Testez le ping entre VM, vers Internet, et depuis le PC hôte vers les VM.

5.d, Accès par pont

Les deux clones en Accès par pont, nom : la carte réseau physique du PC (la carte Ethernet, pas une carte VirtualBox). Relancez l’interface et relevez l’adresse obtenue : comparez-la avec celle du PC (ipconfig sous Windows, ip -br a sous Linux). Faites les mêmes tests que pour les autres modes, puis :

Machine : CLI-LNX-01 (sysadmin)
curl -sI http://deb.debian.org/debian/ | head -n 3    # que répond le serveur ?
sudo apt update                                       # que se passe-t-il ?

Au lieu de 200 OK, vous obtenez une redirection vers la page d’authentification du pare-feu du lycée, ou rien du tout : la VM en pont a sa propre adresse, le pare-feu attend qu’elle s’identifie, et elle n’a pas de navigateur pour le faire. Notez la réponse obtenue dans le tableau et expliquez-la dans votre journal.

Pendant ce test

En pont, vos VM sont visibles de tout le réseau du lycée : ne lancez aucun service réseau dessus et passez au mode suivant dès le test terminé.

5.e, Réseau NAT

Les deux clones sur Réseau NAT → LAB-HEXALOG. Relancez l’interface et refaites tous les tests.

Étape 6. Inventaire

Créez le fichier d’inventaire du lab (tableur ou Markdown, modèle sur Modèles de livrables) avec une ligne par VM : nom, système, rôle, vCPU, RAM, disque, type de clone, réseau, adresse IP, compte d’administration, snapshots. Il sera complété à chaque séance.

Étape 7. Sauvegarder le modèle

Exportez le modèle : sélectionnez TPL-DEB13, menu Fichier → Exporter un appareil virtuel, format OVF 1.0, fichier TPL-DEB13.ova. Enregistrez-le hors du PC si possible (clé USB, disque externe, espace réseau).

Vérifications

Questions

  1. Quelle différence de taille constatez-vous entre les dossiers des deux clones ? Expliquez.
  2. Que se passerait-il pour CLI-LNX-01 si on supprimait le snapshot 02-modele-pret du modèle ?
  3. Dans le mode Réseau NAT, les VM peuvent-elles être jointes depuis le PC hôte ? Comment faudrait-il faire ? (réponse à la séance 3)
  4. Pourquoi a-t-on besoin de régénérer les clés d’hôte SSH d’un clone ?
  5. Un fichier OVA stocké sur le même disque que les VM est-il une vraie sauvegarde ?

Dépannage

Symptôme Piste
curl échoue lors de l’étape 1 la VM a-t-elle Internet (curl -sI http://deb.debian.org/debian/) ? Sinon, identifier le PC sur le portail du lycée dans le navigateur, ou recopier le script à la main
Internet fonctionnait et ne répond plus (NAT, Réseau NAT) l’authentification du PC sur le portail du lycée a expiré : la refaire dans le navigateur
ping vers Internet échoue mais curl répond 200 OK le pare-feu filtre le ping : l’accès web, celui qu’utilise apt, fonctionne
Aucune adresse en Accès par pont mauvaise carte choisie (Wi-Fi ou carte VirtualBox) : choisir la carte Ethernet du PC
Le réseau NAT n’apparaît pas dans la liste des réseaux d’une VM vérifier qu’il est créé et activé dans le Gestionnaire de réseau
Pas d’adresse après changement de mode sudo ifdown enp0s3 ; sudo ifup enp0s3, sinon redémarrer la VM ; vérifier « Câble branché »
Les deux clones reçoivent la même adresse sur LAB-HEXALOG le script de généralisation n’a pas été lancé sur l’un des deux
ifdown affiche « interface not configured » normal si l’interface n’était pas active, enchaîner avec ifup
Le clone lié ne démarre pas le modèle ou son snapshot a été supprimé ou déplacé
