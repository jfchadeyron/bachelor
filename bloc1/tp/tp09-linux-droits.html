TP 9 : Partages Linux et délégation sudo

Vous reproduisez sous Linux la matrice des droits mise en place sur le serveur Windows : comptes et groupes locaux, dossiers partagés avec setgid, ACL et héritage, sticky bit sur le dossier commun. Puis vous confiez à un technicien la gestion de nginx, et rien d'autre, avec sudo. Un TD compare enfin les deux systèmes.

Contexte

Hexalog veut héberger une copie de travail des dossiers de services sur SRV-LNX-01 (dans /srv/partages, sur le disque de données ajouté à la séance 8). Les droits doivent respecter la même matrice que sur le serveur Windows. Par ailleurs, Nicolas Fournier doit pouvoir redémarrer le serveur web en cas de problème, sans être administrateur complet de la machine.

Rappel de la matrice :

Dossier direction rh compta exploitation
commun lecture-écriture lecture-écriture lecture-écriture lecture-écriture
direction lecture-écriture
rh lecture seule lecture-écriture
compta lecture seule lecture-écriture
exploitation lecture seule lecture-écriture

Règle supplémentaire pour commun : chacun peut lire et modifier les fichiers des autres, mais pas les supprimer.

Étape 1. Groupes et comptes

Faites un snapshot 09-avant-droits. Puis sur SRV-LNX-01 :

Machine : SRV-LNX-01 (sysadmin)
for g in salaries direction rh compta exploitation web-ops ; do sudo groupadd "$g" ; done

# identifiant:groupe du service
for u in cdubois:direction slaurent:rh amartin:compta tpetit:compta jmoreau:exploitation egarcia:exploitation ; do
    login="${u%%:*}" ; service="${u##*:}"
    sudo useradd -m -s /bin/bash -G "$service,salaries" "$login"
done
sudo useradd -m -s /bin/bash -c "Nicolas Fournier" -G web-ops nfournier

read -s -p "Mot de passe de lab : " MDP ; echo
for login in cdubois slaurent amartin tpetit jmoreau egarcia nfournier ; do
    echo "$login:$MDP" | sudo chpasswd
done
unset MDP

Vérifiez :

Machine : SRV-LNX-01 (sysadmin)
id amartin ; id cdubois ; id nfournier
getent group compta salaries web-ops
sudo tail -n 8 /etc/passwd
sudo tail -n 8 /etc/shadow           # repérez l'empreinte ($y$ = algorithme yescrypt)

Dans votre journal, décomposez la ligne de amartin dans /etc/passwd champ par champ.

Étape 2. Observer le umask et le problème du groupe

Machine : SRV-LNX-01 (sysadmin)
umask
mkdir ~/essai && touch ~/essai/fichier
ls -ld ~/essai && ls -l ~/essai

Expliquez les droits obtenus à partir du umask. Puis constatez le problème à résoudre :

Machine : SRV-LNX-01 (sysadmin)
sudo mkdir /srv/partages/test && sudo chown root:compta /srv/partages/test && sudo chmod 770 /srv/partages/test
sudo -u amartin touch /srv/partages/test/facture.txt
ls -l /srv/partages/test                                    # à quel groupe appartient le fichier ?
sudo -u tpetit sh -c 'echo ajout >> /srv/partages/test/facture.txt'   # Thomas peut-il le modifier ?
sudo rm -r /srv/partages/test

sudo -u amartin commande exécute la commande en tant qu’Alice : c’est la façon la plus rapide de tester des droits.

Étape 3. Créer les dossiers partagés

Machine : SRV-LNX-01 (sysadmin)
sudo apt install -y acl
cd /srv/partages
sudo mkdir commun direction rh compta exploitation
sudo chmod 755 /srv/partages

# Propriétaire root, groupe du service, setgid, rien pour les autres
sudo chown root:salaries commun      ; sudo chmod 3770 commun      # + sticky bit
sudo chown root:direction direction  ; sudo chmod 2770 direction
sudo chown root:rh rh                ; sudo chmod 2770 rh
sudo chown root:compta compta        ; sudo chmod 2770 compta
sudo chown root:exploitation exploitation ; sudo chmod 2770 exploitation
ls -l /srv/partages

Ajoutez les ACL : lecture pour la direction sur trois dossiers, et partout une ACL par défaut qui donne la lecture-écriture au groupe du dossier pour les futurs fichiers.

Machine : SRV-LNX-01 (sysadmin)
for d in rh compta exploitation ; do
    sudo setfacl -m g:direction:rx /srv/partages/$d
    sudo setfacl -d -m g::rwx,g:direction:rx,o::--- /srv/partages/$d
done
for d in commun direction ; do
    sudo setfacl -d -m g::rwx,o::--- /srv/partages/$d
done
getfacl /srv/partages/compta
ls -l /srv/partages

Étape 4. Tester

Recopiez et complétez la matrice de tests. Permission denied = refus.

Machine : SRV-LNX-01 (sysadmin)
P=/srv/partages
sudo -u amartin sh -c "echo 'Facture 001' > $P/compta/facture-001.txt"
ls -l $P/compta ; getfacl $P/compta/facture-001.txt        # droits hérités ?
sudo -u tpetit  sh -c "echo 'ligne ajoutée' >> $P/compta/facture-001.txt"   # collègue : modification
sudo -u cdubois cat $P/compta/facture-001.txt                                # direction : lecture
sudo -u cdubois touch $P/compta/note-direction.txt                           # direction : écriture ?
sudo -u jmoreau ls $P/compta                                                 # exploitation : accès ?
sudo -u egarcia sh -c "echo 'planning' > $P/commun/planning.txt"
sudo -u amartin sh -c "echo 'modif' >> $P/commun/planning.txt"               # commun : modification
sudo -u amartin rm $P/commun/planning.txt                                    # commun : suppression ?
sudo -u slaurent ls $P/direction                                             # RH dans direction ?

Étape 5. Déléguer la gestion de nginx

Créez le fichier de règles avec visudo :

Machine : SRV-LNX-01 (sysadmin)
sudo visudo -f /etc/sudoers.d/web-ops
Fichier : /etc/sudoers.d/web-ops
# Rôle opérateurs web : gérer le service nginx uniquement
Cmnd_Alias NGINX = /usr/bin/systemctl restart nginx, /usr/bin/systemctl reload nginx, \
                   /usr/bin/systemctl status nginx, /usr/sbin/nginx -t
%web-ops ALL=(root) NGINX
Machine : SRV-LNX-01 (sysadmin)
sudo visudo -c
sudo -l -U nfournier

Testez en tant que Nicolas (ouvrez une session avec son compte) :

Machine : SRV-LNX-01 (sysadmin)
su - nfournier
Machine : SRV-LNX-01 (nfournier)
sudo -l
sudo /usr/sbin/nginx -t
sudo systemctl restart nginx          # autorisé
sudo systemctl stop nginx             # refusé : pourquoi ?
sudo apt install -y cowsay            # refusé
cat /etc/shadow                       # refusé
exit

Retrouvez les traces :

Machine : SRV-LNX-01 (sysadmin)
sudo journalctl _COMM=sudo --since "15 min ago" --no-pager

Repérez pour chaque tentative : qui, quand, depuis quel terminal, quelle commande, et si elle a été acceptée (COMMAND=) ou refusée (command not allowed).

Étape 6. Verrouiller un compte

Thomas Petit part en congé longue durée : son compte doit être bloqué sans être supprimé.

Machine : SRV-LNX-01 (sysadmin)
sudo usermod -L tpetit
sudo passwd -S tpetit          # L = locked
su - tpetit                    # échec avec le bon mot de passe
sudo usermod -U tpetit         # déverrouillage à son retour
sudo chage -l tpetit

Faites un snapshot 09-droits-linux et mettez à jour l’inventaire (comptes, groupes, partages, règles sudo).

Vérifications

Questions

  1. Sans le bit setgid, à quel groupe appartiendrait facture-001.txt ? Qui pourrait le lire ?
  2. Sans l’ACL par défaut, Thomas aurait-il pu modifier le fichier d’Alice ? Pourquoi ?
  3. Pourquoi sudo systemctl stop nginx est-il refusé à Nicolas alors que restart est autorisé ?
  4. Que se passerait-il si on avait autorisé /usr/bin/systemctl * pour le groupe web-ops ?

Dépannage

Symptôme Piste
setfacl: command not found paquet acl non installé
setfacl: Operation not supported système de fichiers monté sans ACL (rare avec ext4) ; vérifier que /srv/partages est bien sur /dev/sdb1
Un fichier créé n’a pas le groupe du dossier bit setgid absent : ls -ld doit montrer un s dans les droits du groupe
visudo signale une erreur lire la ligne indiquée, choisir e pour corriger ; ne jamais forcer l’enregistrement
sudo: /etc/sudoers.d/web-ops is world writable ou ignoré droits du fichier : sudo chmod 440 /etc/sudoers.d/web-ops
su - nfournier : échec d’authentification mot de passe non défini : relancer la boucle chpasswd pour ce compte
