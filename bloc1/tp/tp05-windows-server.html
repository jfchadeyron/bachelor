TP 5 : Installer et administrer SRV-WIN-01

Installation de Windows Server 2025 dans le lab, configuration initiale en PowerShell, accès en bureau à distance, installation d'un rôle, ajout d'un disque de données, puis résolution de trois incidents introduits volontairement sur votre serveur.

Contexte

Hexalog a besoin d’un serveur Windows qui deviendra à la séance suivante son contrôleur de domaine. Avant cela, il doit être installé proprement, configuré, documenté, et vous devez savoir le dépanner.

Objectifs

  • Installer Windows Server en mode Expérience de bureau dans VirtualBox.
  • Réaliser la configuration initiale en PowerShell.
  • Accéder au serveur en bureau à distance via une redirection de ports.
  • Installer un rôle et vérifier le service associé.
  • Ajouter et préparer un disque de données.
  • Diagnostiquer et corriger des incidents avec les journaux.

Prérequis

  • L’ISO Windows Server 2025 Evaluation en français (fournie en séance).
  • 4 Go de RAM disponibles pour la VM (3 Go si votre PC n’a que 8 Go ; n’allumez alors que CLI-LNX-01 à côté).
  • Le DNS relevé à la séance 3 (dans votre journal).

Architecture en fin de TP

Étape 1. Créer la VM

Nouvelle machine virtuelle :

Champ Valeur
Nom SRV-WIN-01
Image ISO Windows Server 2025 Evaluation
Type / version Microsoft Windows / Windows 2025 (64 bits) ou la plus récente proposée
Ignorer l’installation automatique (Skip Unattended Installation) coché
Mémoire / processeurs 4096 Mo / 2
Disque VDI dynamique de 50 Go

Puis Configuration → Réseau → Adaptateur 1 : Réseau NAT → LAB-HEXALOG.

Étape 2. Installer Windows Server

  1. Démarrez la VM. Si le message Press any key to boot from CD or DVD apparaît, appuyez tout de suite sur une touche dans la fenêtre de la VM.
  2. Langue, format horaire, clavier : Français. Choisissez Installer Windows Server.
  3. Édition : Windows Server 2025 Standard Evaluation (Expérience de bureau).
  4. Type d’installation : Personnalisée, sur le disque de 50 Go (non alloué).
  5. Mot de passe du compte Administrateur : le mot de passe de lab (Windows exige 8 caractères minimum avec majuscules, minuscules, chiffres ou symboles).
  6. Pour ouvrir la session : menu Entrée → Clavier → Insérer Ctrl-Alt-Suppr (ou touche hôte + Suppr).

Installez ensuite les Additions invité (meilleur affichage, souris fluide, presse-papiers) : menu Périphériques → Insérer l’image CD des Additions invité, ouvrez le lecteur dans l’Explorateur, lancez VBoxWindowsAdditions.exe, acceptez, redémarrez. Réglez Périphériques → Presse-papiers partagé → Bidirectionnel.

Faites un snapshot 05-installation-propre.

Étape 3. Configuration initiale en PowerShell

Ouvrez PowerShell en tant qu’administrateur (clic droit sur le menu Démarrer → Terminal (administrateur) ou Windows PowerShell (administrateur) selon la version).

3.1, Observer l’état de départ

Machine : SRV-WIN-01 (PowerShell administrateur)
hostname
Get-NetIPConfiguration

Quelle adresse IP la carte a-t-elle ? Pourquoi ? (Rappel : le DHCP de LAB-HEXALOG a été désactivé à la séance 3.)

3.2, Nom, adresse, DNS

Machine : SRV-WIN-01 (PowerShell administrateur)
Get-NetAdapter                                   # vérifiez le nom de la carte, en général "Ethernet"
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 10.10.10.10 -PrefixLength 24 -DefaultGateway 10.10.10.1
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses X.X.X.X   # DNS relevé à la séance 3
Get-TimeZone                                     # doit être (UTC+01:00) Bruxelles, Copenhague, Madrid, Paris
Rename-Computer -NewName "SRV-WIN-01" -Restart

Après le redémarrage :

Machine : SRV-WIN-01 (PowerShell administrateur)
hostname
Get-NetIPConfiguration
Test-NetConnection 10.10.10.20                   # ping vers SRV-LNX-01
Resolve-DnsName deb.debian.org

3.3, Autoriser le ping et le bureau à distance

Machine : SRV-WIN-01 (PowerShell administrateur)
# Ping entrant
New-NetFirewallRule -DisplayName "Lab - Ping entrant" -Direction Inbound -Protocol ICMPv4 -IcmpType 8 -Action Allow

# Bureau à distance : activer puis ouvrir les règles prédéfinies
Set-ItemProperty -Path 'HKLM:\System\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections -Value 0
Enable-NetFirewallRule -Name RemoteDesktop-UserMode-In-TCP, RemoteDesktop-UserMode-In-UDP
Get-NetTCPConnection -State Listen -LocalPort 3389

Vous pouvez aussi faire ces réglages avec sconfig (option 7 pour le bureau à distance) : essayez de retrouver l’état actuel dans ce menu.

Depuis CLI-LNX-01 : ping -c 2 10.10.10.10 doit répondre.

3.4, Accès en bureau à distance depuis l’hôte

Ajoutez une redirection sur LAB-HEXALOG :

Nom Protocole IP hôte Port hôte IP invité Port invité
rdp-dc TCP 127.0.0.1 33890 10.10.10.10 3389

Sur le PC hôte Windows, lancez mstsc, ordinateur 127.0.0.1:33890, utilisateur Administrateur. Sur un hôte Linux, utilisez Remmina. Acceptez l’avertissement de certificat (certificat auto-signé du serveur).

Faites un snapshot 05-config-initiale.

Étape 4. Explorer le serveur

Dans le Gestionnaire de serveur, repérez : le serveur local et ses propriétés, les rôles installés, la liste des événements et des services. Puis en PowerShell :

Machine : SRV-WIN-01 (PowerShell administrateur)
Get-ComputerInfo | Select-Object WindowsProductName, OsVersion, CsName, CsDomain, OsTotalVisibleMemorySize
(Get-Service | Where-Object Status -eq 'Running').Count      # nombre de services démarrés
Get-WindowsFeature | Where-Object Installed | Select-Object Name, DisplayName
Get-HotFix | Sort-Object InstalledOn -Descending | Select-Object -First 5
Get-NetFirewallProfile | Select-Object Name, Enabled

Notez dans votre journal les réponses : version exacte, nombre de services démarrés, profil réseau actif.

Étape 5. Installer un rôle : IIS

Machine : SRV-WIN-01 (PowerShell administrateur)
Install-WindowsFeature Web-Server -IncludeManagementTools
Get-Service W3SVC, WAS
Get-Service W3SVC -RequiredServices
Set-Content -Path C:\inetpub\wwwroot\index.html -Value "<h1>Hexalog - SRV-WIN-01</h1>"
Get-NetFirewallRule -Name IIS-WebServerRole-HTTP-In-TCP | Select-Object DisplayName, Enabled, Action

Depuis CLI-LNX-01 :

Machine : CLI-LNX-01 (sysadmin)
curl http://10.10.10.10
nc -zv 10.10.10.10 80

Quel service est indispensable au démarrage de W3SVC ?

Étape 6. Ajouter un disque de données

  1. Éteignez la VM (Stop-Computer).
  2. Configuration → Stockage → Contrôleur SATA → Ajouter un disque dur → Créer : VDI, dynamique, 10 Go, nom SRV-WIN-01-DATA.
  3. Démarrez, puis préparez le disque (graphiquement avec diskmgmt.msc, ou en PowerShell) :
Machine : SRV-WIN-01 (PowerShell administrateur)
Get-Disk
Get-Disk | Where-Object PartitionStyle -eq 'RAW' |
    Initialize-Disk -PartitionStyle GPT -PassThru |
    New-Partition -DriveLetter E -UseMaximumSize |
    Format-Volume -FileSystem NTFS -NewFileSystemLabel "DATA" -Confirm:$false
Get-Volume

La lettre D: est en général prise par le lecteur optique : c’est pourquoi on utilise E:. Ce volume accueillera les partages de fichiers à la séance 7.

Étape 7. Mises à jour

Ouvrez Paramètres → Windows Update et relevez l’état. Ne lancez pas l’installation complète pendant la séance : quinze serveurs qui téléchargent plusieurs gigaoctets en même temps saturent la connexion du lycée. Relevez la date de la dernière mise à jour installée (Get-HotFix) et notez-la dans l’inventaire.

Faites un snapshot 05-avant-incidents.

Étape 8. Résoudre des incidents

M. CHADEYRON (ou votre binôme) exécute sur votre serveur un script qui introduit trois pannes. Ne regardez pas l’écran pendant ce temps. Le symptôme signalé par les utilisateurs :

« L’intranet sur SRV-WIN-01 ne répond plus, et le serveur n’arrive plus à joindre les sites Internet par leur nom. »

Pour chaque panne, remplissez une fiche d’incident (modèle sur Modèles de livrables) :

  1. symptôme constaté (commande et résultat) ;
  2. hypothèses ;
  3. tests réalisés et résultats ;
  4. cause identifiée, avec la preuve (événement, règle, configuration) ;
  5. correction appliquée ;
  6. vérification.

Outils à utiliser : Get-Service, sc.exe qc, l’Observateur d’événements (journal Système), Get-NetFirewallRule, Test-NetConnection, Resolve-DnsName, Get-DnsClientServerAddress.

Indice de méthode

Suivez l’ordre : le service tourne-t-il ? Si non, pourquoi (journal Système) ? Le port est-il joignable depuis CLI-LNX-01 ? Si non, quelle règle bloque ? Les noms se résolvent-ils ? Si non, quel DNS est configuré ?

Étape 9. Remise en état

IIS ne doit pas rester sur un futur contrôleur de domaine : désinstallez-le.

Machine : SRV-WIN-01 (PowerShell administrateur)
Uninstall-WindowsFeature Web-Server
Restart-Computer

Faites un snapshot 05-srv-win-pret et complétez l’inventaire (système, rôle, IP, disques, redirection rdp-dc).

Vérifications

Questions

  1. Pourquoi la carte avait-elle une adresse en 169.254.x.x au premier démarrage ?
  2. De quel service dépend W3SVC ? Comment l’avez-vous trouvé ?
  3. Quel ID d’événement vous a mis sur la piste de la première panne ?
  4. Pourquoi une règle de pare-feu de blocage est-elle plus dangereuse à oublier qu’une règle d’autorisation manquante ?
  5. Pourquoi ne met-on pas IIS sur un contrôleur de domaine ?

Dépannage

Symptôme Piste
L’installation ne démarre pas, écran noir ou No bootable medium ISO bien insérée ; appuyer sur une touche au message Press any key ; VM de type Windows 2025/2022 64 bits
Écran figé à « Préparation de Windows » très longtemps RAM insuffisante ou tortue verte (Hyper-V actif sur l’hôte)
New-NetIPAddress : l’objet existe déjà l’adresse est déjà posée : Get-NetIPAddress -InterfaceAlias Ethernet, la supprimer avec Remove-NetIPAddress puis recommencer
Pas d’accès RDP règle rdp-dc, bureau à distance activé, règles de pare-feu activées, VM allumée
Le nouveau disque n’apparaît pas ajouté sur le bon contrôleur, VM redémarrée ; Get-Disk
Clavier en QWERTY dans la VM vérifier la langue de saisie en bas à droite (FRA)
