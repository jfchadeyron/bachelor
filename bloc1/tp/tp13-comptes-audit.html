TP 13 : Arrivées, mobilités, départs et audit

Vous activez l'audit, vous traitez trois demandes des ressources humaines (une arrivée, une mobilité, un départ) sur Windows et sur Linux, vous menez une revue d'accès qui révèle des anomalies, et vous prouvez chaque action à partir des journaux.

Durée2 h 45
Machines virtuellesSRV-WIN-01, CLI-WIN-01, SRV-LNX-01
Cours associéSéance 13 : Cycle de vie des comptes et audit
Sommaire
  • Contexte
  • Partie A. Activer l’audit (30 min)
  • Partie B. Traiter les demandes des RH (1 h)
  • Partie C. Revue d’accès (45 min)

Contexte

Les RH d’Hexalog envoient trois demandes pour la semaine. En parallèle, le commissaire aux comptes demande une revue des accès et la preuve que les changements de comptes sont tracés.

Partie A. Activer l’audit (30 min)

Snapshots 13-avant-audit sur SRV-WIN-01 et SRV-LNX-01.

A.1, Stratégie d’audit des contrôleurs de domaine

Ouvrez Gestion des stratégies de groupe (Outils, ou gpmc.msc) → hexalog.local → Domain Controllers → sélectionnez Default Domain Controllers Policy → onglet Paramètres : notez ce qui est déjà audité (rubrique Stratégies locales → Stratégie d’audit, souvent vide).

Clic droit sur la Default Domain Controllers Policy → Modifier : Configuration ordinateur → Stratégies → Paramètres Windows → Paramètres de sécurité → Configuration avancée de la stratégie d’audit → Stratégies d’audit. Configurez (double-clic sur chaque sous-catégorie, cochez Configurer les événements d’audit suivants, puis Succès et/ou Échec) :

Catégorie Sous-catégorie Succès Échec
Connexion de compte Valider les informations d’identification oui oui
Gestion des comptes Gestion des comptes d’utilisateur oui oui
Gestion des comptes Gestion des groupes de sécurité oui oui
Ouverture/fermeture de session Ouvrir la session oui oui
Ouverture/fermeture de session Verrouillage du compte oui
Accès aux objets Système de fichiers oui oui
Changement de stratégie Auditer la modification de la stratégie oui

Fermez l’éditeur, tapez gpupdate /force dans l’Invite de commandes du serveur, puis revenez à l’onglet Paramètres de la stratégie (F5) : les sous-catégories configurées apparaissent.

Agrandissez enfin le journal Sécurité : Observateur d’événements → Journaux Windows → clic droit sur Sécurité → Propriétés → Taille maximale du journal : 262144 Ko (256 Mo) → OK.

A.2, Auditer le dossier RH

Propriétés de C:\Partages\RH → Sécurité → Avancé → onglet Audit → Continuer → Ajouter :

  • principal : Utilisateurs authentifiés ; type : Tout ; s’applique à : ce dossier, les sous-dossiers et les fichiers ;
  • afficher les autorisations avancées, cocher : Création de fichier/écriture de données, Suppression de sous-dossier et fichier, Suppression.

A.3, Linux : auditd

Machine : SRV-LNX-01 (sysadmin)
sudo apt install -y auditd
sudo tee /etc/audit/rules.d/hexalog.rules > /dev/null <<'EOF'
-w /etc/passwd -p wa -k comptes
-w /etc/group -p wa -k comptes
-w /etc/sudoers -p wa -k sudoers
-w /etc/sudoers.d/ -p wa -k sudoers
-w /srv/partages/rh -p wa -k partage-rh
EOF
sudo augenrules --load
sudo auditctl -l

Partie B. Traiter les demandes des RH (1 h)

Pour chaque demande, écrivez d’abord la liste des actions (Windows et Linux), puis réalisez-les, puis vérifiez. Notez l’heure de chaque action : elle servira à la partie D.

Demande 1. Arrivée

Léa Fontaine rejoint le service Comptabilité comme assistante comptable, en contrat à durée déterminée de six mois. Elle doit accéder aux dossiers Commun et Comptabilite.

Indications, dans Utilisateurs et ordinateurs Active Directory :

  1. Clic droit sur t.petit (assistant comptable) → Copier… → Léa Fontaine, l.fontaine, mot de passe de lab (doit changer le mot de passe coché en entreprise, décoché dans le lab). La copie reprend l’OU et le groupe GG_Comptabilite.
  2. Propriétés de l.fontaine → onglet Compte → Date d’expiration du compte : Fin de → la date dans six mois.
  3. Onglet Organisation : fonction Assistante comptable, service Comptabilite.
  4. Onglet Membre de : vérifiez GG_Comptabilite.
Machine : SRV-LNX-01 (sysadmin)
sudo useradd -m -s /bin/bash -c "Lea Fontaine" -G compta,salaries -e "$(date -d '+6 months' +%F)" lfontaine
sudo passwd lfontaine
sudo chage -l lfontaine          # date d'expiration du compte

Prouvez les accès de Léa : session HEXALOG\l.fontaine sur CLI-WIN-01 (dossiers Commun et Comptabilite ouverts, RH refusé), et sudo -u lfontaine sur SRV-LNX-01.

Demande 2. Mobilité

Emma Garcia quitte l’Exploitation pour devenir chargée de formation aux Ressources humaines, dès aujourd’hui.

À vous de faire, dans les propriétés d’e.garcia : onglet Organisation (service, fonction), onglet Membre de (ajouter le nouveau groupe, retirer l’ancien) ; sous Linux, gpasswd -d et usermod -aG. Prouvez qu’Emma accède au dossier RH et n’accède plus au dossier Exploitation, sur les deux serveurs.

Demande 3. Départ

Julien Moreau quitte l’entreprise ce soir. Ses fichiers doivent être conservés pour son successeur.

Procédure attendue, dans Utilisateurs et ordinateurs Active Directory :

  1. Une seule fois : clic droit sur l’OU HEXALOG → Nouveau → Unité d’organisation : Desactives.
  2. Clic droit sur j.moreau → Désactiver le compte (une flèche vers le bas apparaît sur son icône).
  3. Clic droit → Réinitialiser le mot de passe : un mot de passe long et aléatoire, que personne ne garde.
  4. Propriétés → onglet Membre de : retirez tous les groupes GG_… (laissez Utilisateurs du domaine, son groupe principal).
  5. Onglet Général → Description : Départ - demande RH n° ... - suppression prévue à J+90.
  6. Clic droit → Déplacer… → HEXALOG → Desactives.
Machine : SRV-LNX-01 (sysadmin)
sudo usermod -L jmoreau                        # verrouiller le mot de passe
sudo chage -E 0 jmoreau                        # expirer le compte
sudo pkill -u jmoreau || true                  # fermer ses éventuelles sessions
sudo find /srv/partages /home -user jmoreau    # ses fichiers : à transmettre
sudo ls -l /home/jmoreau/.ssh 2>/dev/null      # clés à révoquer ?
sudo passwd -S jmoreau ; sudo chage -l jmoreau

Vérifiez que Julien ne peut plus s’authentifier (session sur CLI-WIN-01 : « Votre compte a été désactivé » ; su - jmoreau : échec).

Partie C. Revue d’accès (45 min)

M. CHADEYRON (ou votre binôme) exécute sur vos serveurs un script qui introduit quelques anomalies, comme dans une entreprise réelle. Votre revue doit les trouver.

C.1, Revue Windows

Dans Utilisateurs et ordinateurs Active Directory :

  1. Les groupes à privilèges : onglet Membres de Admins du domaine, Administrateurs de l’entreprise et Administrateurs du schéma (conteneur Users), puis Administrateurs, Opérateurs de serveur et Opérateurs de sauvegarde (conteneur Builtin). Qui ne devrait pas y être ?
  2. Les comptes qui posent question : clic droit sur Requêtes enregistrées → Nouveau → Requête → nom Revue → Définir la requête → Requêtes courantes → cochez Comptes désactivés, puis faites d’autres requêtes avec Mot de passe sans date d’expiration et Nombre de jours depuis la dernière ouverture de session (30). Les résultats s’affichent dans la console.
  3. Les comptes hors de l’arborescence : regardez le conteneur Users (seuls les comptes et groupes créés par Windows devraient s’y trouver) et l’OU Utilisateurs (les services et fonctions sont-ils cohérents ? menu Affichage → Ajouter/Supprimer des colonnes : ajoutez Description, Service, Fonction).
  4. Les groupes des services : onglet Membres de chaque groupe GG_… de l’OU Groupes. Chacun est-il dans le groupe de son service, et seulement celui-là ?
  5. Les groupes de droits : onglet Membres de chaque groupe DL_…. En AGDLP, on n’y trouve que des groupes GG_…, conformes au tableau du TP 7. Une personne directement dans un DL_… est une anomalie.

Puis, dans l’Explorateur de SRV-WIN-01 : propriétés de chaque dossier de C:\Partages → Sécurité. En AGDLP, seuls des groupes DL_… y reçoivent des droits (plus les administrateurs et SYSTEM). Une permission donnée directement à une personne, ou à un groupe GG_…, est une anomalie.

C.2, Extractions Linux

Machine : SRV-LNX-01 (sysadmin)
awk -F: '$3 >= 1000 && $3 < 60000 {print $1, $3, $7}' /etc/passwd     # comptes humains
getent group sudo ssh-users web-ops salaries
sudo cat /etc/sudoers.d/*
for u in $(awk -F: '$3 >= 1000 && $3 < 60000 {print $1}' /etc/passwd) ; do sudo passwd -S "$u" ; done   # P actif, L verrouillé, NP sans mot de passe
sudo find /home -name authorized_keys -exec sh -c 'echo "== $1" ; cat "$1"' _ {} \;
for d in /srv/partages/* ; do getfacl -p "$d" | grep -E '^(# file|user:[a-z]|group:)' ; done

C.3, Rapport de revue

Pour chaque anomalie : constat (avec la capture ou la commande qui le prouve), risque, action proposée, validation (qui doit décider), action réalisée. Corrigez ce qui relève de l’administration, et listez ce qui doit être validé par un responsable.

Partie D. Prouver par les journaux (30 min)

Générez un accès audité au dossier RH : ouvrez la session HEXALOG\s.laurent sur CLI-WIN-01, créez un fichier entretien.txt dans \\SRV-WIN-01\Partages\RH, écrivez une ligne, enregistrez, puis supprimez-le.

Puis retrouvez les événements de toute la séance, sur SRV-WIN-01 : Observateur d’événements → Journaux Windows → Sécurité → Filtrer le journal actuel :

  • Journalisé : Dernières 12 heures ; ID : 4720,4722,4724,4725,4728,4729,4732,4733,4738,4740,4767 → OK. Triez par date (colonne Date et heure) et ouvrez chaque événement : qui a fait quoi, sur quel compte ;
  • puis ID 4663 : les accès au dossier RH (fichier, compte, type d’accès).

Pour revenir souvent à ce filtre, enregistrez-le : volet de droite, Créer une vue personnalisée.

Machine : SRV-LNX-01 (sysadmin)
sudo journalctl -t useradd -t usermod -t userdel -t groupadd -t gpasswd -t passwd -t chage --since today --no-pager
sudo ausearch -k comptes -i | tail -n 30
sudo ausearch -k sudoers -i

Complétez le journal d’audit de la séance : pour chaque action de la partie B et chaque anomalie de la partie C, l’heure, le serveur, l’auteur, l’événement ou la ligne de journal qui le prouve.

Dépannage

Symptôme Piste
Les réglages d’audit ne s’appliquent pas gpupdate /force ; vérifier que c’est bien la Default Domain Controllers Policy (sous Domain Controllers) qui a été modifiée
Aucun événement 4663 sous-catégorie Système de fichiers non activée, ou pas d’entrée dans l’onglet Audit du dossier
Déplacer : accès refusé vous êtes connecté avec un compte sans droits d’administration du domaine ; la protection contre la suppression accidentelle n’empêche pas de déplacer un objet dans une OU
Pas d’événement 4663 alors que le fichier a été créé la liste d’audit (A.2) manque sur RH, ou la stratégie n’est pas encore appliquée (gpupdate /force)
augenrules --load ne charge rien syntaxe du fichier de règles ; sudo auditctl -l ; le service auditd est-il actif ?
useradd -e refuse la date format AAAA-MM-JJ attendu
