TP 11 : Politiques de mots de passe et verrouillage

Vous appliquez la politique d'authentification d'Hexalog : stratégie de domaine par GPO, stratégie renforcée pour les administrateurs, scénarios de verrouillage, de déverrouillage et de réinitialisation avec leurs traces, puis l'équivalent sous Linux avec chage et PAM. Une étude de cas termine la séance.

Durée2 h 30
Machines virtuellesSRV-WIN-01, CLI-WIN-01, SRV-LNX-01
Cours associéSéance 11 : Authentification : concepts et politiques

Contexte

Le RSSI d’Hexalog a rédigé la politique suivante, que vous devez mettre en œuvre et prouver.

Règle Utilisateurs Administrateurs (Admins du domaine)
Longueur minimale 12 16
Complexité oui oui
Historique 12 24
Durée de vie maximale 365 jours 180 jours
Durée de vie minimale 1 jour 1 jour
Seuil de verrouillage 5 échecs 3 échecs
Durée de verrouillage et fenêtre d’observation 15 min 30 min

Partie A. Windows

Faites un snapshot 11-avant-politiques de SRV-WIN-01. Toute la partie A se fait avec les consoles graphiques : Gestion des stratégies de groupe, Centre d’administration Active Directory, Utilisateurs et ordinateurs Active Directory et Observateur d’événements (menu Outils du Gestionnaire de serveur).

A.1, État initial

Ouvrez Gestion des stratégies de groupe (Outils, ou gpmc.msc) → Forêt → Domaines → hexalog.local → sélectionnez Default Domain Policy → onglet Paramètres. Dépliez Configuration ordinateur → Stratégies → Paramètres Windows → Paramètres de sécurité → Stratégies de comptes.

Notez les valeurs actuelles dans votre journal.

A.2, La stratégie de domaine par GPO

Clic droit sur Default Domain Policy → Modifier. Dans l’éditeur, allez dans Configuration ordinateur → Stratégies → Paramètres Windows → Paramètres de sécurité → Stratégies de comptes :

  • Stratégie de mot de passe : réglez les cinq valeurs de la colonne Utilisateurs (double-clic sur chaque paramètre) ;
  • Stratégie de verrouillage du compte : seuil 5, durée 15 minutes, réinitialisation du compteur après 15 minutes.

Fermez l’éditeur. Pour appliquer tout de suite, tapez gpupdate /force dans l’Invite de commandes du serveur (sinon, la stratégie s’applique d’elle-même en quelques minutes). Revenez sur l’onglet Paramètres de la Default Domain Policy (F5) : les nouvelles valeurs apparaissent.

Pourquoi la Default Domain Policy ?

La politique de mots de passe des comptes du domaine se règle dans la stratégie liée au domaine : c’est elle qui fait foi. Une valeur modifiée ailleurs finirait par être écrasée par cette GPO.

Clic droit sur la Default Domain Policy → Enregistrer le rapport : gardez ce rapport pour votre dossier.

A.3, La stratégie renforcée des administrateurs

Une GPO s’applique à tout le domaine. Pour des règles plus strictes réservées aux administrateurs, on crée une stratégie de mot de passe affinée (PSO) dans le Centre d’administration Active Directory (Outils, ou dsac.exe) :

  1. Dans le volet de gauche : hexalog (local) → System → Password Settings Container.
  2. Volet de droite : Nouveau → Paramètres de mot de passe.
  3. Nom PSO-Admins, priorité 10. Cochez et réglez : longueur minimale 16, complexité, historique 24, durée de vie minimale 1 jour, durée de vie maximale 180 jours ; Appliquer la stratégie de verrouillage de compte : 3 tentatives, réinitialisation du compteur après 30 minutes, compte verrouillé pendant 30 minutes.
  4. En bas, S’applique directement à → Ajouter → Admins du domaine → Vérifier les noms → OK. Puis OK.

Vérifiez à qui elle s’applique : dans le Centre d’administration, cherchez adm.nfournier (zone Recherche globale), clic droit → Afficher les paramètres de mot de passe résultants : PSO-Admins. Faites de même pour a.martin : aucune PSO, c’est la stratégie du domaine qui s’applique.

Vérifiez que la politique est appliquée : dans dsa.msc, clic droit sur adm.nfournier → Réinitialiser le mot de passe → Court-Mdp1! (11 caractères). Quel message obtenez-vous ? Annulez.

A.4, Scénario : verrouillage d’un compte

Thomas Petit appelle le support : « Je ne peux plus me connecter. » Reproduisez la situation sur CLI-WIN-01 : à l’écran de connexion, Autre utilisateur, HEXALOG\t.petit, et tapez six fois un mauvais mot de passe. Essayez ensuite avec le bon mot de passe : que se passe-t-il ?

Côté serveur, menez l’enquête :

  1. dsa.msc → propriétés de t.petit → onglet Compte : la case Déverrouiller le compte indique que le compte est verrouillé.
  2. Observateur d’événements → Journaux Windows → Sécurité → clic droit → Filtrer le journal actuel → dans la zone des ID, tapez 4740 → OK. Ouvrez l’événement : il indique le compte verrouillé et le nom de l’ordinateur appelant, d’où venaient les échecs.
  3. Filtrez ensuite sur 4625,4771,4776 : les échecs d’authentification qui ont précédé.

Puis traitez la demande comme le ferait le support : vérification d’identité (décrivez comment), puis dans l’onglet Compte de t.petit, cochez Déverrouiller le compte → Appliquer. Vérifiez sur CLI-WIN-01 que Thomas peut se connecter, et retrouvez l’événement 4767 (déverrouillage) dans le journal Sécurité.

Sans CLI-WIN-01

Si votre PC ne peut pas faire tourner le poste Windows en même temps, provoquez les échecs depuis CLI-LNX-01 : sudo apt install -y smbclient, puis six fois smbclient -L //10.10.10.10 -U 'HEXALOG\t.petit%MauvaisMotDePasse'.

A.5, Scénario : réinitialisation du mot de passe

Thomas a oublié son mot de passe. Dans dsa.msc, clic droit sur t.petit → Réinitialiser le mot de passe : un mot de passe temporaire conforme, et cochez L’utilisateur doit changer le mot de passe à la prochaine ouverture de session.

Ouvrez la session de t.petit sur CLI-WIN-01 avec le mot de passe temporaire : que demande Windows ? Choisissez un nouveau mot de passe.

Pour la suite des TP, remettez ensuite le mot de passe de lab (Réinitialiser le mot de passe, case doit changer décochée). Retrouvez l’événement 4724 (réinitialisation) dans le journal Sécurité.

Partie B. Linux

Faites un snapshot 11-avant-pam de SRV-LNX-01. Gardez une deuxième session ouverte avec sudo -i pendant toute la partie B.

B.1, Expiration

Machine : SRV-LNX-01 (sysadmin)
grep -E '^PASS_(MAX|MIN|WARN)' /etc/login.defs
sudo chage -l amartin
sudo chage -M 365 -m 1 -W 14 amartin
sudo chage -l amartin
sudo passwd -e amartin                 # expiration immédiate
su - amartin                           # le changement est exigé

B.2, Qualité des mots de passe

Machine : SRV-LNX-01 (sysadmin)
sudo apt install -y libpam-pwquality
grep pwquality /etc/pam.d/common-password     # le module a été ajouté automatiquement
sudo nano /etc/security/pwquality.conf

Réglez (en décommentant les lignes concernées) :

Fichier : /etc/security/pwquality.conf
minlen = 12
minclass = 3
dictcheck = 1
usercheck = 1
enforce_for_root

Testez en tant qu’utilisateur :

Machine : SRV-LNX-01 (sysadmin)
su - cdubois
passwd            # essayez : soleil, Soleil123, un mot de passe contenant cdubois, puis une vraie phrase de passe
exit

Notez chaque message de refus (BAD PASSWORD: ...).

Partie C. Étude de cas (30 min)

Hexalog prévoit les évolutions suivantes :

  1. les commerciaux doivent accéder depuis l’extérieur à l’application de suivi des colis et aux partages de fichiers ;
  2. l’entreprise passe à une messagerie en ligne (SaaS) et veut que les salariés utilisent leur compte habituel ;
  3. les deux administrateurs gèrent les serveurs sur site et la console cloud de l’application ;
  4. l’entrepôt utilise des postes partagés par plusieurs préparateurs, avec des gants.

Pour chaque point, proposez les mécanismes d’authentification (facteurs, MFA et type de second facteur, SSO ou non, politique de mot de passe, verrouillage) et justifiez en termes de risques couverts et de contraintes d’usage. Une page maximum, sous forme de tableau.

Pour aller plus loin

Verrouillage des comptes Linux avec pam_faillock

À faire uniquement avec un snapshot et une session root ouverte. Dans /etc/pam.d/common-auth, encadrez la ligne pam_unix.so ainsi (les autres lignes du fichier restent en place) :

Fichier : /etc/pam.d/common-auth (extrait)
auth    requisite                       pam_faillock.so preauth
auth    [success=1 default=ignore]      pam_unix.so nullok
auth    [default=die]                   pam_faillock.so authfail
auth    sufficient                      pam_faillock.so authsucc

Ajoutez account required pam_faillock.so en tête de /etc/pam.d/common-account, réglez deny = 5 et unlock_time = 900 dans /etc/security/faillock.conf, puis testez avec su - cdubois et de mauvais mots de passe. Consultez et réinitialisez le compteur avec sudo faillock --user cdubois et sudo faillock --user cdubois --reset.

Second facteur TOTP sur SSH

Le paquet libpam-google-authenticator ajoute un code à 6 chiffres (application d’authentification sur téléphone) en plus de la clé SSH : AuthenticationMethods publickey,keyboard-interactive dans la configuration de sshd. À tester sur une VM dédiée : une erreur de configuration bloque tous les accès SSH.

Un poste Linux dans le domaine

Les paquets realmd, sssd et adcli permettent de joindre CLI-LNX-01 au domaine hexalog.local (sudo realm join -U Administrateur hexalog.local), puis d’ouvrir une session Linux avec un compte Active Directory et d’obtenir un ticket Kerberos (kinit, klist). C’est l’illustration concrète du SSO dans un environnement mixte.
