TP 6 : Un poste Windows 11 dans le domaine

Contexte

Depuis le TP 5, Hexalog a son domaine hexalog.local sur le contrôleur SRV-WIN-01. Il manque deux choses : un poste de travail pour les salariés, et des comptes pour ces salariés. C’est l’objet de ce TP. Demain, au TP 7, vous utiliserez ce poste et ces comptes pour tester les droits d’accès aux dossiers partagés.

Organisation de la séance

  1. Dès le début : étape 1 (vérifier le serveur) puis étape 2 (créer la VM et lancer l’installation de Windows 11). L’installation tourne seule pendant 20 à 30 minutes : c’est le moment du cours.
  2. Pendant que Windows 11 s’installe : étape 3, sur SRV-WIN-01, pour créer les comptes.
  3. Ensuite : étapes 4 à 7 sur le poste.
  4. Pas terminé ? Vous continuez au créneau de 13 h 30. Pour le TP 7, il faut : les comptes et les groupes (étape 3) et CLI-WIN-01 dans le domaine (étape 6).

Objectifs

  • Installer un poste Windows 11 Pro dans le lab.
  • Configurer son réseau pour qu’il trouve le domaine (DNS).
  • Créer des unités d’organisation, des groupes et des utilisateurs dans l’annuaire, avec la console Utilisateurs et ordinateurs Active Directory.
  • Faire entrer le poste dans le domaine.
  • Ouvrir une session avec un compte du domaine et vérifier qui l’a authentifiée.

Étape 5. Le réseau du poste

Pour trouver le domaine, le poste doit poser la question au DNS du contrôleur de domaine. C’est la règle numéro un : un poste dont le DNS n’est pas le contrôleur de domaine ne peut pas rejoindre le domaine.

  1. Touches Windows + R, tapez ncpa.cpl, Entrée.
  2. Clic droit sur Ethernet → Propriétés → double-clic sur Protocole Internet version 4 (TCP/IPv4).
  3. Utiliser l’adresse IP suivante : adresse 10.10.10.100, masque 255.255.255.0, passerelle 10.10.10.1.
  4. Utiliser l’adresse de serveur DNS suivante : serveur préféré 10.10.10.10, serveur auxiliaire vide. OK, OK.

Vérifiez la configuration : Paramètres → Réseau et Internet → Ethernet affiche l’adresse IPv4 et le serveur DNS. Puis testez que le poste trouve le domaine. Ouvrez l’Invite de commandes (touches Windows + R, tapez cmd, Entrée) :

Machine : CLI-WIN-01 (Invite de commandes, session localadmin)
nslookup hexalog.local
nslookup srv-win-01.hexalog.local

Les deux réponses doivent donner l’adresse 10.10.10.10. La ligne « Serveur : UnKnown » n’a pas d’importance.

Un seul DNS : celui du domaine

N’ajoutez pas de DNS auxiliaire (celui de la box, 8.8.8.8…) : le poste pourrait l’interroger, et ce DNS ne connaît pas hexalog.local. Les noms d’Internet restent accessibles : le contrôleur les demande lui-même à l’extérieur.

Le ping 10.10.10.10 peut ne pas répondre : le pare-feu de Windows Server bloque le ping par défaut. Ce n’est pas une panne. Le bon test, c’est nslookup.

Étape 6. Faire entrer le poste dans le domaine

  1. Touches Windows + R, tapez sysdm.cpl, Entrée. Onglet Nom de l’ordinateur → Modifier…
  2. Nom de l’ordinateur : CLI-WIN-01 (s’il ne l’est pas déjà).
  3. Membre d’un domaine : hexalog.local → OK.
  4. Windows demande un compte autorisé à ajouter des ordinateurs au domaine : HEXALOG\Administrateur et son mot de passe.
  5. Message « Bienvenue dans le domaine hexalog.local » → OK → redémarrez.

Sur SRV-WIN-01, dans dsa.msc, ouvrez le dossier Computers (appuyez sur F5 pour actualiser) : le compte ordinateur CLI-WIN-01 vient d’y être créé. Déplacez-le dans l’OU HEXALOG → Ordinateurs (clic droit → Déplacer, ou glisser-déposer).

Pourquoi faut-il le compte administrateur du domaine ?

Faire entrer un poste, c’est créer un objet dans l’annuaire (le compte ordinateur). Seul un compte du domaine qui en a le droit peut le faire. Le compte local localadmin est administrateur du poste, mais il n’est rien pour le domaine.

Étape 7. Ouvrir une session avec un compte du domaine

7.1, Une session d’Alice

Sur l’écran de connexion de CLI-WIN-01, cliquez sur Autre utilisateur (en bas à gauche), puis tapez HEXALOG\a.martin et le mot de passe de lab. La première connexion d’un compte prend une ou deux minutes : Windows crée son profil sur le poste.

Ouvrez l’Invite de commandes (touches Windows + R, cmd) et tapez ces quatre commandes, une par une :

Machine : CLI-WIN-01 (Invite de commandes, session a.martin)
whoami
whoami /groups
echo %LOGONSERVER%
hostname
Commande Résultat attendu Ce que cela montre
whoami hexalog\a.martin la session est celle d’un compte du domaine
whoami /groups dans la liste : HEXALOG\GG_Comptabilite, HEXALOG\Utilisateurs du domaine les groupes d’Alice, reçus du contrôleur à l’ouverture de session
echo %LOGONSERVER% \\SRV-WIN-01 le contrôleur qui a vérifié le mot de passe
hostname CLI-WIN-01 le poste sur lequel elle travaille

Vous pouvez aussi voir le compte de la session dans Paramètres → Comptes → Vos informations.

Déconnectez-vous : menu Démarrer → clic sur le nom de l’utilisateur → Se déconnecter.

7.2, Le compte local existe toujours

Ouvrez une session avec .\localadmin (le préfixe .\ signifie « ce poste-ci »). Dans l’Invite de commandes, whoami affiche cli-win-01\localadmin. Ce compte n’existe que sur ce poste : il ne servirait à rien sur un autre ordinateur du domaine. Déconnectez-vous.

7.3, Le serveur décide pour tous les postes

  1. Sur SRV-WIN-01, dans dsa.msc : clic droit sur j.moreau → Désactiver le compte.
  2. Sur CLI-WIN-01, essayez d’ouvrir une session avec HEXALOG\j.moreau : refusé, « Votre compte a été désactivé ».
  3. Réactivez le compte (clic droit → Activer le compte), puis ouvrez la session de j.moreau : elle fonctionne.

Vous n’avez rien modifié sur le poste : c’est l’annuaire qui décide, pour tous les ordinateurs du domaine à la fois.

7.4, Sauvegarder

Faites un snapshot 06-domaine de chacune des deux VM et complétez votre inventaire (CLI-WIN-01 : système, adresse, DNS, domaine ; comptes créés).

Snapshots et domaine

Le poste et le contrôleur partagent un secret qui change automatiquement tous les 30 jours. Si vous restaurez un ancien snapshot de l’un des deux, ce secret peut ne plus correspondre : voir le dépannage (« relation d’approbation »). Prenez toujours les snapshots des deux machines au même moment.

Pour information : la même chose en PowerShell

Ce que vous avez fait à la souris peut s’automatiser. Rien d’obligatoire ici : c’est pour voir à quoi ressemble un script d’administration.

Créer un compte et le mettre dans son groupe :

Machine : SRV-WIN-01 (PowerShell administrateur)
New-ADUser -Name "Léa Test" -SamAccountName l.test -UserPrincipalName l.test@hexalog.local `
    -Path "OU=Utilisateurs,OU=HEXALOG,DC=hexalog,DC=local" `
    -AccountPassword (Read-Host -AsSecureString "Mot de passe") -Enabled $true
Add-ADGroupMember -Identity GG_Comptabilite -Members l.test
Remove-ADUser l.test        # supprimer le compte de test (confirmer par O)

Joindre un poste au domaine (à lancer sur un poste, pas sur CLI-WIN-01 qui est déjà membre) :

Machine : poste à joindre (PowerShell administrateur)
Add-Computer -DomainName hexalog.local -Credential HEXALOG\Administrateur `
    -OUPath "OU=Ordinateurs,OU=HEXALOG,DC=hexalog,DC=local" -Restart
