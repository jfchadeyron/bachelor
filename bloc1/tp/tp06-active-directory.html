TP 6 : L'annuaire Hexalog

Vous transformez SRV-WIN-01 en contrôleur du domaine hexalog.lan, vous faites du DC le serveur DNS du lab, puis vous construisez l'annuaire d'Hexalog : unités d'organisation, groupes par service, comptes des salariés importés depuis un fichier, compte d'administration séparé. Vous terminez par des tests d'appartenance et d'authentification.

Durée2 h 30

Contexte

Hexalog compte cinq services et dix salariés dans ce premier périmètre (liste dans le fichier CSV fourni). La DSI veut un annuaire propre, organisé, où les droits seront attribués par groupes selon la méthode AGDLP.

Objectifs

  • Promouvoir un serveur en contrôleur de domaine et vérifier la promotion.
  • Configurer le DNS du domaine (redirecteur, enregistrements des serveurs Linux).
  • Créer une structure d’OU conforme au schéma de l’entreprise.
  • Créer des groupes globaux, des utilisateurs (un à la main, les autres par import CSV) et un compte d’administration.
  • Vérifier les appartenances et tester l’authentification d’un utilisateur du domaine.

Architecture en fin de TP

Étape 1. Promouvoir SRV-WIN-01

Faites un snapshot 06-avant-promotion. Puis, dans PowerShell administrateur :

Machine : SRV-WIN-01 (PowerShell administrateur)
Install-WindowsFeature AD-Domain-Services -IncludeManagementTools

Install-ADDSForest -DomainName "hexalog.lan" -DomainNetbiosName "HEXALOG" -InstallDns `
    -SafeModeAdministratorPassword (Read-Host -AsSecureString "Mot de passe DSRM") -Force

Le mot de passe DSRM (mode de restauration des services d’annuaire) sert à réparer l’annuaire en cas de problème grave : notez-le dans votre journal comme le mot de passe de lab. Des avertissements s’affichent (délégation DNS impossible, etc.) : ils sont normaux dans un lab. Le serveur redémarre tout seul.

Avec l'interface graphique

Le même résultat s’obtient dans le Gestionnaire de serveur : Gérer → Ajouter des rôles → Services AD DS, puis le drapeau jaune « Promouvoir ce serveur en contrôleur de domaine » → Ajouter une nouvelle forêt. À la dernière page, le bouton Afficher le script montre la commande PowerShell équivalente.

Reconnectez-vous en tant que HEXALOG\Administrateur (même mot de passe qu’avant).

Étape 2. Vérifier la promotion et le DNS

Machine : SRV-WIN-01 (PowerShell administrateur)
Get-ADDomain | Select-Object DNSRoot, NetBIOSName, DomainMode
Get-ADDomainController | Select-Object HostName, IPv4Address, IsGlobalCatalog
Get-DnsClientServerAddress -InterfaceAlias Ethernet -AddressFamily IPv4     # le DC s'interroge lui-même
Resolve-DnsName -Type SRV _ldap._tcp.dc._msdcs.hexalog.lan                  # enregistrements SRV du domaine
Get-DnsServerForwarder                                                      # redirecteur vers l'extérieur

Si aucun redirecteur n’apparaît, ajoutez le DNS relevé à la séance 3, puis testez la résolution externe :

Machine : SRV-WIN-01 (PowerShell administrateur)
Add-DnsServerForwarder -IPAddress X.X.X.X
Resolve-DnsName deb.debian.org
dcdiag /q                         # n'affiche que les erreurs ; quelques avertissements sont possibles dans un lab

Ajoutez les serveurs Linux dans la zone DNS :

Machine : SRV-WIN-01 (PowerShell administrateur)
Add-DnsServerResourceRecordA -ZoneName "hexalog.lan" -Name "srv-lnx-01" -IPv4Address 10.10.10.20
Add-DnsServerResourceRecordA -ZoneName "hexalog.lan" -Name "cli-lnx-01" -IPv4Address 10.10.10.101
Add-DnsServerResourceRecordCName -ZoneName "hexalog.lan" -Name "intranet" -HostNameAlias "srv-lnx-01.hexalog.lan"
Get-DnsServerResourceRecord -ZoneName "hexalog.lan" -RRType A

Étape 3. Le DC devient le DNS du lab

Sur SRV-LNX-01 et CLI-LNX-01, remplacez le contenu de /etc/resolv.conf :

Fichier : /etc/resolv.conf (SRV-LNX-01 et CLI-LNX-01)
search hexalog.lan
nameserver 10.10.10.10

Puis testez depuis CLI-LNX-01 :

Machine : CLI-LNX-01 (sysadmin)
dig +short srv-win-01.hexalog.lan
dig +short -t SRV _ldap._tcp.hexalog.lan
dig +short intranet.hexalog.lan
ping -c 2 srv-lnx-01                 # nom court complété grâce à la ligne search
dig +short deb.debian.org            # résolution externe via le redirecteur du DC

Étape 4. Les unités d’organisation

Gardez la même fenêtre PowerShell pour toute la suite (les variables $dom et $base y sont définies).

Machine : SRV-WIN-01 (PowerShell administrateur)
$dom  = "DC=hexalog,DC=lan"
New-ADOrganizationalUnit -Name "HEXALOG" -Path $dom
$base = "OU=HEXALOG,$dom"

"Utilisateurs","Groupes","Ordinateurs","Admins" |
    ForEach-Object { New-ADOrganizationalUnit -Name $_ -Path $base }
"Direction","RH","Comptabilite","Exploitation","Informatique" |
    ForEach-Object { New-ADOrganizationalUnit -Name $_ -Path "OU=Utilisateurs,$base" }
"Globaux","DomaineLocal" |
    ForEach-Object { New-ADOrganizationalUnit -Name $_ -Path "OU=Groupes,$base" }
"Serveurs","Postes" |
    ForEach-Object { New-ADOrganizationalUnit -Name $_ -Path "OU=Ordinateurs,$base" }

Get-ADOrganizationalUnit -Filter * -SearchBase $base | Select-Object DistinguishedName

Ouvrez Utilisateurs et ordinateurs Active Directory (dsa.msc) et vérifiez l’arborescence. Le compte ordinateur SRV-WIN-01 est dans l’OU Domain Controllers : il doit y rester.

Étape 5. Les groupes globaux

Machine : SRV-WIN-01 (PowerShell administrateur)
"Direction","RH","Comptabilite","Exploitation","Informatique" | ForEach-Object {
    New-ADGroup -Name "GG_$_" -GroupScope Global -GroupCategory Security `
        -Path "OU=Globaux,OU=Groupes,$base" -Description "Salariés du service $_"
}
Get-ADGroup -Filter 'Name -like "GG_*"' | Select-Object Name, GroupScope

Étape 6. Un utilisateur à la main

Ouvrez le Centre d’administration Active Directory (dsac.exe). Dans hexalog (local) → HEXALOG → Utilisateurs → Exploitation, créez :

  • prénom Hugo, nom Blanc, identifiant h.blanc, UPN h.blanc@hexalog.lan ;
  • fonction : Stagiaire logistique ; service : Exploitation ;
  • mot de passe initial au choix (respectant la complexité), compte désactivé (il arrive le mois prochain).

Ajoutez-le à GG_Exploitation. Puis déroulez en bas de la fenêtre la visionneuse de l’historique Windows PowerShell : recopiez dans votre journal la commande New-ADUser générée par l’outil.

Étape 7. Importer les salariés

Téléchargez le fichier des salariés et regardez son contenu :

Machine : SRV-WIN-01 (PowerShell administrateur)
New-Item -ItemType Directory -Path C:\Scripts -Force
Invoke-WebRequest -UseBasicParsing -Uri "https://jfchadeyron.github.io/bachelor/bloc1/fichiers/utilisateurs-hexalog.csv" -OutFile C:\Scripts\utilisateurs-hexalog.csv
Import-Csv C:\Scripts\utilisateurs-hexalog.csv -Delimiter ';' -Encoding UTF8 | Format-Table

Si le téléchargement échoue, créez le fichier avec le Bloc-notes à partir de ce fichier.

Puis importez :

Machine : SRV-WIN-01 (PowerShell administrateur)
$mdp = Read-Host -AsSecureString "Mot de passe initial des salariés"
Import-Csv C:\Scripts\utilisateurs-hexalog.csv -Delimiter ';' -Encoding UTF8 | ForEach-Object {
    $ou = "OU=$($_.Service),OU=Utilisateurs,$base"
    New-ADUser -Name "$($_.Prenom) $($_.Nom)" -GivenName $_.Prenom -Surname $_.Nom `
        -DisplayName "$($_.Prenom) $($_.Nom)" -SamAccountName $_.Login `
        -UserPrincipalName "$($_.Login)@hexalog.lan" -Department $_.Service -Title $_.Fonction `
        -Path $ou -AccountPassword $mdp -Enabled $true -ChangePasswordAtLogon $false
    Add-ADGroupMember -Identity "GG_$($_.Service)" -Members $_.Login
    Write-Host "Créé : $($_.Login) -> $ou"
}

Pourquoi ChangePasswordAtLogon à false ?

En entreprise, on oblige l’utilisateur à changer son mot de passe initial à la première connexion ($true). Dans le lab, on met $false : les tests d’accès des séances suivantes se font depuis Linux avec smbclient, qui ne sait pas changer un mot de passe expiré.

Étape 8. Le compte d’administration

Nicolas Fournier est technicien informatique. Pour son travail quotidien, il utilise n.fournier (sans droits particuliers). Pour administrer, il utilise un second compte :

Machine : SRV-WIN-01 (PowerShell administrateur)
New-ADUser -Name "ADM Nicolas Fournier" -SamAccountName adm.nfournier `
    -UserPrincipalName adm.nfournier@hexalog.lan -Path "OU=Admins,$base" `
    -Description "Compte d'administration de n.fournier" `
    -AccountPassword (Read-Host -AsSecureString "Mot de passe adm.nfournier") -Enabled $true

# Groupe Admins du domaine désigné par son SID (se termine par -512), quelle que soit la langue
$admins = Get-ADGroup -Identity "$((Get-ADDomain).DomainSID)-512"
$admins.Name
Add-ADGroupMember -Identity $admins -Members adm.nfournier
Get-ADGroupMember $admins | Select-Object SamAccountName

Étape 9. Vérifier

Machine : SRV-WIN-01 (PowerShell administrateur)
Get-ADUser -Filter * -SearchBase "OU=Utilisateurs,$base" | Measure-Object       # 11 comptes attendus
Get-ADGroupMember GG_Comptabilite | Select-Object SamAccountName
Get-ADPrincipalGroupMembership a.martin | Select-Object Name
Get-ADUser h.blanc -Properties Enabled, Title | Select-Object SamAccountName, Enabled, Title
Get-ADDefaultDomainPasswordPolicy

Exportez la matrice utilisateurs / groupes :

Machine : SRV-WIN-01 (PowerShell administrateur)
Get-ADUser -Filter * -SearchBase $base -Properties Department, MemberOf |
    Select-Object SamAccountName, Name, Department, Enabled,
        @{n='Groupes'; e={ ($_.MemberOf | ForEach-Object { ($_ -split ',')[0] -replace '^CN=' }) -join ', ' }} |
    Export-Csv C:\Scripts\matrice-utilisateurs.csv -NoTypeInformation -Delimiter ';' -Encoding UTF8
Import-Csv C:\Scripts\matrice-utilisateurs.csv -Delimiter ';' | Format-Table

Testez enfin qu’un salarié peut s’authentifier sur le domaine, depuis Linux :

Machine : CLI-LNX-01 (sysadmin)
sudo apt install -y smbclient
smbclient -L //srv-win-01.hexalog.lan -U 'HEXALOG\a.martin'     # mot de passe initial des salariés
smbclient -L //srv-win-01.hexalog.lan -U 'HEXALOG\h.blanc'      # que se passe-t-il ? pourquoi ?

Le premier doit lister les partages NETLOGON et SYSVOL du contrôleur de domaine. Faites un snapshot 06-annuaire sur SRV-WIN-01 et mettez à jour l’inventaire (rôles AD DS et DNS, domaine, comptes d’administration).

Dépannage

Symptôme Piste
Install-ADDSForest refuse : mot de passe administrateur local non conforme changer le mot de passe du compte Administrateur local (complexité) et relancer
Après redémarrage, « Préparation de Windows » ou « Application des paramètres » très long normal au premier démarrage d’un DC (plusieurs minutes)
Pas de résolution externe depuis le DC redirecteur absent ou faux : Get-DnsServerForwarder
dig depuis Linux ne trouve pas hexalog.lan /etc/resolv.conf pointe-t-il sur 10.10.10.10 ? pare-feu Windows : le rôle DNS ouvre normalement le port 53
New-ADUser : « The server is unwilling to process the request » mot de passe non conforme à la complexité, ou OU inexistante (faute de frappe dans $base)
Add-ADGroupMember : impossible de trouver GG_Comptabilité la colonne Service ne doit pas contenir d’accent (Comptabilite)
smbclient : NT_STATUS_LOGON_FAILURE mauvais mot de passe ou mauvais identifiant (HEXALOG\a.martin)
Accents incorrects dans les noms importés ajouter -Encoding UTF8 à Import-Csv

Pour aller plus loin : un poste Windows dans le domaine

Si votre PC a au moins 16 Go de RAM, créez CLI-WIN-01 (Windows 11 Entreprise évaluation, 4 Go, 2 vCPU, 64 Go, réseau LAB-HEXALOG). À l’installation, choisissez les options de connexion puis Joindre un domaine à la place pour créer un compte local. Ensuite :

Machine : CLI-WIN-01 (PowerShell administrateur)
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 10.10.10.100 -PrefixLength 24 -DefaultGateway 10.10.10.1
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 10.10.10.10
Add-Computer -DomainName hexalog.lan -Credential HEXALOG\Administrateur `
    -OUPath "OU=Postes,OU=Ordinateurs,OU=HEXALOG,DC=hexalog,DC=lan" -NewName CLI-WIN-01 -Restart

Ouvrez une session avec HEXALOG\a.martin, puis lancez whoami /upn, whoami /groups et echo %LOGONSERVER%.
