Comptes et mots de passe du lab

  • Sur les VM Debian : l’utilisateur sysadmin, membre du groupe sudo ; le compte root est verrouillé.
  • Sur Windows Server : Administrateur, puis HEXALOG\Administrateur après la création du domaine.
  • Sur CLI-WIN-01 : le compte local localadmin (pour le dépannage du poste), puis les comptes du domaine (HEXALOG\a.martin…).
  • Le mot de passe de lab est donné en séance 1. Il est réservé au lab : ne le réutilisez jamais ailleurs, et ne réutilisez jamais un de vos mots de passe personnels dans le lab.

Logiciels et images

  • VirtualBox, dernière version 7.x.
  • Debian 13 netinst amd64.
  • Windows Server 2025, version d’évaluation (ISO en français, 180 jours).
  • Windows 11, image ISO officielle de Microsoft en français : on installe l’édition Professionnel, sans clé de produit (non activée, cela suffit pour le lab).
  • Un client SSH (intégré à Windows 10/11 et aux systèmes Linux) et un client Bureau à distance (mstsc sous Windows, Remmina sous Linux).

Les images sont volumineuses (plusieurs Go pour Windows) : elles sont mises à disposition en séance, sur le réseau ou sur clé USB, pour éviter de saturer la connexion.

Windows : éviter le mode lent de VirtualBox

Si Hyper-V ou la sécurité basée sur la virtualisation sont actifs, VirtualBox fonctionne au ralenti (icône de tortue verte en bas de la fenêtre des VM). Seulement si vous n’utilisez pas WSL 2, Docker Desktop ou d’autres VM Hyper-V :

  1. Paramètres → Confidentialité et sécurité → Sécurité Windows → Sécurité de l’appareil → Isolation du noyau : désactiver Intégrité de la mémoire.
  2. Activer ou désactiver des fonctionnalités Windows : décocher Hyper-V, Plateforme de machine virtuelle et Plateforme de l’hyperviseur Windows.
  3. Dans un terminal administrateur : bcdedit /set hypervisorlaunchtype off, puis redémarrer.

Pour revenir en arrière : recocher les fonctionnalités et bcdedit /set hypervisorlaunchtype auto.

Bonnes pratiques

  • Éteindre proprement les VM (sudo poweroff, Stop-Computer) plutôt que de fermer la fenêtre en coupant le courant.
  • Snapshot avant chaque étape risquée, avec un nom numéroté ; supprimer de temps en temps les snapshots devenus inutiles.
  • Sauvegarder : exporter régulièrement les VM importantes en OVA sur un autre support.
  • Réseau NAT pour le lab : au lycée, une VM en Accès par pont n’a pas Internet en ligne de commande (le pare-feu demande une identification par page web, voir Séance 2 : VirtualBox : snapshots, clones, réseaux). Ne lancez jamais de service DHCP sur une carte en pont.
  • Noter dans le journal de bord toute modification, même petite.

Dépannage VirtualBox

Symptôme Solution
« VT-x is disabled in the BIOS » ou pas de système 64 bits proposé activer la virtualisation dans le BIOS/UEFI
Tortue verte, VM très lente Hyper-V ou VBS actifs sous Windows : voir ci-dessus
La souris ou le clavier restent capturés touche hôte (Ctrl droit par défaut)
Clavier QWERTY dans une VM Debian sudo dpkg-reconfigure keyboard-configuration, puis redémarrer
VM « inaccessible » au démarrage de VirtualBox dossier de la VM déplacé ou disque externe absent : rebrancher, ou Machine → Ajouter le fichier .vbox
Plus d’espace disque supprimer des snapshots inutiles, vider la corbeille, déplacer les VM sur un autre disque
Une VM refuse de démarrer après une fausse manipulation restaurer le dernier snapshot
Kernel driver not installed (rc=-1908) sur un PC Linux réinstaller VirtualBox, gérer la signature des modules si le Secure Boot est actif
